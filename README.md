# 나비

## 심사자 안내

### 서비스 소개

나비는 누구나 PC 화면이나 휴대폰 카메라로 실시간 방송을 켜고, 시청자가 채팅과 후원으로 참여하는 라이브 방송 서비스입니다.
후원은 "꿀"이라는 충전식 포인트로 합니다. 방송자는 받은 후원으로 등급이 오르고 월 1회 정산을 받습니다.
방송은 녹화해서 다시보기로 공개할 수 있고, 운영자는 신고를 처리해 이용자를 제재합니다.
결제와 송금은 모두 테스트입니다. 실제 돈은 오가지 않습니다.

### 테스트 계정

로그인 화면 아래쪽 버튼 세 개는 비밀번호 없이 바로 들어갑니다.

| 버튼 | 이 계정으로 확인하는 것 |
|---|---|
| 테스트 방송자 | 방송 켜기, 등급이 오르는 것, 정산, 시청자에게 채팅 제한 걸기 |
| 테스트 시청자 | 꿀 충전, 후원, 미션, 신고, 환급 내역 |
| 테스트 운영자 | 운영자 화면(`/admin`) 전체 |

홈의 "예시" 표시가 붙은 방송은 화면 구성을 보여 주는 예시라서 영상이 재생되지 않습니다. 영상이 나오는 방송은 테스트 방송자로 직접 켜서 확인합니다.

버튼에 없는 계정 두 개는 로그인 화면에서 이메일과 비밀번호로 들어갑니다. 심사용 계정이라 비밀번호가 공개되어 있어도 괜찮습니다.

| 계정 | 이메일 | 비밀번호 | 이 계정으로 확인하는 것 |
|---|---|---|---|
| 연습용시청자 | `practice@nabi.test` | `nabi-test-2026` | 운영자에게 제재를 받은 사람이 보는 화면, 이의 제기, 꿀 환급 신청 |
| 정지예시계정 | `suspended@nabi.test` | `nabi-test-2026` | 영구 정지된 계정으로 로그인했을 때 나오는 안내 |

이 밖에 하린방송, 민수게임, 지우, 서연, 하늘달, 도윤, 소라, 보람, 예린, 태양, 지민, 서준은 화면을 채우기 위한 샘플 계정입니다. 운영자 화면의 모든 메뉴가 여러 상태의 줄로 채워지도록 신고, 제재, 이의 제기, 환급, 정산, 충전 기록을 가지고 있습니다. 로그인할 수 없고, 다시보기와 채팅과 후원 내역에 상대방으로 나옵니다.
샘플 방송과 다시보기 제목에는 "예시"가 붙어 있습니다.

홈에는 "예시" 표시가 붙은 방송 중 예시 방송 8개와 준비 중 예시 방송 2개가 있습니다. 직접 송출하는 확인은 방송을 직접 켜는 것부터 시작합니다.

### 기능 확인 순서

아래 순서대로 따라 하면 모든 기능을 볼 수 있습니다. 준비물은 맥북 크롬(방송자), 아이폰(시청자)입니다. 각 번호가 그대로 되면 그 기능은 정상입니다.

**1. PC 화면 방송 (테스트 방송자, 맥북 크롬)**
1. 테스트 방송자로 로그인하고 "방송 만들기"에서 "PC 화면 공유"를 골라 만듭니다.
2. 공유 전 안내를 읽고, 소리가 나는 탭(예: 유튜브)을 "탭 오디오 공유"를 켠 채 공유합니다.
3. 미리보기에서 탭 소리 막대와 마이크 소리 막대가 움직이는지 봅니다.
4. "방송 시작"을 누르면 송출이 올라온 뒤 "방송 중"으로 바뀝니다. 30초 안에 올라오지 않으면 "방송을 시작하지 못했어요"가 나옵니다.
5. 아이폰에서 방송 링크를 엽니다. 화면이 나오고, "소리 켜기"를 누르면 탭 소리와 마이크 소리가 함께 들립니다.
6. 맥북에서 "방송 종료"를 누르면 아이폰 화면이 "방송이 끝났어요"로 바뀌고 홈 목록에서 사라집니다.
7. 방송을 다시 만들어 시작한 뒤 크롬의 "공유 중지"를 누르면 방송이 종료됩니다.

**2. 휴대폰 카메라 방송 (아이폰)**
1. 아이폰에서 테스트 방송자로 로그인하고 방송을 만듭니다. 송출 방식은 카메라가 기본으로 골라져 있습니다.
2. 링크를 복사하고, 권한 안내 뒤에 카메라와 마이크를 허용한 다음 "방송 시작"을 누릅니다.
3. 맥북에서 링크를 열면 카메라 영상과 소리가 나옵니다.
4. 아이폰에서 "방송 종료"를 누르면 맥북 화면이 종료 안내로 바뀝니다.
5. 방송을 다시 시작하고 아이폰 화면을 잠그면 방송이 종료됩니다.

**3. 방송 관리와 시청**
1. 내 방송 관리에서 방송 제목 수정과 삭제를 해 봅니다. 방송 중인 방송에는 삭제 버튼이 없고, 끝난 방송만 지울 수 있습니다.
2. 홈 목록에는 방송 중인 방송이 먼저, 최근에 시작한 순서로 나옵니다.
3. 방송 보기 화면의 상태(준비, 방송 중, 종료)는 새로고침 없이 바뀝니다.

**4. 회원가입, 로그인, 권한**
1. 회원가입, 로그인, 로그아웃이 되고 새로고침해도 로그인이 유지됩니다.
2. 로그아웃한 상태에서도 방송 목록을 보고 시청할 수 있습니다. 방송 만들기를 누르면 로그인 화면으로 갑니다.
3. 회원가입에서 필수 약관에 동의하지 않으면 가입 버튼이 눌리지 않고, 이미 쓰는 닉네임은 거절됩니다.
4. 새로 가입한 계정에서 닉네임은 한 번만 바꿀 수 있습니다. 새 계정을 탈퇴하면 다시 로그인할 수 없고, 그 계정의 채팅은 "탈퇴한 사용자"로 보입니다.
5. 테스트 시청자로 로그인해 테스트 방송자의 송출 화면 주소를 열면 거절됩니다.
6. 테스트 시청자의 로그인 토큰으로 남의 방송을 서버에 직접 요청해도 403으로 거절됩니다. 아래 "확인용 명령"을 보세요.

**5. 채팅**
1. 로그아웃한 상태에서 채팅을 읽을 수 있고, 쓰려고 하면 로그인 화면으로 갑니다.
2. 로그인하고 채팅을 쓰면 다른 기기에 새로고침 없이 보입니다. 채팅에는 수정·삭제 메뉴가 없습니다.
3. 1초 안에 두 번 보내면 두 번째는 "조금 천천히 보내 주세요"로 거절됩니다.
4. 금칙어가 들어간 채팅은 모든 기기에서 "부적절한 표현이 감지되어 숨긴 채팅이에요"로 보입니다.
5. 방송이 끝나면 입력 칸이 막히고, 서버에 직접 보내도 거절됩니다.
6. 방송 중에 새로고침하거나 늦게 들어와도 최근 채팅 50개가 보입니다.

**6. 후원과 꿀 (테스트 시청자 + 테스트 방송자)**
1. 테스트 시청자로 로그인하고, 방송자가 켠 방송에서 "후원하기"를 누릅니다. 꿀이 0이라 아래에서 후원 창이 올라옵니다.
2. "+1천"을 세 번 눌러 3,000꿀을 만들고 메시지를 씁니다. 버튼이 "충전하고 후원하기"로 바뀌고 충전 꿀은 5,000꿀로 골라집니다.
3. 테스트 결제창에서 5,500원(부가세 포함)을 결제하면 5,000꿀이 충전되고 3,000꿀 후원이 바로 확정됩니다. 송출 화면에 알림이 뜨고 방송 후원 합계가 3,000 늘며, 내 꿀에는 2,000꿀이 남습니다.
4. 같은 결제 승인 요청을 다시 보내도 꿀과 합계는 늘지 않습니다. 아래 "확인용 명령"을 보세요.
5. 익명을 켜고 남은 꿀에서 1,000꿀을 후원하면 채팅과 송출 화면에 "익명"으로 보입니다. 결제창은 뜨지 않습니다.
6. 후원 버튼을 빠르게 두 번 눌러도 꿀은 한 번만 빠집니다.
7. 방송 중에 미션 탭에서 제한 시간 5분, 상금 5,000꿀로 미션을 보냅니다. 잔액이 모자라니 "충전하고 후원하기"로 채웁니다. 송출 화면의 미션 목록에 뜨고 시청자 잔액에서 5,000꿀이 묶입니다. 방송자가 거절하면 5,000꿀이 돌아오고, 수락한 뒤 "성공"을 누르면 5,000꿀이 후원 합계에 들어갑니다. 준비 상태의 방송에서는 미션 탭이 눌리지 않습니다.
8. 수락한 미션을 5분 동안 두면 "실패"가 되고, 응원금 1,000꿀만 후원 합계에 들어가고 4,000꿀은 시청자에게 돌아옵니다. 대기 중인 미션이 있을 때 방송을 종료하면 "취소됨"이 되고 5,000꿀이 모두 돌아옵니다.
9. 내 꿀 화면에서 쓰지 않은 충전은 취소할 수 있고, 일부라도 쓴 충전은 "취소할 수 없음"으로 보입니다.
10. 새로 가입한 계정으로 "충전하기"를 누르면 결제창보다 본인인증(목업) 창이 먼저 뜹니다. 생년월일을 만 19세 미만으로 넣으면 "만 19세 이상만 꿀을 충전할 수 있어요"가 나옵니다.
11. 충전 창에서 "오늘 남은 한도"를 볼 수 있습니다. 한도를 넘기는 경우는 화면에서 확인하지 않습니다. 같이 쓰는 테스트 계정의 그날 충전이 막히기 때문입니다. 대신 서버 테스트로 확인합니다(아래 "확인용 명령").
12. 테스트 방송자의 내 방송 관리에서 후원 내역, 합계, 예상 수익이 보이고, 줄마다 적용한 배분 비율이 보입니다.
13. 방송을 종료하면 시청 화면에서 후원 버튼이 사라지고, 서버에 직접 후원해도 거절됩니다.
14. **등급 올리기:** 테스트 방송자는 애벌레가 되기 직전(방송 2회, 누적 2시간, 받은 후원 6건)으로 준비되어 있습니다. 1번에서 10분 넘게 방송했다면 이미 애벌레가 되었으니, 운영자 화면 "테스트 계정"에서 "테스트 방송자: 승급 직전으로"를 먼저 누릅니다. 그다음 10분 넘게 방송하고 종료하면 등급이 애벌레로 오르고, 내 등급 화면에 변경 내역이 한 줄 늘어납니다. 그 뒤 받는 후원은 82%로 계산됩니다. 오르기 전에 받은 후원은 80%로 남습니다.

**7. 녹화와 다시보기**
1. 송출 화면에서 방송을 시작하기 직전에 "이 방송 녹화하기"를 켜고, 1~2분 방송한 뒤 종료합니다.
2. 잠시 뒤 내 방송 관리에서 녹화가 "볼 수 있음, 비공개"로 보입니다. 이때 다시보기 목록에는 없습니다.
3. "공개"로 바꾸면 다시보기 목록에 나타나고 로그아웃한 상태에서도 재생됩니다. 다시 비공개로 바꾸면 목록에서 사라지고 재생 주소도 막힙니다.
4. 녹화가 처리 중인 방송은 삭제 버튼을 눌러도 지워지지 않습니다.
5. 처음부터 준비된 다시보기 예시(테스트 방송자, 하린방송, 민수게임)는 녹화 시간을 쓰지 않고 공개·비공개 전환과 재생을 확인할 수 있습니다.

**8. 정산 (테스트 방송자 + 테스트 운영자)**
1. 테스트 방송자의 내 방송 관리 정산 카드에 정산 계좌 "테스트은행 ****1234 (테스트)"와 "다음 달 25일에 받을 금액(쌓이는 중)"이 보입니다. 이 금액은 후원 내역의 예상 수익 합계와 같습니다.
2. 테스트 운영자로 로그인해 정산 관리에서 "월 정산 지금 실행(테스트)"을 누릅니다. 테스트 방송자로 돌아가면 정산 내역에 새 줄이 있습니다. 기간은 이번 달 1일부터 지금까지이고, 상태는 "지급 완료(테스트)", 송금 번호는 `MOCK-`로 시작합니다.
3. 바로 한 번 더 누르면 "정산할 후원이 없어요"가 나옵니다. 같은 후원이 두 번 정산되지 않습니다.
4. 같은 요청 번호로 서버에 다시 요청해도 정산 기록이 늘지 않습니다. 아래 "확인용 명령"을 보세요.
5. 새 후원을 받은 뒤 다시 누르면 새 후원만 들어간 정산 기록이 하나 더 생깁니다.
6. 정산 관리에서 연습용시청자의 정산을 보류한 뒤 다시 실행하면 그 계정의 새 정산 기록이 "보류(운영 조치)"로 생깁니다. 보류를 풀고 다시 누르면 "지급 완료(테스트)"가 됩니다.
7. 민수게임은 정산 계좌가 없어서 정산하면 "보류(정산 정보 없음)"가 됩니다.
8. 테스트 방송자나 테스트 시청자가 서버에 정산 실행을 직접 요청하면 403으로 거절됩니다.

**9. 신고와 방송자 활동 제한**
1. 테스트 시청자로 테스트 방송자의 방송에서 다른 사람 채팅의 닉네임을 누르면 사용자 시트가 열립니다. 내 닉네임에는 신고 항목이 없습니다.
2. "이 메시지 신고"에서 사유를 골라 신고하면 "신고했어요"가 나오고, 같은 메시지를 다시 신고하면 "이미 신고했어요"가 나옵니다. 내 정보의 신고 내역에 "접수됨"으로 보입니다.
3. 테스트 방송자가 송출 화면에서 시청자 닉네임을 눌러 "이 방송에서 채팅 금지(1일)"를 걸면, 그 시청자의 입력 칸에 "이 방송에서 채팅이 제한됐어요"가 보이고 서버에 직접 보내도 거절됩니다.
4. 내 방송 관리의 활동 제한 탭에서 해제하면 바로 다시 채팅할 수 있습니다.

**10. 운영자 화면과 제재 (테스트 운영자)**
1. 테스트 운영자로 로그인하면 `/admin` 대시보드가 보입니다. 테스트 시청자로 `/admin`을 열면 403입니다.
2. "신고 처리"에 연습용시청자에 대한 신고 4건이 묶여 보이고, 채팅 신고 상세에 원문이 보입니다.
3. "제재하기"에서 채팅 금지 1일과 사유를 고르면 신고 4건이 모두 "조치함"이 되고 운영 기록에 한 줄 남습니다.
4. 연습용시청자로 로그인하면(위 표의 이메일과 비밀번호) 위쪽에 채팅 금지 안내 띠가 보이고 채팅을 쓸 수 없습니다. 제재 내역에서 이의를 제기할 수 있고, 같은 제재에 두 번째 이의 제기는 막힙니다.
5. 운영자가 이의를 받아들이면 바로 채팅할 수 있습니다.
6. 테스트 운영자가 테스트 방송자에게 제재를 걸려고 하면 "심사용 테스트 계정은 제재할 수 없어요"가 나오고 서버도 거절합니다.
7. "방송 관리"에서 방송 중인 방송을 강제 종료하면 시청 화면이 바로 종료로 바뀝니다.
8. 새로 가입한 계정에 제재를 걸려고 하면 "테스트 운영자는 심사용 계정만 보고 조치할 수 있어요"가 나오고 서버도 403으로 거절합니다.
9. "테스트 계정"에서 "제재 연습용: 신고 4건·제재 없음·꿀 5,000으로"를 누르면 신고 4건과 제재 없음 상태로 돌아갑니다.

**11. 꿀 환급 (연습용시청자 + 테스트 운영자)**
1. 연습용시청자로 로그인합니다. 내 꿀에 잔액 5,000이 보이고, 그 충전은 "취소할 수 없음(7일 지남)"으로 보입니다.
2. "환급 신청"을 누르면 환급할 꿀 5,000, 결제 금액 기준 5,500원, 수수료 550원, 받을 금액 4,950원이 보입니다. 계좌를 넣고 신청하면 잔액은 0, 환급 대기는 5,000이 됩니다. 이때 후원하려고 하면 잔액이 모자라다고 나옵니다.
3. 같은 신청 번호로 서버에 다시 요청해도 신청은 하나만 남고, 처리 중인 신청이 있으면 새 신청 버튼이 눌리지 않습니다.
4. 테스트 운영자로 환급 관리에서 이 신청을 사유와 함께 거절하면 연습용시청자의 잔액이 5,000으로 돌아오고 환급 결과 알림이 옵니다.
5. 다시 신청하고 운영자가 승인하면 상태가 "환급 완료(테스트)"가 되고 `MOCK-`로 시작하는 송금 번호가 붙으며, 꿀 내역에 "환급" 줄이 생깁니다.
6. 테스트 시청자가 서버에 환급 승인을 직접 요청하면 403으로 거절됩니다.
7. "테스트 계정"에서 연습용시청자를 되돌리면 남은 꿀이 5,000으로 돌아옵니다. 지난 환급 신청 기록은 남습니다.

### 여러 심사자가 함께 쓸 때

- 테스트 계정은 모든 심사자가 함께 씁니다. 앞 심사자가 남긴 충전, 후원, 신고 기록이 다음 심사자에게 보입니다. 두 사람이 동시에 쓰면 서로의 기록이 보일 수 있습니다.
- 테스트 방송자의 방송은 30분까지만 이어집니다. 송출 화면이 25분에 "5분 뒤에 방송이 끝나요"를 보여주고 30분에 종료합니다.
- 테스트 계정 로그인 버튼은 같은 IP에서 1시간에 20번까지만 눌러집니다. 넘으면 "잠시 뒤에 다시 시도해 주세요"가 나옵니다.
- 운영자 화면 "테스트 계정"에서 계정 상태를 되돌릴 수 있습니다. 부분 초기화는 버튼 하나씩 눌러 상태만 되돌리고(테스트 시청자는 꿀 0, 테스트 방송자는 승급 직전, 연습용시청자는 신고 4건·제재 없음·꿀 5,000), 전체 초기화는 테스트 계정 17개와 더미 데이터를 처음부터 다시 만듭니다. 전체 초기화는 테스트 운영자가 10분에 한 번만 할 수 있습니다.
- 서버에서는 `pnpm seed --reset`으로 같은 전체 초기화를 할 수 있습니다.

심사 기간에는 테스트 계정 버튼 로그인과 월 정산 테스트 실행을 켜 둡니다. 심사가 끝나면 두 기능을 끕니다.

### API 문서

서비스 주소 뒤에 `/api-docs`를 붙이면 모든 API를 목록으로 볼 수 있습니다. 같은 내용이 `/openapi.json`에도 있습니다. 로그인 토큰은 `authorization: Bearer <토큰>` 헤더로 보냅니다.

### 확인용 명령

서버에 직접 요청하는 확인에는 로그인 토큰이 필요합니다. 아래 명령은 버튼 계정의 토큰을 한 줄로 출력합니다(방송자, 시청자, 운영자 중 하나).
주소는 배포한 서비스 주소를 `NABI_URL`에 넣어 바꿉니다. 로컬은 기본값 `http://localhost:3000`입니다.

```bash
pnpm test-token 시청자
```

**남의 방송을 서버에 직접 수정하기 (거절되는지 확인)**

```bash
TOKEN=$(pnpm -s test-token 시청자)
# 방송 ID는 테스트 방송자가 만든 방송 주소(/live/방송ID)에서 찾습니다.
curl -i -X PATCH -H "authorization: Bearer $TOKEN" -H "content-type: application/json" \
  -d '{"title":"바꿔 보기"}' http://localhost:3000/api/broadcasts/방송ID     # 403
curl -i -X DELETE -H "authorization: Bearer $TOKEN" http://localhost:3000/api/broadcasts/방송ID        # 403
curl -i -X POST   -H "authorization: Bearer $TOKEN" http://localhost:3000/api/broadcasts/방송ID/end   # 403
```

**시청자가 정산이나 환급 승인을 직접 요청하기 (거절되는지 확인)**

```bash
TOKEN=$(pnpm -s test-token 시청자)
curl -i -X POST -H "authorization: Bearer $TOKEN" -H "content-type: application/json" \
  -d '{"requestId":"aaaaaaaaaaaaaaaa"}' http://localhost:3000/api/admin/settlements/run-test           # 403
curl -i -X POST -H "authorization: Bearer $TOKEN" http://localhost:3000/api/admin/refunds/신청번호/approve  # 403
```

**같은 정산 요청을 두 번 보내도 기록이 하나인지 확인**

```bash
TOKEN=$(pnpm -s test-token 운영자)
for i in 1 2; do
  curl -s -X POST -H "authorization: Bearer $TOKEN" -H "content-type: application/json" \
    -d '{"requestId":"settle-check-0001"}' http://localhost:3000/api/admin/settlements/run-test
done   # 두 번째도 첫 번째와 같은 결과이고, 정산 관리에 기록이 하나만 있습니다
```

**같은 결제 승인 요청을 두 번 보내도 꿀이 한 번만 늘어나는지 확인**

테스트 결제를 마치면 성공 화면 주소에 `paymentKey`, `orderId`, `amount`가 붙습니다. 그 값을 그대로 두 번 보냅니다.

```bash
TOKEN=$(pnpm -s test-token 시청자)
for i in 1 2; do
  curl -s -X POST -H "authorization: Bearer $TOKEN" -H "content-type: application/json" \
    -d '{"paymentKey":"성공 주소의 paymentKey","orderId":"성공 주소의 orderId","amount":5500}' \
    http://localhost:3000/api/charges/confirm
done   # 꿀과 후원 합계는 한 번만 늘어납니다
```

**하루 충전 한도 테스트**

한도를 넘기는 경우(오늘 999,000꿀을 충전한 상태에서 5,000꿀 주문)는 화면 대신 서버 테스트로 확인합니다. 하루 한도에 무엇을 세는지는 이 테스트가 확인합니다.

```bash
pnpm --filter @nabi/core test
```

## 로컬에서 실행하기

### 필요한 도구

- Node 22.14 이상 (`.nvmrc` 참고)
- pnpm 10 (`corepack enable` 하면 `package.json`의 버전이 자동으로 쓰입니다)
- LiveKit 개발 서버: `brew install livekit`
- Java (Firebase 에뮬레이터의 Firestore가 씁니다)

### 처음 한 번

```bash
pnpm install
cp apps/web/.env.example apps/web/.env.local   # 이미 있으면 건너뜁니다. 값은 그대로 쓰면 됩니다.
```

### 서버 세 개 띄우기

터미널을 세 개 열고 루트에서 차례로 실행합니다.

```bash
pnpm livekit     # 1. LiveKit 개발 서버 (포트 7880)
pnpm emulators   # 2. Firebase 에뮬레이터: 로그인 9099, 데이터베이스 8080, 관리 화면 4000
pnpm dev         # 3. 웹 서버 (포트 3000) → http://localhost:3000
```

`pnpm livekit`은 방송 중 일어나는 일(송출 시작, 방송자 나감)을 `http://localhost:3000/api/webhooks/livekit`으로 알려 줍니다.
그래서 웹 서버(3)가 떠 있어야 방송이 "방송 중"과 "종료"로 바뀝니다.

### 녹화 환경 띄우기 (도커)

녹화(다시보기)는 LiveKit egress가 방을 합쳐서 MP4로 저장합니다. 로컬에서는 도커가 필요합니다.
`docker compose`로 redis, egress, S3 호환 저장소(s3mock, 포트 9090)를 띄웁니다. 저장소 주소와 키는 `apps/web/.env.local`의 `STORAGE_*` 변수입니다.

```bash
docker compose -f docker-compose.dev.yml up -d   # redis 6379, 저장소 9090, egress
pnpm livekit                                      # redis가 떠 있어야 켜집니다(livekit.dev.yaml이 redis를 씁니다)
```

- `pnpm livekit`은 이제 redis를 씁니다. 도커를 켜지 않고 방송만 확인하려면 `livekit.dev.yaml`의 `redis:` 두 줄을 잠시 주석 처리하세요. 이때는 녹화를 켜도 녹화가 실패로 남고 방송은 계속됩니다.
- egress를 처음 켠 뒤 첫 녹화는 크롬을 처음 띄우느라 실패할 수 있습니다. 실패하면 새 방송으로 다시 해 보세요.
- 도커 없이 녹화 규칙(상태 바뀜, 3분 제한, 월 50분, 웹훅 처리, 서명 주소)만 확인하려면 에뮬레이터를 켠 채로 `pnpm --filter @nabi/core check-recording`을 실행합니다. 가짜 egress와 가짜 저장소로 돌립니다.
- 배포는 Cloudflare R2를 씁니다. `STORAGE_ENDPOINT`(`https://<계정ID>.r2.cloudflarestorage.com`), `STORAGE_REGION=auto`, `STORAGE_BUCKET`, `STORAGE_ACCESS_KEY_ID`, `STORAGE_SECRET_ACCESS_KEY`를 채우고 `STORAGE_EGRESS_ENDPOINT`는 비웁니다.

### Docker로 웹 서버 띄우기

`apps/web`을 Next standalone 출력으로 담는 `Dockerfile`이 레포 루트에 있습니다. 빌드는 루트에서 합니다.

```bash
docker build -t nabi-web \
  --build-arg NEXT_PUBLIC_FIREBASE_API_KEY=... \
  --build-arg NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=... \
  --build-arg NEXT_PUBLIC_FIREBASE_PROJECT_ID=... \
  --build-arg NEXT_PUBLIC_LIVEKIT_URL=wss://... \
  --build-arg NEXT_PUBLIC_TOSS_CLIENT_KEY=... .

docker run --rm -p 3000:3000 --env-file apps/web/.env.production nabi-web   # http://localhost:3000
```

- `NEXT_PUBLIC_*` 값은 브라우저 코드에 박히므로 **빌드할 때** `--build-arg`로 넘깁니다. 바꾸려면 다시 빌드해야 합니다.
- 그 밖의 값(`FIREBASE_*`, `LIVEKIT_*`, `STORAGE_*`, `TOSS_SECRET_KEY`, `CRON_SECRET` 등)은 **실행할 때** `--env-file`이나 `-e`로 넘깁니다. 이미지 안에는 키가 들어가지 않습니다. 변수 이름은 `apps/web/.env.example`을 봅니다.
- 이 이미지는 웹 서버만 담습니다. LiveKit, Firebase, 저장소(R2)는 밖에 있는 서비스를 환경 변수의 주소로 씁니다.

### API 문서 (OpenAPI)

```bash
pnpm openapi   # packages/shared의 모든 API 약속 → apps/web/public/openapi.json
```

웹 서버를 띄우고 `http://localhost:3000/api-docs`를 열면 목록으로 볼 수 있습니다. API 약속(`packages/shared/src`의 `*Api`)을 바꾸면 `pnpm openapi`를 다시 실행해 파일을 갱신합니다. 새 약속 파일을 만들었다면 `packages/shared/scripts/openapi.ts`의 목록에 더합니다.

### 테스트 계정 만들기 (시드)

에뮬레이터가 뜬 뒤에 한 번 실행합니다. 에뮬레이터를 껐다 켜면 데이터가 사라지니 다시 실행해 주세요.

```bash
pnpm seed                        # 에뮬레이터에 만듭니다
pnpm seed --reset                # 전체 초기화. 운영자 화면의 "전체 초기화"와 같은 함수입니다
pnpm seed --target=production    # 배포 환경. Firebase 프로젝트 이름을 한 번 더 입력해야 실행됩니다
```

테스트 계정 17개(버튼 3개, 연습용시청자, 정지예시계정, 샘플 계정 12개)와 지난 방송, 채팅, 후원, 신고, 제재, 다시보기가 만들어집니다.
후원, 충전, 신고, 제재는 실제 서버 기능을 거쳐 만들고, 결제만 "시드 결제"로 바꿉니다. 여러 번 돌려도 결과가 같습니다.

- 다시보기 예시 영상 3개는 `ffmpeg`로 만든 테스트 화면입니다. `ffmpeg`가 없으면 영상 없이 녹화 기록만 만들어지고 재생은 되지 않습니다(`brew install ffmpeg`). 올릴 저장소는 `STORAGE_*` 환경 변수의 값입니다.
- 방송 중 예시 방송 8개와 준비 중 예시 방송 2개를 만듭니다. 영상은 나오지 않습니다.
- 전체 초기화는 심사자가 만든 처리 중 돈 기록(결제 대기, 환급 대기 등)이 있으면 거절합니다. 시드가 만든 처리 중 기록은 막지 않습니다.

### 운영자 표시 붙이기

실제 계정을 운영자로 만들려면 가입을 마친 뒤 `pnpm grant-admin 이메일주소`를 실행합니다. 떼려면 `--revoke`, 배포 환경이면 `--target=production`을 붙입니다.

### 테스트 계정 버튼

`http://localhost:3000/login` 아래쪽의 "테스트 방송자 / 시청자 / 운영자로 로그인" 버튼을 누르면 비밀번호 없이 로그인됩니다.
`apps/web/.env.local`의 `ENABLE_TEST_LOGIN=true`일 때만 동작합니다.
테스트 방송자의 방송은 30분까지만 이어집니다.

### curl로 API 확인하기 (test-token)

```bash
pnpm test-token 시청자   # 방송자, 시청자, 운영자 중 하나
```

그 계정의 로그인 토큰을 한 줄로 출력합니다. 웹 서버가 떠 있어야 합니다.

```bash
TOKEN=$(pnpm -s test-token 방송자)
curl -H "authorization: Bearer $TOKEN" http://localhost:3000/api/me
```

### 문제 해결

- `pnpm emulators`에서 `EACCES` 오류가 나면, 이 환경이 `~/.config`를 읽지 못하는 경우입니다.
  설정 폴더를 읽을 수 있는 곳으로 바꿔서 띄웁니다.

  ```bash
  XDG_CONFIG_HOME=/tmp/xdg pnpm emulators
  ```

- 도커 데몬이 꺼져 있으면 `open -a Docker`로 켠 뒤 위 compose 명령을 다시 실행합니다.
- 방송이 "준비 중"에서 넘어가지 않으면 `pnpm livekit`과 `pnpm dev`가 모두 떠 있는지 확인합니다.
- 실제 화면 공유와 카메라는 브라우저가 허용을 물어봅니다. 자동 테스트로는 누를 수 없습니다.
