## 1. 평가 기준

### 영향도: 이 가정이 틀리면 얼마나 크게 무너지는가

목표는 1명이 2주 안에 공모작을 제출하는 것이다. 마감은 2026년 11월 19일(목) 밤 11시 59분이다. 그래서 영향도는 아래 순서로 판단한다.

| 영향도 | 뜻 |
|---|---|
| 높음 | 틀리면 심사자가 PC 송출, 휴대폰 송출, 시청, 종료, 권한 거절 중 하나를 확인하지 못한다. 또는 제출 자체가 늦어진다 |
| 중간 | 틀려도 시연은 된다. 하지만 기획 설명이 약해지거나 선택 기능 하나를 빼야 한다 |
| 낮음 | 시장과 사업에 관한 가정이다. 제출 뒤에 확인해도 심사 결과는 크게 바뀌지 않는다 |

### 위험도: 지금 이 가정이 틀렸을 가능성

| 위험도 | 뜻 |
|---|---|
| 높음 | 근거가 없거나 추론뿐이다. 틀렸을 가능성이 크다 |
| 중간 | 근거가 일부 있지만 실제 기기나 공식 자료로 확인하지 않았다 |
| 낮음 | 공식 자료나 널리 알려진 브라우저 동작이 받쳐 준다. 그래도 한 번은 실제로 확인한다 |

### 영향도와 위험도를 합쳐서 정하는 처리 방식

| | 위험도 낮음 | 위험도 높음 또는 중간 |
|---|---|---|
| **영향도 높음** | 바로 설계에 반영한다. 개발하면서 한 번 확인한다 | 개발 시작 전에 작은 테스트로 먼저 확인한다 |
| **영향도 중간·낮음** | 제출 뒤로 미룬다 | 지금은 다루지 않는다. 기획서에는 위험으로만 적는다 |

### 확인 시점

- **개발 시작 전:** 2026년 11월 7일(토)까지 확인한다. 틀리면 송출 구조나 범위가 바뀌는 가정이다.
- **개발 중:** 11월 18일(수)까지 확인한다. 틀리면 화면이나 안내 문구를 고친다.
- **제출 후:** 11월 20일 이후에 확인한다. 심사 결과에는 영향이 적다.

## 4. 이번 주에 먼저 확인할 것 상위 5개

> 이 장은 개발 전에 세운 확인 계획이다. 확인한 결과는 [00 기획 통합 브리핑](00-planning-brief.md) 8장과 [06 결정 기록](06-decisions.md)의 결정 1, 2, 6, 28, "공식 문서 확인 결과"에 있다.

이번 주는 11월 5일(목)부터 11월 8일(일)까지다. 아래 순서대로 하면 약 하루 안에 끝난다. 2번, 3번, 4번 테스트는 같은 테스트 페이지를 함께 쓴다.

### 1) 심사 환경 확인 (가정 1)

- **이미 확인된 것:** 요강 원문으로 탭 소리만으로 충분하다는 점(가정 2), 휴대폰은 카메라 송출만 하면 된다는 점(가정 9), 후원은 테스트 결제로 만든다는 점(가정 16)을 확인했다.
- **확인할 것:** 심사자가 어떤 기기와 브라우저로 확인하는지. 요강에는 이 내용이 없다.
- **방법:** 주최 측이나 강사에게 심사 기기와 브라우저를 한 번 묻는다. 답이 없으면 맥북 크롬과 아이폰 크롬을 기준으로 정하고, README의 지원 환경에 그대로 적는다.
- **시간:** 10분.
- **통과 기준:** 테스트할 기기와 브라우저가 정해지고, README에 적을 지원 환경 문장이 나온다.
- **함께 반영할 것:** 요강은 README에 테스트 계정이나 테스트 계정으로 바로 로그인하는 기능을 요구한다. 이 기능은 심사자가 가입 단계 없이 바로 방송을 켜게 해 준다. 그래서 켜기 장벽을 줄이는 설계에도 포함한다.

### 2) 맥북 크롬 탭 공유 테스트 (가정 3, 4, 5)

- **확인할 것:** 탭 공유와 탭 소리가 화면 기록 권한 없이 되는지, "탭 오디오 공유" 체크가 기본으로 켜져 있는지, 체크를 끄면 페이지가 소리 없음을 알 수 있는지, 전체 화면 공유는 어떤 권한 창이 뜨는지.
- **방법:** 실제 맥북 크롬에서 화면 공유 예제 페이지를 열고 유튜브 탭 하나를 공유한다. macOS와 크롬 버전을 함께 적는다.
- **시간:** 20분.
- **통과 기준:** 시스템 설정을 바꾸지 않고 탭 화면과 소리가 함께 들어온다. 소리가 빠지면 페이지가 그 사실을 알 수 있다.

### 3) HTTPS 테스트 페이지를 배포하고 아이폰 크롬에서 확인 (가정 7, 8, 10, 15)

- **확인할 것:** 아이폰 크롬에서 카메라와 마이크가 켜지는지, 화면을 잠그면 페이지가 끊김을 알아채는지, 소리 있는 자동 재생이 막히는지, 고른 배포 서비스가 무료 한도 안에서 HTTPS 주소를 주는지.
- **방법:** 카메라를 켜고 상태를 화면에 표시하는 페이지 하나를 실제 배포할 서비스에 올린다. 아이폰 크롬으로 연다.
- **시간:** 1시간.
- **통과 기준:** 카메라 영상이 보이고, 잠금 뒤 상태 표시가 바뀐다. 배포 서비스가 심사 기간 내내 켜져 있을 수 있다.

### 4) 송출 구조를 정하고 휴대폰 데이터로 시청 테스트 (가정 11, 12, 14)

- **확인할 것:** 기기끼리 직접 연결하는 구조와 미디어 서버를 거치는 구조 중 무엇을 쓸지, 아이폰이 휴대폰 데이터일 때도 시청이 되는지, 송출이 끊기면 서버가 알 수 있는지, 녹화를 지원하는지.
- **방법:** 후보 구조를 두 개 이하로 줄인다. 하나를 골라 맥북 와이파이에서 송출하고 아이폰 휴대폰 데이터로 시청한다. 그다음 송출 탭을 닫아 본다.
- **시간:** 반나절.
- **통과 기준:** 와이파이를 끈 아이폰에서 영상이 10초 안에 나온다. 송출 탭을 닫으면 서버가 끊김을 안다.

### 5) 2주 일정이 가능한지 확인 (가정 13)

- **확인할 것:** 필수 기능과 선택 기능을 마감 안에 모두 만들 수 있는지.
- **방법:** 기능별로 하루 단위 일정을 적는다. 4번에서 만든 "PC에서 켜고 아이폰에서 본다"에 걸린 시간을 기준으로 남은 일정을 다시 계산한다.
- **시간:** 1시간.
- **통과 기준:** 11월 17일(화)까지 필수 기능이 끝나고, 이틀이 심사 시나리오 점검용으로 남는다. 남지 않으면 선택 기능을 녹화와 다시보기, 후원, 댓글 순서로 뺀다.
