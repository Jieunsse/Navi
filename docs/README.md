# 나비 문서 색인

이 파일은 `docs/` 폴더의 입구입니다. 기획, 디자인(화면 설계), 설계(아키텍처), 수익 구조(BM), 운영 정책, 기능 명세, 공모 요구사항 근거를 어느 문서에서 읽으면 되는지 알려 줍니다.

- 주제마다 그 주제만 모은 문서가 하나씩 있습니다. 그 문서 하나만 읽어도 주제 전체를 알 수 있게 썼습니다.
- 주제 문서는 자세한 근거를 원문(06 결정 기록, 07 기능 명세 등)의 절 링크로 이어 줍니다.
- 서비스 실행 방법, 테스트 계정, 기능 확인 순서는 [루트 README](../README.md)에 있습니다.

## 4. 어느 문서가 기준인가

두 문서의 내용이 다르면 아래 기준 문서를 따릅니다. 주제 문서(00, 11, 12, 13, 14, 15)는 원문을 모은 요약이므로, 원문과 다르면 원문이 맞습니다.

| 무엇이 다를 때 | 기준 문서 |
|---|---|
| 기능의 동작 | [07 기능 명세](07-feature-spec.md) |
| 화면의 모양 | 피그마 시안. 와이어프레임이 없는 화면은 배포된 화면 |
| 결정의 이유와 날짜 | [06 결정 기록](06-decisions.md) |
| 코드 위치와 실제 동작 | 코드. 문서와 코드가 다르면 코드를 기준으로 문서를 고친다 |
| 사용자와 맺는 약속의 문장 | [09](09-streamer-terms-draft.md), [10](10-terms-of-service-draft.md) 약관 초안 |

## 5. 이 색인을 고치는 규칙

- 새 문서를 만들면 3장 문서 목록에 한 줄을 더합니다. 새 주제라면 1장에도 더합니다.
- 원문을 고치면 그 내용을 모은 주제 문서도 함께 고칩니다. 그러지 않으면 두 문서가 서로 달라집니다.
- 원문의 제목을 바꾸면 주제 문서와 이 색인의 링크도 고칩니다. 링크 주소가 제목으로 만들어지기 때문입니다.
- 이 색인에는 결론 한 줄과 위치만 둡니다. 규칙과 숫자는 주제 문서에 둡니다.
