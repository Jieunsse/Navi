# 나비 기능 명세

- 작성일: 2026-11-06
- 기준 문서: [00 기획 통합 브리핑](00-planning-brief.md), [03 고객 여정 지도](03-customer-journey-map.md), [06 결정 기록](06-decisions.md)
- 목적: 화면마다 무엇을 하고, 어떤 경우에 어떻게 동작하는지 정한다. 개발과 README의 기능 확인 절차는 이 문서를 기준으로 한다.
- 기술 구성: Next.js(Vercel), Firebase Auth와 Firestore, LiveKit Cloud, Cloudflare R2, 토스페이먼츠 테스트 모드. 고른 이유는 06 결정 기록에 있다.

## 1. 지켜야 할 원칙

이 원칙은 모든 화면과 기능에 적용한다.

1. **켜기까지의 단계를 줄인다.** 방송 만들기에서 필수 입력은 제목 하나뿐이고, 제목에도 기본값을 넣는다.
2. **브라우저가 만드는 단계는 미리 안내한다.** 화면 공유 창, 권한 창, 탭 오디오 체크가 뜨기 전에 무엇을 누를지 먼저 보여준다.
3. **방송은 어떤 방법으로 끝나도 확실하게 종료된다.** 종료 버튼, 크롬의 공유 중지, 탭 닫기, 휴대폰 잠금이 모두 해당한다.
4. **쓰기는 모두 서버를 거친다.** 서버가 로그인 상태와 소유자를 확인한 뒤 저장한다. 브라우저는 Firestore에 직접 쓰지 못한다.
5. **보기는 로그인 없이 된다.** 방송 목록, 시청, 다시보기, 채팅 읽기는 비로그인 사용자도 할 수 있다.

### 화면 사이의 흐름

- **방송자:** 홈 → 방송하기 → (로그인) → 방송 만들기 → 송출 화면 → 방송 종료 → 종료 안내 → 내 방송 관리 또는 다시보기
- **시청자:** 링크 또는 홈 → 방송 보기 → (채팅이나 후원을 하려 할 때 로그인) → 같은 방송 화면으로 돌아옴
- **로그인 뒤 돌아오기:** 로그인이 필요한 동작을 누르면 로그인 화면으로 간다. 로그인이 끝나면 원래 있던 화면으로 돌아간다. 쓰던 채팅 내용은 지우지 않는다.

## 3. 방송 상태

### 상태 세 가지

| 상태 | 뜻 | 시청자에게 보이는 것 |
|---|---|---|
| 준비(`ready`) | 방송을 만들었지만 아직 송출을 시작하지 않았다 | "곧 방송이 시작돼요" 안내 |
| 방송 중(`live`) | 송출 중이다 | 영상, 채팅, 후원 버튼 |
| 종료(`ended`) | 방송이 끝났다. 다시 방송 중으로 돌아가지 않는다 | "방송이 끝났어요" 안내. 녹화가 있으면 다시보기 링크 |

### 상태가 바뀌는 경우

| 무엇이 일어났나 | 바뀌는 상태 | 누가 바꾸나 |
|---|---|---|
| 방송자가 송출 화면에서 "방송 시작"을 누른다 | 바뀌지 않는다. 준비 그대로다 | 서버가 소유자를 확인하고 송출용 접속 권한만 준다(06 결정 25) |
| 송출이 LiveKit에 실제로 올라온다 | 준비 → 방송 중 | 송출 화면의 "송출 확인" 요청과 LiveKit의 "트랙이 올라왔다" 알림 가운데 먼저 온 것으로 서버가 바꾼다. 서버는 LiveKit 서버 API로 송출자(`host_사용자ID`)가 방에 있는지 확인한 뒤에 바꾼다. 둘 다 와도 한 번만 바꾼다 |
| "방송 시작"을 누르고 30초 안에 송출이 올라오지 않는다 | 바뀌지 않는다. 준비 그대로다 | 송출 화면이 LiveKit 연결을 끊고 "방송을 시작하지 못했어요. 다시 시도해 주세요"를 보여준다(PC는 D-9. 휴대폰 화면은 아직 없다). 연결을 끊었으므로 늦게 온 "트랙이 올라왔다" 알림은 송출자가 방에 없어 무시된다(7장). 다시 시도하면 새 송출용 접속 권한을 받는다. 30초는 임시값이다(06 결정 30) |
| 방송자가 "방송 종료"를 누른다 | 방송 중 → 종료 | 서버가 소유자를 확인하고 바꾼다. LiveKit 방을 닫아서 송출과 시청 연결을 모두 끊는다 |
| 방송자가 크롬의 "공유 중지"를 누른다 | 방송 중 → 종료 | 송출 화면이 공유가 끝난 것을 알아채고 종료를 요청한다 |
| 방송자가 탭을 닫거나 새로고침하거나 네트워크가 끊긴다 | 방송 중 → 종료 | LiveKit이 "송출자가 나갔다"는 알림을 서버에 보낸다. 서버가 종료로 바꾼다. 방송 중인 방송에는 송출용 접속 권한을 다시 주지 않으므로 새로고침한 화면도 다시 송출할 수 없다(06 결정 30) |
| 휴대폰 화면이 잠기거나 다른 앱으로 넘어가 송출 연결이 끊긴다 | 방송 중 → 종료 | 위와 같다 |
| 방송자가 준비 상태에서 방송을 삭제한다 | 방송 정보가 사라진다 | 서버가 소유자를 확인하고 지운다. LiveKit 방도 닫아서 기다리던 시청자 연결을 끊는다. 방이 없으면 오류로 보지 않는다(06 결정 30) |
| 방송자가 방송 중에 방송을 삭제하려 한다 | 바뀌지 않는다. 삭제할 수 없다 | 서버가 거절한다. 방송을 끝낸 뒤 내 방송 관리 목록에서 지운다(06 결정 24) |
| 운영자가 방송을 강제 종료하거나 방송 금지를 건다 | 방송 중 → 종료 | 서버가 운영자를 확인하고 바꾼다(4-15) |

- 종료는 되돌리지 않는다. 다시 방송하려면 새 방송을 만든다. 휴대폰이 잠깐 잠겨도 종료되는 것은 불편하다. 하지만 2주 범위에서는 "끊기면 끝난다"를 명확하게 지키는 쪽을 고른다.
- 송출용 접속 권한은 준비 상태인 방송에만 준다. 방송 중인 방송의 송출 화면에는 다시 들어갈 수 없다. 테스트 방송자 계정은 심사자가 함께 쓰므로, 다시 들어가기를 허용하면 다른 심사자가 진행 중인 방송을 가로챌 수 있기 때문이다. 네트워크가 흔들려 LiveKit이 스스로 다시 연결하는 경우는 처음 받은 권한을 쓰므로 막히지 않는다(06 결정 30).
- LiveKit 방 이름은 방송 ID와 같다. 웹훅(7장)은 방 이름으로 방송 문서를 바로 찾는다(06 결정 30).
- 상태가 바뀌면 방송 보기 화면과 홈 목록에 바로 반영된다. Firestore 실시간 구독을 쓰기 때문이다.
- 같은 종료 요청이 두 번 와도(버튼과 알림이 함께 오는 경우) 한 번만 처리한다. 이미 종료된 방송에 온 종료 요청은 무시한다.

### 방송 종료는 서버 함수 하나가 처리한다

방송을 종료하는 경로는 네 가지다. 종료 버튼, 크롬 공유 중지, LiveKit 끊김 알림, 운영자의 강제 종료와 방송 금지다. 방송 중 삭제는 경로가 아니다. 방송 중에는 삭제할 수 없기 때문이다(06 결정 24). 네 경로 모두 서버의 "방송 종료" 함수 하나를 부른다. 경로마다 따로 만들면 한 경로에서 미션 반환이나 녹화 상태 변경을 빠뜨리기 쉽기 때문이다.

이 함수는 트랜잭션 하나 안에서 아래를 함께 처리한다.

1. 방송 상태를 종료로 바꾸고 종료 시각을 저장한다. 이미 종료된 방송이면 아무것도 하지 않고 끝낸다. 방송 중인 방송만 종료로 바꾼다. 준비 상태인 방송에 LiveKit 알림이 오면 아무것도 하지 않는다(7장). 준비 상태에서는 시청자만 방에 들어와 있으므로, 시청자가 모두 나가 방이 닫혀도 방송은 준비 상태로 남아야 하기 때문이다.
2. 녹화가 "녹화 중"이면 "처리 중"으로 바꾼다(4-9).
3. 그 방송의 미션을 정리한다(4-8). 대기 중 미션은 "취소됨"으로 바꾸고 묶어 둔 꿀을 모두 돌려준다. 진행 중 미션은 "실패"로 바꾸고, 실패 시 응원금은 방송자에게 주고 나머지는 시청자에게 돌려준다. 꿀이 움직인 기록은 꿀 내역에 남긴다.
4. 방송자의 방송 횟수(10분 이상 이어진 방송만)와 누적 방송 시간을 더하고 승급을 확인한다(4-12).

트랜잭션이 끝나면 LiveKit 방을 닫는다. 방이 이미 닫혀 있으면 오류로 보지 않는다.

Firestore 값이 바뀔 때 자동으로 실행되는 기능(Cloud Functions 트리거)은 쓰지 않는다. 무료 플랜에서 쓸 수 있는지 확인하지 못했다. 또 결정 2의 "쓰기는 모두 Next 서버를 거친다"와 맞추기 위해서다.

## 4. 기능별 동작

### 4-1. 회원가입, 로그인, 로그아웃

- **회원가입:** 이메일, 비밀번호, 닉네임을 받고 약관 동의를 받는다. 계정과 사용자 정보는 서버가 한 번에 만든다. 브라우저가 계정을 먼저 만들면, 닉네임이 겹쳐 가입이 실패해도 계정이 남는다. 그러면 그 이메일로 다시 가입할 수 없다.
  1. 브라우저는 이메일, 비밀번호, 닉네임, 동의 내역을 서버에 한 번에 보낸다.
  2. 서버가 입력을 검사한다. 형식, 금칙어, 필수 동의를 확인한다.
  3. 서버가 새 사용자 ID를 먼저 만든다. 그다음 트랜잭션 안에서 닉네임 중복을 확인하고, 닉네임 문서와 사용자 문서를 함께 저장한다.
  4. 서버가 Firebase 관리자 SDK로 그 ID의 계정을 만든다. 이미 가입된 이메일이라 실패하면, 3단계에서 저장한 두 문서를 지우고 "이미 가입된 이메일이에요"를 보여준다.
  5. 성공하면 브라우저가 이메일과 비밀번호로 로그인한다.
  - 닉네임을 이메일보다 먼저 확인하는 이유가 있다. 닉네임 확인은 실패해도 되돌릴 것이 없다. 그래서 더 자주 실패하는 쪽을 먼저 확인한다.
- **비밀번호 확인:** 가입 화면에 "비밀번호 확인" 칸을 둔다. 두 칸이 같아야 가입 버튼이 눌린다. 비교는 브라우저에서만 하고, 서버에는 비밀번호 하나만 보낸다. 다르면 칸에서 벗어날 때 "비밀번호가 같지 않아요"를 보여준다.
- **비밀번호 보기:** 모든 비밀번호 칸(로그인, 가입, 탈퇴할 때 다시 입력) 오른쪽에 눈 아이콘을 둔다.
  - 처음에는 입력한 글자를 ●●●로 가린다.
  - 눈 아이콘을 누르면 입력한 글자가 보이고, 아이콘이 "눈 감기"로 바뀐다. 다시 누르면 ●●●로 돌아간다.
  - 칸마다 따로 동작한다. 비밀번호 칸을 보이게 해도 비밀번호 확인 칸은 그대로 가려져 있다.
  - 화면을 새로 열면 다시 가려진 상태로 시작한다.
  - 화면 읽기 프로그램에는 "비밀번호 보기", "비밀번호 숨기기"로 읽히게 한다.
- **닉네임 중복 확인:** 가입 화면의 닉네임 칸 옆에 "중복 확인" 버튼을 둔다.
  - 칸이 비어 있으면 버튼이 눌리지 않는다.
  - 누르면 서버가 닉네임 규칙(길이, 글자, 금칙어)과 중복을 확인한다. 쓸 수 있으면 칸 아래에 "쓸 수 있는 닉네임이에요"를 보여준다. 쓸 수 없으면 아래 오류 표의 닉네임 안내를 보여준다.
  - 중복 확인을 통과해야 가입 버튼이 눌린다. 확인한 뒤 닉네임을 고치면 다시 확인해야 한다.
  - 중복 확인은 닉네임을 붙잡아 두지 않는다. 가입할 때 서버가 트랜잭션 안에서 한 번 더 확인한다(회원가입 3단계). 그 사이 다른 사람이 같은 닉네임으로 가입했으면 "이미 쓰고 있는 닉네임이에요"를 보여준다.
  - 구글 가입 마무리 화면과 닉네임 변경(4-11)에도 같은 버튼을 둔다.
- **가입 버튼이 눌리는 조건:** 이메일 형식이 맞고, 비밀번호가 6자 이상이고, 비밀번호 확인이 같고, 닉네임 중복 확인을 통과했고, 필수 약관에 모두 동의했을 때다.
- **약관 동의:** 가입 화면에서 아래 항목에 동의를 받는다. 필수 항목에 모두 동의해야 가입 버튼이 눌린다. "전체 동의"를 누르면 모든 항목이 한 번에 체크된다. 각 항목 옆의 "보기"를 누르면 전문(`/terms`, `/terms/streamer`, `/privacy`)이 열린다.
  - 만 14세 이상입니다(필수)
  - 이용약관 동의(필수)
  - 방송자 이용약관 동의(필수). 나비는 가입하면 누구나 바로 방송하고 후원을 받을 수 있다. 그래서 방송자 등록 단계를 따로 두지 않고 가입할 때 함께 동의받는다(06 결정 9, 09 초안 제5조)
  - 개인정보 수집과 이용 동의(필수)
  - 서버는 필수 항목 동의 없이 온 가입 요청을 거절한다. 동의한 항목, 약관 버전, 동의 시각을 저장한다.
- **닉네임 규칙**
  - 2~12자다. 한글, 영문, 숫자만 쓸 수 있고 띄어쓰기는 쓸 수 없다.
  - 다른 사용자와 겹칠 수 없다. 영문은 대소문자를 구분하지 않고 비교한다. 서버가 트랜잭션 안에서 중복을 확인한 뒤 저장한다. 그래서 두 사람이 같은 닉네임으로 동시에 가입해도 한 명만 성공한다.
  - 금칙어(4-7의 채팅 걸러내기와 같은 목록)가 들어간 닉네임은 쓸 수 없다.
  - 가입한 뒤 **한 번만** 바꿀 수 있다(4-11). 바꾸기 전에 "닉네임은 한 번만 바꿀 수 있어요"를 확인 창으로 알린다.
- **로그인:** 이메일과 비밀번호, 또는 구글 계정으로 로그인한다. 로그인 상태는 새로고침해도 유지된다.
- **구글 로그인:** 로그인 화면의 "Google로 계속하기"를 누르면 구글 계정으로 로그인한다. 처음 쓰는 사람은 이 버튼 하나로 가입까지 한다. 가입 화면의 단계를 줄이기 위해서다(03 고객 여정 지도 2단계).
  1. 브라우저가 Firebase Auth의 구글 로그인 창(팝업)을 띄운다. 브라우저가 팝업을 막으면 구글 로그인 페이지로 이동했다가 돌아오는 방식으로 바꾼다.
  2. 구글 로그인이 끝나면 브라우저가 서버에 "이 사용자의 사용자 문서가 있는지"를 묻는다.
  3. 사용자 문서가 있으면 로그인이 끝난다. 원래 있던 화면으로 돌아간다.
  4. 사용자 문서가 없으면 처음 온 사람이다. 구글 가입 마무리 화면(`/signup/google`)으로 보낸다. 이 화면은 닉네임과 필수 약관 네 가지만 받는다. 이메일과 비밀번호는 받지 않는다.
  5. 서버는 로그인 토큰으로 사용자 ID를 확인한다. 그다음 회원가입 3단계와 같이 트랜잭션 안에서 닉네임 중복을 확인하고, 닉네임 문서와 사용자 문서를 함께 저장한다. 닉네임 규칙과 약관 동의 규칙은 이메일 가입과 같다.
  6. 저장이 끝나면 원래 있던 화면(없으면 홈)으로 간다.
  - 구글 로그인은 이메일 가입과 달리 Firebase 계정이 먼저 생긴다. 구글 계정 확인은 Firebase Auth 로그인 창이 해야 하기 때문이다. 그래서 가입 마무리를 하지 않고 나가면 Firebase 계정만 남는다. 이 계정으로 다시 구글 로그인하면 4단계부터 다시 한다. 남은 계정 때문에 다시 가입하지 못하는 일은 없다.
  - 서버는 사용자 문서가 없는 로그인을 비로그인과 똑같이 다룬다. 그래서 가입 마무리를 하지 않은 사람은 채팅, 후원, 방송을 할 수 없다. 서버는 이 요청에 401 오류와 "가입을 마무리해 주세요"를 돌려준다. 브라우저는 이 오류를 받으면 가입 마무리 화면으로 보낸다.
  - 닉네임은 구글 계정 이름을 그대로 쓰지 않는다. 닉네임 규칙(2~12자, 한글·영문·숫자)에 맞지 않는 이름이 많기 때문이다. 입력 칸은 비워 둔다.
  - 이메일 하나에는 계정 하나만 둔다(Firebase Auth 기본 설정). 이메일로 가입한 사람이 같은 Gmail 주소로 구글 로그인하면 같은 계정으로 들어간다. 이때 Firebase가 기존 비밀번호 로그인을 지우는지는 확인하지 못했다. 공식 문서로 확인해야 한다.
- **로그아웃:** 화면 오른쪽 위 메뉴에서 로그아웃한다. 로그아웃하면 홈으로 간다.
- **비밀번호 찾기:** 로그인 화면의 "비밀번호를 잊었어요"에서 이메일을 받는다. Firebase Auth가 비밀번호를 다시 정하는 메일을 보낸다. 가입하지 않은 이메일을 넣어도 "비밀번호를 다시 정하는 링크를 보냈어요. 메일이 오지 않으면 스팸함을 확인해 주세요"로 똑같이 안내한다. 가입 여부를 알려주지 않기 위해서다.
- **테스트 계정 바로 로그인:** 로그인 화면에 "테스트 방송자로 로그인", "테스트 시청자로 로그인", "테스트 운영자로 로그인" 버튼을 둔다. 운영자 버튼은 심사자가 신고 처리와 제재를 해 보게 하기 위해서다(4-15). 공모 요강이 요구하는 기능이고, 심사자가 채점할 때 가입 없이 바로 써 보게 하기 위해서다. 방송자와 시청자 두 계정이 있어야 "방송 소유자"와 "다른 사용자"를 나눠 확인할 수 있다. 버튼은 비밀번호 없이 서버가 만든 로그인 토큰으로 들어간다. 계정 구성과 미리 넣는 데이터는 4-18에 있다. 테스트 계정은 닉네임 변경과 회원 탈퇴를 막는다. 심사자 한 명이 바꾸거나 지우면 다음 심사자가 쓸 수 없기 때문이다.
- **오류:** 아래 경우에 입력 칸 아래에 이유를 보여준다. 로그인 오류는 이메일과 비밀번호 중 어느 쪽이 틀렸는지 알려주지 않는다.

### 4-2. 홈(방송 목록)

- 홈은 위에서 아래로 다음 순서로 채운다(06 결정 31).
  1. 안내 카드 줄: 나비 자체 안내 5개(첫 방송 켜기, 꿀 충전과 후원, 다시보기, 등급과 수익 배분, 심사용 테스트 계정). 누르면 해당 화면으로 간다. 그림은 색 배경과 아이콘으로 만든다.
  2. 지금 방송: 방송 중인 방송 중 가장 최근에 시작한 것 하나를 크게, 다음 4개를 2×2로 보여준다. 방송 중인 방송이 모자라면 준비 중인 방송으로 채운다. 오른쪽 위에 "방송하기" 버튼을 둔다.
  3. 가로 광고 배너: 오른쪽 위에 "광고 예시"를 표시하고, 도움말로 광고가 나비의 수익 모델이라는 것을 알린다. 내용은 나비 자체 프로모션이다. 실제 광고는 붙이지 않는다.
  4. 카테고리별 방송: 카테고리 탭(전체와 8개)과 그 카테고리의 방송 카드 가로 줄. "전체보기"를 누르면 줄이 격자로 펼쳐진다. 사이드바의 카테고리를 누르면 이 탭이 선택된 채로 열린다(`/?category=게임`).
  5. 다시보기: 최근 공개 다시보기 12개의 카드 가로 줄과 "전체보기"(`/replays`). 다시보기 목록 화면은 최근 50개까지 보여준다.
- 방송이 하나도 없으면 방송 영역에만 "지금 방송 중인 사람이 없어요"와 "방송하기" 버튼을 보여주고, 안내 카드·광고 배너·다시보기는 그대로 둔다.
- 오른쪽 아래에 나비 이벤트 팝업을 홈에서만 띄운다. "1일간 보지 않기"는 브라우저에 저장하고, "닫기"는 이번 화면에서만 닫는다. 휴대폰에서는 화면 아래 띠로 줄여 보여준다.
- 영상 썸네일이 없어서 카드는 카테고리별 색 배경, 카테고리 아이콘, 방송자 아바타로 채운다. 시드 방송은 제목에 "예시"가 들어 있다. 카드에 따로 표시를 붙이지는 않는다. 시드 방송을 열면 "예시 방송이라 영상이 나오지 않아요"를 보여준다. 카드는 넓은 화면에서 한 줄에 4~5개가 들어가게 한다.
- 방송 중인 방송을 먼저 보여준다. 그 안에서는 최근에 시작한 방송이 위에 온다.
- 그 아래에 준비 중인 방송을 최근에 만든 순서로 보여준다. 만든 지 1시간이 지난 준비 중 방송은 보여주지 않는다. 지우지는 않고 내 방송 관리에는 남는다(06 결정 19). 1시간은 임시값이다. 종료된 방송은 홈에 보여주지 않고 다시보기 목록에서 보여준다.
- 시청자 수로 정렬하지 않는다. 그래서 방금 켠 작은 방송도 맨 위에 보인다(06 결정 5, 31).
- 카드에는 제목, 방송자 닉네임, 카테고리, 상태, 시작 시각을 보여준다. 준비 중인 방송은 시작 시각 대신 "곧 시작"을 보여준다. 방송 중인 카드에는 상태 옆에 지금 보는 사람 수를 "1,234명"으로 보여준다(4-6).
- 시청자 수로 정렬하지는 않는다. 숫자는 보여주기만 한다.
- "방송하기" 버튼은 지금 방송 영역 위쪽에 항상 둔다.

### 4-3. 방송 만들기

- 로그인하지 않았으면 로그인 화면으로 보낸다. 로그인하면 이 화면으로 돌아온다.
- **입력 항목**
  - 제목: 필수다. 기본값은 "[닉네임]의 방송"이다. 1~50자다.
  - 카테고리: 잡담, 게임, 공부, 음악, 요리, 그림, 운동, 여행 중 하나를 고른다. 필수는 아니고 기본은 "잡담"이다. 방송 문서에 `category`로 저장하고, 값이 없는 예전 방송은 "잡담"으로 본다(06 결정 31). 방송 보기 화면 정보 줄에 보여준다.
  - 송출 방식: "PC 화면 공유"와 "카메라" 중 하나를 고른다. 휴대폰으로 들어오면 카메라를 기본으로 고르고, PC로 들어오면 화면 공유를 기본으로 고른다. 휴대폰 브라우저에서는 화면 공유를 고를 수 없다.
  - 내 얼굴도 같이 보여주기: PC에서 "PC 화면 공유"를 골랐을 때만 스위치를 보여준다. 기본은 꺼짐이다. 켜면 화면과 함께 카메라를 송출한다(06 결정 15). 필수 기능이 끝난 뒤에 만든다.
  - 녹화는 여기서 고르지 않는다. 송출 화면에서 방송을 시작하기 직전에 고른다(4-4, 4-5, 06 결정 24).
- 영구 정지 계정과 방송 금지 기간인 계정은 방송을 만들 수 없고 송출도 시작할 수 없다. "운영정책 위반으로 ○월 ○일까지 방송할 수 없어요"를 보여준다(4-15).
- "만들기"를 누르면 서버가 방송을 준비 상태로 저장하고 송출 화면으로 보낸다.
- 방송 링크는 이때 만들어진다. 그래서 방송을 시작하기 전에 링크를 먼저 복사할 수 있다.

### 4-4. 송출 화면 (PC 화면 공유)

방송 소유자만 들어올 수 있다. 다른 사용자가 주소를 열면 "이 방송의 송출 화면은 방송자만 열 수 있어요"를 보여준다.

1. **공유 전 안내:** "화면 공유 시작"을 누르기 전에 그림으로 안내한다. 내용은 세 가지다.
   - "Chrome 탭"을 고르면 가장 쉽다.
   - "탭 오디오도 공유"가 켜져 있어야 소리가 나간다.
   - 창이나 전체 화면을 고르면 맥에서 화면 기록 권한과 크롬 재시작이 필요할 수 있다.
2. **화면 공유와 마이크:** 브라우저의 공유 창이 뜬다. 공유가 시작되면 마이크 권한을 요청한다.
3. **미리보기:** 공유한 화면을 보여준다. 탭 소리 막대와 마이크 소리 막대를 따로 보여준다.
4. **소리 경고:** 공유에 소리 트랙이 없으면 "탭 소리가 들어오지 않아요. 탭 오디오 공유를 켜고 다시 공유해 주세요"를 띄우고 "다시 공유" 버튼을 준다.
5. **녹화 고르기:** 미리보기 아래, "방송 시작" 버튼 바로 위에 "이 방송 녹화하기" 스위치를 둔다. 기본은 꺼짐이다. LiveKit 무료 녹화가 한 달 60분뿐이기 때문이다(06 결정 6). 스위치 옆에 "?" 도움말 아이콘을 두고, 마우스를 올리면 "켜면 방송이 끝난 뒤 다시보기가 만들어져요. 한 번에 3분까지 녹화되고, 처음에는 나만 볼 수 있어요"를 말풍선으로 보여준다(06 결정 29). 방송이 시작된 뒤에는 바꿀 수 없다(06 결정 24).
6. **방송 시작:** "방송 시작"을 누르면 서버가 소유자를 확인하고 송출용 접속 권한(LiveKit 토큰)을 준다. 녹화 스위치 값도 함께 보내고, 서버가 방송 문서의 녹화 여부에 저장한다. 송출 화면은 화면과 소리를 LiveKit에 올린 뒤 서버에 "송출 확인"을 보낸다. 서버가 송출을 확인하면 상태가 방송 중으로 바뀐다(3장, 06 결정 25). 그동안 버튼에 회전 표시를 보여준다.
7. **방송 중:** 링크 복사 버튼, 경과 시간, 채팅 목록, 후원 알림을 보여준다.
8. **방송 정보 수정:** 방송 중에도 제목을 바꿀 수 있다.
   - **시청자 화면으로 보기:** 방송 중에 "시청자 화면으로 보기"를 누르면 방송 보기 화면(`/live/[방송ID]`)을 새 탭으로 연다. 시청자에게 어떻게 보이는지 직접 확인하게 하기 위해서다. 치지직 스튜디오의 "내 방송 보기"와 같은 역할이다(레퍼런스 `studio-방송하기-전체.webp`). 이 탭은 소리를 끈 채로 연다. 소리가 켜져 있으면 마이크가 그 소리를 다시 받아 시청자에게 울려 들린다. 자기 방송에는 후원할 수 없으므로 후원 버튼은 눌리지 않는다(5장 권한 표).
   - **연결 상태:** 방송 중에 경과 시간 옆에 연결 상태를 "좋음", "불안정", "다시 연결 중" 세 가지로 보여준다. 치지직은 해상도, 비트레이트, FPS를 숫자로 보여주지만(레퍼런스 `studio-방송하기-전체.webp`), 처음 방송하는 사람은 숫자를 읽기 어렵다. 그래서 말로만 보여준다.
     - 값은 LiveKit이 브라우저에 알려주는 내 연결 품질을 쓴다. 매우 좋음과 좋음은 "좋음", 나쁨은 "불안정"이다. 연결이 끊겨 LiveKit이 다시 연결을 시도하는 동안은 "다시 연결 중"이다. 서버를 거치지 않으므로 추가 비용이 없다.
     - "불안정"이 10초 넘게 이어지면 "인터넷이 불안정해서 시청자 화면이 끊길 수 있어요. 다른 탭의 동영상이나 내려받기를 멈춰 보세요"를 경고 띠로 보여준다. 연결이 "좋음"으로 돌아오면 경고 띠를 내린다. 10초는 임시값이다.
     - 연결 상태는 송출 화면에만 보여준다. 시청자 화면에는 보이지 않는다.
     - 다시 연결하지 못해 서버가 방송을 종료하면 종료 화면으로 바뀐다(3장의 LiveKit 끊김 알림 경로).
   - **떠나기 경고:** 방송 중에 새로고침하거나 탭을 닫으려 하면 브라우저 기본 확인 창("이 사이트에서 나가시겠습니까?")을 띄운다. 나가면 방송이 끝나고 다시 송출할 수 없기 때문이다(06 결정 30).
9. **방송 종료:** "방송 종료"를 누르면 확인 창을 띄운 뒤 종료한다. 종료 화면으로 바꾸고 "방송이 끝났어요. 시청자에게도 끝났다고 보여요"를 보여준다. 녹화를 켰다면 "다시보기를 만드는 중이에요. 다 되면 내 방송 관리에서 공개할 수 있어요"를 함께 보여준다.

**카메라를 함께 보낼 때(06 결정 15):** "내 얼굴도 같이 보여주기"를 켰다면 마이크 권한과 함께 카메라 권한을 요청한다. 미리보기에서 화면 오른쪽 아래에 작은 카메라 창을 보여준다. 방송 중에 카메라 버튼으로 카메라만 끄고 켤 수 있다. 카메라를 거부하거나 카메라가 없으면 "카메라를 켜지 못했어요. 화면만 송출돼요"를 보여주고 방송 시작은 허용한다.

**권한을 거부했을 때:** 화면 공유를 거부하면 이유와 다시 켜는 방법을 보여준다. 화면 공유 없이는 방송을 시작할 수 없다. 마이크를 거부한 경우 크롬 주소창 왼쪽의 아이콘에서 다시 허용하라고 안내한다.

**마이크 없이 방송할 때:** 마이크를 거부했거나 마이크가 없어도 경고를 보여준 뒤 방송 시작은 허용한다. 대신 방송이 끝날 때까지 송출 화면 위쪽에 "마이크가 꺼져 있어요. 시청자에게 내 목소리가 들리지 않아요"를 계속 보여준다. 이 안내는 닫을 수 없다. 방송 중에 마이크 권한을 다시 허용하면 안내가 사라지고 마이크 소리가 송출된다. 방송자가 마이크 버튼으로 잠깐 끈 경우에도 같은 안내를 보여준다.

### 4-5. 송출 화면 (휴대폰 카메라)

1. **링크 먼저 복사:** 시작 전에 "링크를 먼저 복사해 두세요. 방송 중에 다른 앱으로 가면 방송이 끝나요"를 보여준다.
2. **권한 안내:** "다음 창에서 허용을 눌러 주세요"를 먼저 보여주고 카메라와 마이크 권한을 요청한다.
3. **미리보기:** 카메라 영상과 마이크 소리 막대를 보여준다. 앞과 뒤 카메라를 바꾸는 버튼을 둔다.
4. **녹화 고르기와 방송 시작, 종료:** PC와 같다. 미리보기 아래에 "이 방송 녹화하기" 스위치를 두고, 방송 시작 전에 고른다. 방송 중 연결 상태 표시와 불안정 경고도 PC(4-4)와 같다. 휴대폰 경고 문구는 "인터넷이 불안정해서 시청자 화면이 끊길 수 있어요. 와이파이가 잘 잡히는 곳으로 옮겨 보세요"다.
5. **화면 꺼짐 안내:** 방송 중에는 "화면을 켜 둔 채로 두세요"를 계속 보여준다.
6. **끊겼을 때:** 다른 앱으로 넘어가거나 화면이 잠겨 송출이 끊기면 방송은 종료된다. 다시 돌아오면 송출 화면이 서버의 방송 상태를 확인한다. 종료면 "방송이 끝났어요. 새 방송 만들기" 버튼을 보여준다. 아직 방송 중이고 LiveKit이 스스로 다시 연결했으면 송출 화면을 그대로 둔다. 아직 방송 중인데 다시 연결하지 못했으면 서버에 종료를 요청한 뒤 "방송이 끝났어요"를 보여준다. 방송 중인 방송에는 송출용 접속 권한을 다시 주지 않기 때문이다(06 결정 30).

**권한을 거부했을 때:** 아이폰에서는 설정 앱에서 다시 켜야 한다고 안내한다. 카메라를 거부하면 방송을 시작할 수 없다. 마이크만 거부했다면 PC와 같이 시작은 허용하고 "마이크가 꺼져 있어요" 안내를 계속 보여준다. HTTPS가 아니면 카메라가 켜지지 않는다. 배포 주소는 항상 HTTPS다.

### 4-6. 방송 보기

- 로그인 없이 볼 수 있다. 서버가 시청 전용 접속 권한(송출 불가)을 준다. 이 권한은 방송이 준비 상태이거나 방송 중일 때만 준다. 종료된 방송과 지운 방송에는 주지 않고, 화면은 Firestore 기록만 보여준다. 끝난 방송에 시청자가 들어와 방이 다시 생기면 무료 사용량이 줄기 때문이다(06 결정 27).
- **상태별 화면**
  - 준비: "곧 방송이 시작돼요"를 보여준다. 방송이 시작되면 새로고침 없이 영상이 나온다.
  - 방송 중: 영상을 재생한다. 방송자가 카메라도 함께 보내면 화면 오른쪽 아래에 작은 카메라 창을 얹는다. 카메라 영상이 없으면 창을 숨긴다(06 결정 15).
  - 종료: "방송이 끝났어요"를 보여준다. 녹화가 있으면 "다시보기" 버튼을 보여준다.
- **소리:** 영상은 소리를 끈 채 자동 재생한다. 화면 가운데에 "눌러서 소리 켜기" 버튼을 크게 둔다. 아이폰은 소리가 있는 자동 재생을 막기 때문이다.
- **송출이 잠깐 끊겼을 때:** 영상이 멈추면 "방송자 연결을 기다리는 중이에요"를 보여준다.
- **방송 정보:** 제목, 방송자 닉네임, 카테고리, 시작 시각을 보여준다. 후원 합계는 후원이 한 번이라도 있을 때만 정보 줄에 보여주고, 채팅 위쪽에는 늘 보여준다. 방송 중이면 지금 보는 사람 수("1,234명 시청")를 함께 보여준다.
- **시청자 수:** 서버가 LiveKit 웹훅의 `participant_joined`와 `participant_left`(이름이 `viewer_`로 시작하는 참가자)를 받을 때마다 그 방의 참가자 목록을 LiveKit 서버에서 받아 `viewer_`로 시작하는 수를 세고, 방송 문서의 `viewerCount`에 저장한다. 하나씩 더하고 빼지 않고 매번 다시 세므로 알림이 빠져도 다음 알림에서 바로잡힌다. 방송이 끝나면 0으로 바꾼다. 같은 사람이 탭을 여러 개 열면 여러 명으로 센다. 화면은 Firestore 문서를 구독해서 새로고침 없이 바뀐다(06 결정 31).
- **채팅과 후원:** 화면 오른쪽(휴대폰은 영상 아래)에 채팅 목록과 입력 칸, 후원 버튼을 둔다.

### 4-7. 채팅

공모 요강의 "댓글"은 나비에서 방송 화면 옆에 실시간으로 올라오는 **채팅**이다. 방송자와 시청자가 같은 채팅 목록에 쓴다. 화면에는 "채팅"으로 적는다. 전달 방식은 06 결정 12에, 수정·삭제 규칙은 06 결정 32에 있다.

- **읽기:** 누구나 읽을 수 있다. 새 채팅은 새로고침 없이 바로 나타난다.
- **쓰기:** 로그인한 사용자만 쓸 수 있다. 비로그인 사용자가 입력 칸을 누르면 로그인 화면으로 보내고, 로그인 뒤 같은 방송으로 돌아온다. 1~200자다.
- **수정과 삭제:** 내 채팅만 고치거나 지울 수 있다. 서버가 작성자 본인인지 확인하고, 아니면 403으로 거절한다. 준비 상태와 방송 중에만 된다. 고친 채팅에는 "(수정됨)"을 붙이고, 지운 채팅은 "삭제된 채팅이에요"로 남긴다. 후원과 미션 메시지는 고치거나 지울 수 없다. 고친 내용도 금칙어 검사를 다시 한다. 바꾸기 전 원문은 운영자만 보는 기록에 남긴다(06 결정 32).
- **언제 쓸 수 있나:** 준비 상태와 방송 중에만 쓸 수 있다. 종료된 방송과 다시보기에서는 읽기만 하고, 입력 칸에 "방송이 끝나 채팅을 쓸 수 없어요"를 보여준다. 서버도 종료된 방송으로 온 채팅 쓰기를 거절한다.
- **도배 막기:** 한 사람이 같은 방송에 1초에 1개까지 보낼 수 있다. 넘으면 서버가 거절하고 입력 칸 아래에 "조금 천천히 보내 주세요"를 보여준다. 쓰던 내용은 지우지 않는다. 1초는 임시값이다.
- 방송자가 쓴 채팅에는 닉네임 옆에 "방송자" 표시를 붙인다.

**전달 방식**

채팅은 LiveKit 연결로 실시간 전달하고, Firestore에 저장한다. 시청자와 방송자는 영상 때문에 이미 LiveKit 방에 연결돼 있다. 그래서 채팅을 위한 서버를 따로 두지 않는다.

1. 브라우저가 채팅을 서버(Next.js)에 보낸다. 브라우저가 고른 메시지 번호를 함께 보낸다.
2. 서버가 로그인, 방송 상태, 도배, 금칙어를 확인한다.
3. 서버가 메시지 번호를 문서 ID로 Firestore에 저장한다. 같은 요청이 두 번 와도 한 번만 저장된다.
4. 서버가 LiveKit 서버 API로 그 방에 채팅을 보낸다. 주제(topic)는 `chat`이다. 실패하면 한 번 다시 보낸다.
5. 방에 연결된 모든 브라우저가 받아서 목록에 붙인다. 이미 있는 메시지 번호는 다시 붙이지 않는다.

- **브라우저는 LiveKit으로 직접 보내지 못한다.** 서버가 주는 접속 권한에서 데이터 보내기를 끈다. 그래서 서버 확인을 건너뛴 메시지는 방에 들어오지 못한다.
- **방에 들어올 때와 다시 연결될 때:** Firestore에서 최근 채팅 50개를 한 번 불러온다. 그 뒤로는 LiveKit으로 받는다. 연결이 끊겼다 돌아오면 다시 불러와 빠진 메시지를 채운다.
- **같은 길로 보내는 것:** 후원 항목과 미션 상태 변화도 서버가 Firestore에 저장한 뒤 같은 방법으로 보낸다. 주제는 `donation`, `mission`이다. LiveKit으로 보내는 내용은 채팅 모음 문서와 같은 필드만 담는다. 익명 후원이면 후원자 ID와 닉네임을 넣지 않고 "익명"만 넣는다(06 결정 27).
- **Firestore 실시간 구독을 계속 쓰는 것:** 방송 상태, 후원 합계, 홈 목록이다.
- **종료된 방송과 다시보기:** LiveKit 방이 닫혀 있으므로 Firestore에서 최근 채팅 50개를 불러온다. 그보다 오래된 채팅은 보이지 않는다.

**나쁜 말 걸러내기**

- 서버는 채팅을 저장하기 전에 금칙어 목록으로 내용을 검사한다. 욕설, 비하, 성적인 표현이 대상이다.
- 걸리면 채팅을 저장하되 "숨김" 상태로 저장한다. 원래 내용은 서버만 읽는 곳에 따로 둔다. 그래서 브라우저는 숨긴 채팅의 원래 내용을 받지 못한다.
- 숨긴 채팅은 모든 사람(작성자 포함)에게 "부적절한 표현이 감지되어 숨긴 채팅이에요"로 보인다.
- 숨긴 채팅을 LiveKit으로 보낼 때도 원래 내용은 넣지 않는다. 숨김 표시만 보낸다.
- 후원 메시지도 같은 방법으로 검사한다. 걸리면 후원은 그대로 확정한다. 메시지만 같은 안내로 숨긴다. 돈이 오간 기록은 막지 않기 위해서다. 미션 내용은 금칙어가 있으면 미션을 만들지 않는다(4-8).
- 닉네임과 방송 제목은 금칙어가 있으면 저장하지 않고 입력 칸 아래에 이유를 보여준다.
- 금칙어 목록은 Firestore 설정 문서 하나에 두고, 운영자 화면에서 고친다(4-15). 서버는 목록을 1분 동안 기억해 두고 쓴다. 그래서 목록을 바꾸면 1분 안에 채팅 검사에 쓰인다. 처음 목록은 코드 안의 파일로 시드한다. 띄어쓰기, 특수문자, 반복 글자를 지운 뒤 비교한다. 예를 들어 "ㅅ.ㅂ"처럼 사이에 기호를 넣어도 걸린다.

### 4-8. 후원

후원은 **꿀**로 한다. 꿀은 나비 안에서 쓰는 후원용 포인트다. 시청자가 꿀을 충전해 두고, 방송 중에 꿀을 써서 후원한다. 꿀 1개는 1원이다. "꿀"은 임시 이름이다(12장).

꿀은 나비가 파는 디지털 상품이다. 후원에 쓴 꿀은 나비 매출이 되고, 방송자는 나비에게서 수익 배분금을 받는다(4-12). 사용자끼리 꿀을 주고받는 기능과 꿀을 현금으로 바꾸는 기능은 없다. 문서와 화면에서 "가상화폐"라고 쓰지 않는다. 결정 이유는 06 결정 22에 있다.

치지직 후원 창을 참고했다. 후원 창은 화면 아래에서 올라오는 창(바텀시트)이다. PC에서는 채팅 영역 위에 같은 모양으로 뜬다.

#### 후원할 수 있는 때

- 채팅 후원은 준비 상태와 방송 중에 할 수 있다. 미션 후원은 방송 중에만 할 수 있다. 준비 상태에서도 미션 탭은 열린다. 안에는 "방송이 시작되면 미션을 보낼 수 있어요"만 보여주고 보내기 버튼은 없다. 서버도 거절한다(06 결정 25). 준비 상태 방송은 시작하지 않은 채 남거나 지워질 수 있어서, 미션에 묶인 꿀을 정리할 길이 없기 때문이다.
- 종료된 방송과 다시보기 화면에는 후원 버튼이 없다. 서버도 종료된 방송으로 온 후원 요청을 거절한다.
- 로그인해야 한다. 비로그인 사용자가 "후원하기"를 누르면 로그인 화면으로 보낸다. 로그인하면 같은 방송으로 돌아와 후원 창이 열린다.
- 내 방송에는 후원할 수 없다. 버튼은 눌리지 않고 "내 방송에는 후원할 수 없어요"를 말풍선으로 보여준다. 서버도 거절한다.

#### 후원 창의 구성

후원 창 위쪽에 "채팅"과 "미션" 탭이 있다. 처음에는 "채팅" 탭이 열린다.

**채팅 후원 탭**

1. **후원 메시지 칸:** 위쪽에 내 닉네임을 보여준다. 그 아래에 "후원과 함께 채팅을 보내세요" 입력 칸이 있다. 0~100자이고 비워도 된다. 글자 수(예: 0/100)를 칸 오른쪽에 보여준다.
2. **익명 스위치:** 닉네임 오른쪽에 둔다. 켜면 채팅 목록, 송출 화면 알림, 방송자의 후원 내역에 닉네임 대신 "익명"으로 보인다. 서버는 실제 후원자 ID를 그대로 저장한다. 후원자 본인의 내 후원 내역에는 "익명으로 후원함"을 붙여 보여준다.
3. **채팅 읽어주기 스위치(화면 시안만):** 켜면 방송자 화면에서 후원 메시지를 소리로 읽어준다. 오른쪽 버튼을 누르면 목소리 고르기 창이 열린다. **이번 개발에서는 만들지 않는다.** 와이어프레임과 기획서에만 넣는다(9장).
4. **후원 금액 칸**
   - 오른쪽 위에 "내 꿀 3,000"처럼 잔액을 보여준다. 새로고침 버튼으로 잔액을 다시 불러온다.
   - 금액 입력 칸에 숫자를 직접 넣을 수 있다. 1,000~1,000,000꿀이다. 오른쪽의 지우기 버튼으로 0으로 돌린다.
   - 입력 칸 아래에 더하기 버튼을 둔다. "+1천", "+1만", "+10만", "+100만", "전액"이다. 누를 때마다 금액에 더한다. "전액"은 내 꿀 전부로 바꾼다. 더한 금액이 1,000,000을 넘으면 1,000,000에서 멈추고 "한 번에 1,000,000꿀까지 후원할 수 있어요"를 보여준다.
   - 잔액이 모자라면 입력 칸 테두리를 빨간색으로 바꾸고 "1,000꿀이 모자라요"를 보여준다.
5. **아래 버튼**
   - 잔액이 충분하면 "1,000꿀 후원하기"다.
   - 잔액이 모자라면 "충전하고 후원하기"다(아래 "충전하고 후원하기" 흐름).
   - 금액이 1,000 미만이면 버튼이 눌리지 않는다.
6. **안내 줄:** 버튼 아래에 "꿀 충전과 후원 유의사항에 동의합니다."와 "안내 보기"를 둔다. "안내 보기"를 누르면 안내 창(13장 문구)이 열린다. 후원 버튼을 누르는 것을 동의로 본다.

**미션 후원 탭**

미션 후원은 시청자가 "이걸 해 주면 후원할게요"라고 요청하는 후원이다. 치지직 미션 후원 창을 참고했다.

- **대가가 아닌 응원이다.** 방송자는 미션을 수행할 의무가 없고 거절할 수 있다. 이 내용을 후원 안내(13장)와 방송자 약관에 적는다(06 결정 22).
- **금지 미션:** 위험한 행동, 불법 행위, 선정적인 행동, 다른 사람을 괴롭히는 행동을 요구하면 안 된다. 이런 미션을 보낸 사용자는 사용자 신고(사유 "불법·위험한 행동", 4-13)로 신고할 수 있다.

- **미션 내용:** 필수, 1~50자다. 입력 칸 안내 문구는 "미션 내용을 입력해 주세요"이고 글자 수(0/50)를 보여준다. 4-7의 금칙어 검사를 한다. 금칙어가 있으면 미션을 만들지 않고 입력 칸 아래에 이유를 보여준다.
- **미션 제한 시간:** 시청자가 정한다. "시:분" 칸에 넣고, 기본값은 00:30이다. 분 단위로만 정하므로 초 칸은 두지 않는다. 5분~3시간이고 분 단위로 정한다. 시간은 방송자가 **수락한 때부터** 잰다.
- **성공 시 상금:** 1,000~1,000,000꿀이다. 더하기 버튼과 "내 꿀" 잔액, 잔액이 모자랄 때의 안내는 채팅 후원과 같다. 제목 옆 안내 아이콘을 누르면 "성공하면 상금 전부, 실패하면 응원금만 방송자에게 가요"를 보여준다.
- **실패 시 응원금:** 금액 버튼 아래에 "실패 시 응원금 1,000꿀"처럼 보여준다. 응원금은 상금의 20%이고 100꿀 아래는 버린다. 시청자가 따로 정하지 않는다.
- **익명 스위치**는 채팅 후원과 같다. 채팅 읽어주기는 없다.
- **아래 버튼:** "후원하기"다. 미션 내용이 비었거나 상금이 1,000꿀 미만이면 눌리지 않는다. 잔액이 모자라면 "충전하고 후원하기"다.
- 미션 상태와 꿀의 흐름은 아래와 같다. 예시는 상금 5,000꿀, 응원금 1,000꿀이다.

| 무엇이 일어났나 | 미션 상태 | 꿀 |
|---|---|---|
| 시청자가 미션을 보낸다 | 대기 중 | 상금 5,000꿀을 시청자 잔액에서 빼서 묶어 둔다 |
| 방송자가 수락한다 | 진행 중 | 계속 묶어 둔다. 제한 시간을 재기 시작한다 |
| 방송자가 거절한다 | 거절됨 | 5,000꿀을 모두 돌려준다 |
| 방송자가 제한 시간 안에 "성공"을 누른다. 서버는 트랜잭션 안에서 마감 시각이 지나지 않았는지 다시 확인하고, 지났으면 실패로 처리한다(06 결정 27) | 성공 | 상금 5,000꿀을 방송자 후원으로 확정한다 |
| 방송자가 "실패"를 누른다 | 실패 | 응원금 1,000꿀은 방송자 후원으로 확정하고, 4,000꿀은 돌려준다 |
| 진행 중인 채로 제한 시간이 지난다 | 실패 | "실패"와 같다 |
| 진행 중인 채로 방송이 끝난다 | 실패 | "실패"와 같다. 3장의 "방송 종료" 함수가 처리한다 |
| 대기 중인 채로 방송이 끝난다 | 취소됨 | 5,000꿀을 모두 돌려준다. 3장의 "방송 종료" 함수가 처리한다 |

- 확정된 상금과 응원금은 방송 후원 합계와 방송자의 예상 수익에 들어간다. 배분 비율은 확정되는 순간의 방송자 등급으로 정한다(4-12).
- **제한 시간이 지났을 때:** 서버에는 정해진 시각에 일을 하는 기능(예약 작업)을 두지 않는다. 송출 화면이나 시청 화면에서 남은 시간이 0이 되면 서버에 마감 처리를 요청한다. 서버는 마감 시각이 정말 지났는지 확인한 뒤 실패로 바꾼다. 화면이 하나도 열려 있지 않으면 방송 종료 함수가 처리한다.
- 서버는 수락, 거절, 성공, 실패 요청을 처리할 때 트랜잭션 안에서 방송 상태와 미션 상태를 다시 확인한다. 방송이 이미 끝났거나 미션이 이미 다른 상태로 바뀌었으면 거절한다. 그래서 방송이 끝나는 순간과 "성공" 버튼이 겹쳐도 꿀이 두 번 움직이지 않는다.
- 송출 화면에 미션 목록을 따로 둔다. 대기 중인 미션에는 "수락"과 "거절", 진행 중인 미션에는 남은 시간과 "성공"·"실패" 버튼이 있다. 카드에는 상금과 실패 시 응원금을 함께 보여준다.
- 시청자 화면의 채팅 목록에는 미션이 상태 표시와 함께 보인다. 상태가 바뀌면 새로고침 없이 바뀐다.
- 묶인 꿀은 "내 꿀"의 "대기 중"으로 따로 보여준다. 묶인 꿀이 들어 있는 충전 건은 충전 취소를 할 수 없다.

#### 충전

- 충전은 내 정보의 "내 꿀" 화면과, 후원 창의 "충전하고 후원하기"에서 한다.
- 충전 단위는 1,000, 5,000, 10,000, 50,000, 100,000꿀이다. 직접 입력은 1,000~1,000,000꿀이고 1,000 단위다.
- 결제 금액은 꿀 수에 부가가치세 10%를 더한 값이다. 예를 들어 1,000꿀은 1,100원이다. 화면에 꿀 수와 결제 금액을 함께 보여준다.
- 결제는 토스페이먼츠 테스트 모드로 한다. 결제창 위에 "테스트 결제라 실제 돈이 나가지 않아요"를 적는다.
- **충전 동의(06 결정 29):** 모든 충전 창(내 꿀의 충전, 후원 창의 "충전하고 후원하기")의 결제 버튼 아래에 "꿀 충전과 후원 유의사항에 동의합니다"와 "안내 보기"를 둔다. "안내 보기"는 13장 문구를 연다. 결제 버튼을 누르는 것을 동의로 본다. 서버는 충전 주문을 만들 때 동의한 안내 버전과 시각을 충전 기록에 저장한다. 이 규칙의 전문은 [10 이용약관 초안](10-terms-of-service-draft.md) 제3조~제5조다.
- **현금영수증:** 계좌이체처럼 현금으로 결제하면 결제창의 현금영수증 기능으로 충전할 때 발급한다. 충전을 취소하면 함께 취소한다. 카드 결제는 발급하지 않는다(06 결정 22).

**충전 전 확인 (06 결정 22)**

- **본인인증(목업):** 처음 충전할 때 본인인증 창을 먼저 띄운다. 이름, 생년월일, 휴대폰 번호를 넣으면 인증된 것으로 처리한다. 창 위에 "테스트용 본인인증이라 실제로 확인하지 않아요"를 적는다. 인증은 한 번만 받는다.
  - 서버는 이름, 생년월일, 인증 시각, 목업 여부, 명의 확인값을 저장한다. 명의 확인값은 이름, 생년월일, 휴대폰 번호를 합쳐 해시한 값이다. 실제 본인인증의 연계정보(CI, 사람마다 하나인 값)를 대신한다.
- **만 19세 미만:** 충전할 수 없다. 인증한 생년월일로 서버가 판단한다. "만 19세 이상만 꿀을 충전할 수 있어요"를 보여준다. 시청, 채팅, 방송, 후원 받기는 할 수 있다.
- **하루 충전 한도:** 한 계정이 하루에 100만 꿀까지 충전할 수 있다. 하루는 한국 시간 0시부터 센다. 서버는 충전 주문을 만들 때 오늘 만든 충전 가운데 "완료"와 만든 지 30분이 안 된 "결제 대기"의 꿀 수를 더한다. 새 주문을 더해 100만 꿀을 넘으면 거절한다.
  - 화면에는 "오늘은 1,000,000꿀까지 충전할 수 있어요. 남은 한도는 300,000꿀이에요"처럼 보여준다. 충전 단위 가운데 남은 한도를 넘는 단위는 눌리지 않는다.
  - 취소한 충전은 한도에서 빼지 않는다. 충전과 취소를 되풀이해서 한도를 넘지 못하게 하기 위해서다.

**충전 흐름**

1. 시청자가 충전할 꿀 수를 고르고 "충전하기"를 누른다.
2. 서버가 충전 주문을 만든다. 주문에는 주문번호, 꿀 수, 결제 금액, 충전자를 저장한다. 금액은 이때 서버에 고정된다.
3. 토스페이먼츠 테스트 결제창이 뜬다.
4. 결제가 끝나면 서버가 아래를 확인한다.
   - 주문이 있는지, 결제 금액이 주문 금액과 같은지 확인한다.
   - 토스페이먼츠에 결제 승인을 요청한다. 같은 주문을 두 번 승인하지 않도록 주문번호를 멱등키로 보낸다.
   - 승인 결과가 "완료"일 때만 꿀을 넣는다.
5. 꿀이 들어가면 원래 화면으로 돌아가고 "1,000꿀을 충전했어요"를 보여준다.

**충전하고 후원하기**

잔액이 모자랄 때 한 번에 충전과 후원을 한다. 공모 요강의 "후원 대상과 금액 선택, 테스트 결제 요청, 서버의 대상 검증" 조건은 이 흐름으로 확인한다.

1. 서버가 충전 주문을 만들 때 후원 정보(후원 요청 번호, 대상 방송과 방송자, 후원 금액, 메시지, 익명 여부, 채팅 또는 미션, 미션이면 미션 내용과 제한 시간(06 결정 28))도 함께 고정한다. 후원 기록과 채팅 모음의 후원 항목은 이 후원 요청 번호를 문서 ID로 쓴다. 주문번호는 충전 기록에만 쓴다.
2. 충전 꿀 수는 모자란 꿀 이상인 가장 작은 충전 단위로 자동으로 고른다. 예를 들어 1,500꿀이 모자라면 5,000꿀을 충전한다. 시청자는 결제 전에 충전 꿀 수를 바꿀 수 있다.
   - 모자란 꿀이 가장 큰 충전 단위(100,000꿀)보다 크면 모자란 꿀을 1,000 단위로 올린 값을 고른다(06 결정 27).
   - 그 단위가 오늘 남은 한도를 넘으면 모자란 꿀을 1,000 단위로 올린 값을 고른다. 이것도 남은 한도를 넘으면 충전할 수 없다고 알리고 결제창을 띄우지 않는다.
   - 본인인증을 하지 않았으면 결제창보다 본인인증 창을 먼저 띄운다.
3. 결제 승인이 끝나면, 서버는 하나의 트랜잭션 안에서 꿀을 넣고 바로 후원을 처리한다.
4. 결제 사이에 방송이 끝났으면 충전만 하고 후원은 하지 않는다. "방송이 끝나서 후원하지 못했어요. 충전한 꿀은 내 꿀에 남아 있어요"를 보여준다.

#### 한 번만 처리하기

- **충전:** 충전 기록은 주문번호를 문서 ID로 저장한다. 트랜잭션 안에서 이미 처리한 주문인지 먼저 확인한다. 결제 결과 화면과 토스페이먼츠 웹훅이 같은 결제를 두 번 알려 줘도, 웹훅이 여러 번 다시 와도 꿀은 한 번만 들어간다.
- **후원:** 후원 창을 열 때 브라우저가 후원 요청 번호를 하나 만든다. 서버는 이 번호를 후원 기록의 문서 ID로 쓴다. 트랜잭션 안에서 이미 있는지 확인하고, 잔액을 확인하고, 꿀을 빼고, 후원 기록을 만든다. 그래서 버튼을 두 번 눌러도 꿀은 한 번만 빠진다.
- 잔액이 0보다 작아지는 일은 없다. 트랜잭션 안에서 잔액이 모자라면 후원을 거절한다.
- 방송별 후원 합계와 건수, 그 방송의 채팅 모음에 넣는 후원 항목(닉네임 또는 "익명", 금액, 메시지)은 같은 트랜잭션에서 함께 처리한다. 후원 항목은 수정과 삭제를 할 수 없다.
- 꿀이 들어오고 나간 기록은 모두 꿀 내역에 남긴다. 잔액은 이 내역의 합과 항상 같아야 한다.

#### 꿀 내역 규칙 (06 결정 25)

꿀이 움직일 때마다 아래 표대로 네 값을 같은 트랜잭션에서 바꾼다. 표의 N은 그 줄의 꿀 수다.

| 꿀 내역 종류 | 꿀 내역에 적는 수 | 잔액 | 미션에 묶인 꿀 | 환급 대기 | 충전 건의 남은 꿀 |
|---|---|---|---|---|---|
| 충전 | +N | +N | 그대로 | 그대로 | 그 충전 건을 N으로 만든다 |
| 충전 취소 | -N | -N | 그대로 | 그대로 | 그 충전 건을 0으로 만든다 |
| 충전 취소 실패 반환 | +N | +N | 그대로 | 그대로 | 그 충전 건을 N으로 되돌린다 |
| 후원(채팅) | -N | -N | 그대로 | 그대로 | 먼저 충전한 건부터 뺀다 |
| 미션 묶음 | -N | -N | +N | 그대로 | 먼저 충전한 건부터 뺀다 |
| 미션 확정(성공의 상금, 실패의 응원금) | 0 | 그대로 | -확정한 꿀 | 그대로 | 그대로 |
| 미션 반환(거절, 취소, 실패의 나머지) | +돌려준 꿀 | +돌려준 꿀 | -돌려준 꿀 | 그대로 | 나중에 쓴 충전 건부터 되살린다 |
| 환급 묶음 | -N | -N | 그대로 | +N | 들어 있는 충전 건을 모두 0으로 만든다 |
| 환급(승인) | 0 | 그대로 | 그대로 | -N | 그대로 |
| 환급 반환(거절) | +N | +N | 그대로 | -N | 환급 신청에 적은 충전 건별 꿀을 되살린다 |
| 시드 조정 | -N | -N | 그대로 | 그대로 | 먼저 충전한 건부터 뺀다. 꿀을 늘려야 할 때는 시드 조정을 쓰지 않는다. 대신 시드 결제 충전(승인 시각을 10일 전으로 둬서 취소할 수 없는 충전)을 만들고 꿀 내역에는 "충전" 한 줄만 남긴다(06 결정 27) |

- 후원 기록과 환급 신청에는 충전 건별 사용량(충전 ID와 꿀 수의 목록)을 저장한다. 되살릴 때 이 목록을 쓴다.
- 미션 실패에서 응원금은 먼저 쓴 충전 건에서 쓴 것으로 본다. 나머지는 나중에 쓴 충전 건부터 되살린다.
- 되살린 충전 건도 충전 취소 기한(충전한 날부터 7일)은 그대로다.
- 이 규칙을 지키면 아래 세 가지가 늘 맞는다. 서버 테스트로 확인한다.
  - 잔액 = 꿀 내역의 합
  - 잔액 = "완료" 상태인 충전 건의 남은 꿀 합
  - 미션에 묶인 꿀 = "대기 중"과 "진행 중"인 미션 상금의 합
- **같은 명의 표시:** 후원을 확정하는 트랜잭션에서 후원자와 방송자의 본인인증 명의 확인값을 비교한다. 둘 다 있고 같으면 후원 기록에 "같은 명의"를 남긴다. 후원은 막지 않는다. 운영자가 회원 관리와 정산 관리에서 보고 정산 보류로 처리한다(4-15, 06 결정 22). 방송자가 다른 계정으로 자기 방송에 후원해서 카드 결제를 정산금으로 바꾸는 일을 찾기 위해서다.

#### 충전 취소와 환불

- 충전하고 7일 안에, 그 충전 건의 꿀을 하나도 쓰지 않았다면 내 꿀 화면에서 직접 충전을 취소할 수 있다.
- **두 단계로 처리한다(06 결정 25).** 먼저 트랜잭션 안에서 조건을 다시 확인하고, 충전 상태를 "취소 중"으로 바꾸고, 꿀을 뺀다(꿀 내역 "충전 취소"). 그다음 토스페이먼츠에 결제 취소를 요청한다. 성공하면 "취소"로 바꾼다. 실패하면 "완료"로 되돌리고 꿀을 돌려준다(꿀 내역 "충전 취소 실패 반환"). 그래서 취소를 기다리는 동안 그 꿀로 후원할 수 없다. "취소 중"인 충전 건에 온 두 번째 취소 요청은 거절한다.
- **결과를 모를 때(06 결정 26):** 토스페이먼츠가 "실패"라고 분명히 답했을 때만 실패로 본다. 응답 시간이 지나거나 연결이 끊겨 결과를 모르면 "취소 중"으로 그대로 둔다. 그다음 결제 조회 API로 그 결제의 상태를 확인한다. 조회 결과가 취소면 "취소"로, 완료면 "완료"로 되돌리고 꿀을 돌려준다. 토스페이먼츠의 결제 상태 변경 알림(7장)이 와도 같은 조회를 거쳐 "취소 중"을 끝낸다.
- **멈춘 건 정리:** "취소 중"으로 5분 넘게 남은 충전 건은 그 사용자가 내 꿀을 열 때와 운영자가 충전·결제 내역을 열 때 같은 조회로 정리한다. 예약 작업을 두지 않기 위해서다. 5분은 임시값이다.
- 일부라도 후원에 쓴 충전 건과 7일이 지난 충전 건은 취소할 수 없다. 미션에 묶인 꿀이 들어 있는 충전 건도 취소할 수 없다.
- 꿀은 먼저 충전한 것부터 쓴다. 그래서 어느 충전 건을 썼는지 정할 수 있다.
- 후원에 쓴 꿀은 돌려주지 않는다.
- 꿀의 유효기간은 충전한 날부터 5년이다. 이번 개발에서는 화면에 표시만 하고 만료 처리는 만들지 않는다.

**쓰지 않은 꿀 환급 (06 결정 22)**

7일이 지났거나 일부를 쓴 충전 건이라도, 쓰지 않은 꿀은 신청하면 돌려준다.

- **환급할 수 있는 꿀:** 잔액에서 7일 안에 취소할 수 있는 충전 건의 꿀을 뺀 나머지 전부다. 일부만 신청할 수 없다. 1,000꿀 미만이면 신청 버튼이 눌리지 않는다. 취소할 수 있는 충전 건이 있으면 "이 충전은 충전 취소로 전액 돌려받을 수 있어요"를 함께 보여준다. 미션에 묶인 꿀은 미션 묶음 때 이미 잔액에서 빠졌으므로 다시 빼지 않는다(4-8의 꿀 내역 규칙, 06 결정 26).
- **환급 금액:** 꿀 1개를 결제 금액 1.1원(부가세 포함)으로 계산하고 10%를 뗀다. 원 단위 아래는 버린다. 예를 들어 3,000꿀은 3,300원에서 330원을 떼고 2,970원이다. 신청 창에 환급할 꿀, 결제 금액 기준 금액, 수수료, 받을 금액을 나눠 보여준다.
- **환급 계좌(목업):** 본인인증을 마친 사람만 신청할 수 있다. 은행과 계좌번호를 넣으면 예금주를 본인인증 이름으로 채운다. 실제 계좌 확인은 하지 않는다. 은행 이름, 계좌번호 끝 4자리, 예금주만 저장한다.

**환급 흐름**

1. 시청자가 내 꿀에서 "환급 신청"을 누르고 계좌를 넣는다.
2. 서버는 하나의 트랜잭션 안에서 환급할 수 있는 꿀을 다시 계산하고, 그 꿀을 잔액에서 빼서 "환급 대기"로 묶는다. 환급 신청 기록과 꿀 내역(환급 묶음)을 함께 만든다. 묶은 꿀이 들어 있는 충전 건의 남은 꿀도 0으로 바꾼다. 그래서 신청한 뒤에는 그 꿀로 후원할 수 없다.
3. 운영자가 운영자 화면의 환급 관리에서 확인한다(4-15).
   - **승인:** 두 단계로 처리한다(06 결정 25). 먼저 트랜잭션 안에서 상태가 "대기"나 "송금 실패"인지 확인하고 "송금 중"으로 바꾼다(06 결정 28). 그다음 송금 함수(목업)를 부른다. 성공하면 "환급 완료(테스트)"로 바꾸고 묶은 꿀을 없앤다. 꿀 내역에 "환급"을 남긴다. 실패하면 "송금 실패"로 바꾸고, 운영자가 다시 승인하거나 거절할 수 있다. 다른 운영자가 같은 신청을 동시에 눌러도 둘째 요청은 "송금 중"을 보고 거절된다. 송금 결과를 모르면 "송금 중"으로 두고, 송금 번호로 결과를 조회한 뒤 마지막 상태를 정한다. 목업 송금은 늘 결과를 바로 돌려주므로 이 경우가 없다. 실제 송금을 붙일 때 만든다(06 결정 26).
   - **거절:** 사유를 적는다. 묶은 꿀을 잔액으로 돌려준다. 충전 건의 남은 꿀도 되돌린다. 꿀 내역에 "환급 반환"을 남긴다.
4. 결과는 알림으로 보낸다(4-17). 한 사람은 처리 중인 환급 신청을 하나만 가질 수 있다.

- 환급 신청 기록은 신청 번호(브라우저가 만든 요청 번호)를 문서 ID로 쓴다. 버튼을 두 번 눌러도 한 번만 신청된다.
- 같은 신청을 승인과 거절이 동시에 처리하지 않도록, 트랜잭션 안에서 상태가 "대기"인지 다시 확인한다.

**회원 탈퇴와 남은 꿀**

- 탈퇴 전에 환급할 수 있는 꿀이 있으면 "남은 꿀 3,000은 환급 신청으로 2,970원을 돌려받을 수 있어요. 취소할 수 있는 충전은 충전 취소로 전액 돌려받을 수 있어요"를 확인 창으로 알린다. 환급 신청 버튼을 함께 둔다.
- 그래도 탈퇴하려면 "남은 꿀을 포기하고 탈퇴합니다"에 체크해야 한다. 동의한 시각을 운영 기록에 남긴다. 탈퇴할 때 남은 잔액만큼 꿀 내역에 "탈퇴 포기"(-N) 줄을 남기고, 남은 충전 건의 남은 꿀을 0으로 만든다. 그래서 탈퇴하는 순간에도 4-8의 불변식이 맞는다(06 결정 28).
- 환급 신청이 처리 중(대기, 송금 중, 송금 실패)이거나 묶인 미션이 있으면 탈퇴할 수 없다.

#### 보여주는 곳

- 방송 보기 화면: 후원 합계. 채팅 목록에 후원자 닉네임(또는 "익명"), 금액, 메시지를 후원 항목으로 끼워 보여준다. 미션은 상태와 함께 보여준다
- 송출 화면: 후원이 올 때마다 알림. 10만 꿀 이상은 알림을 크게 보여준다. 미션 목록과 수락·거절·성공·실패 버튼
- 내 방송 관리: 방송별 후원 내역(후원자 또는 "익명", 종류, 금액, 시각)과 합계. 합계 옆에 예상 수익을 함께 보여준다. 예상 수익은 후원마다 저장한 배분 비율로 계산한다(4-12, 06 결정 9). 지운 방송의 후원도 남는다(4-10)
- 내 정보의 내 꿀: 잔액, 대기 중인 꿀, 환급 대기 중인 꿀, 충전 내역(취소 가능 여부 포함), 사용 내역, 환급 신청 내역
- 내 정보의 내 후원 내역: 내가 한 후원(방송 제목, 방송자, 종류, 금액, 메시지, 익명 여부, 시각)과 합계. 방송이 지워졌어도 남는다(4-11)

#### 실패했을 때

- 결제를 취소하거나 결제가 실패하면 실패 화면에서 이유를 보여주고 원래 화면으로 돌아가는 버튼을 준다. 꿀은 들어가지 않는다.
- 결제 금액이 주문과 다르면 승인하지 않고 실패로 처리한다.
- 후원 중에 잔액이 모자라게 되면(다른 기기에서 먼저 쓴 경우) "꿀이 모자라요. 잔액을 다시 확인해 주세요"를 보여주고 잔액을 새로 불러온다.

### 4-9. 녹화와 다시보기

- **녹화 시작:** 송출 화면에서 방송을 시작하기 직전에 녹화를 켰다면(4-4), 방송이 시작될 때 서버가 LiveKit에 녹화를 요청한다. 모든 방송을 LiveKit 방 합성 녹화(바둑판형 배치)로 녹화한다. 화면만 보낸 방송은 화면이, 카메라 방송은 카메라가, 화면과 카메라를 함께 보낸 방송은 둘이 나란히 녹화된다(06 결정 15). MP4 파일로 Cloudflare R2에 저장한다.
- **녹화 끝:** 방송이 종료되면 녹화도 끝난다. LiveKit이 "녹화가 끝났다"는 알림을 보내면 서버가 녹화 정보(파일 위치, 길이, 상태)를 저장한다.
- **녹화 상태:** 녹화 중, 처리 중, 볼 수 있음, 실패 네 가지다. 바뀌는 때는 아래와 같다.

| 무엇이 일어났나 | 녹화 상태 |
|---|---|
| 방송이 시작되고 LiveKit이 녹화를 받아들였다 | 녹화 중 |
| 방송이 종료됐다(어떤 방법으로든) | 처리 중. 서버가 방송을 종료로 바꿀 때 함께 바꾼다 |
| LiveKit이 "녹화가 끝났다"를 알리고 파일이 있다 | 볼 수 있음 |
| 녹화를 시작하지 못했거나, 끝났다는 알림에 오류가 있다 | 실패 |
| "처리 중"으로 30분이 지났다 | 실패. 예약 작업 없이, 내 방송 관리를 열 때와 방송 삭제·탈퇴를 요청할 때 서버가 확인해서 바꾼다(06 결정 27). 그 뒤 늦게 온 "녹화가 끝났다" 알림은 7장대로 R2 파일을 지운다 |

- **녹화 길이 제한:** 녹화는 한 번에 3분까지다. 송출 화면이 녹화 시작 3분 뒤에 서버에 "녹화 멈춤"을 요청하고, 서버가 LiveKit 녹화를 멈춘다. 방송은 계속된다. 송출 화면이 닫히면 방송이 끝나므로 녹화도 함께 끝난다. 서버는 녹화 사용량을 녹화 기록과 따로 `usage/{연월}` 문서에 센다. 녹화를 시작할 때 3분을 미리 더하고, 녹화가 끝나면 실제 길이로 고친다. 녹화를 지워도 사용량은 줄지 않는다. 서버는 방송 종료 함수와 채팅·시청 권한 요청을 처리할 때도 녹화 시작 뒤 3분이 지났는지 확인하고, 지났으면 녹화를 멈춘다(06 결정 28). 시작할 때 3분을 미리 더해도 이번 달 사용량이 50분을 넘지 않을 때만 새 녹화를 시작한다. 즉 47분을 넘게 썼으면 새 녹화를 시작하지 않고 "이번 달 녹화 시간을 다 썼어요. 방송은 계속돼요"를 보여준다. 3분과 50분은 임시값이다. 한 사람이 무료 녹화 60분을 다 쓰지 못하게 하기 위해서다(06 결정 27).
- **녹화가 실패해도 방송은 계속된다.** 무료 녹화 한도를 넘었거나 오류가 나면 송출 화면에 "녹화를 시작하지 못했어요. 방송은 계속돼요"를 보여준다.
- **공개 여부:** 녹화가 "볼 수 있음"이 되어도 처음에는 **비공개**다. 방송자가 내 방송 관리에서 "공개"로 바꿔야 다시보기 목록과 방송 링크에 나온다. 언제든 다시 비공개로 바꿀 수 있다.
  - 비공개 녹화는 방송자만 내 방송 관리에서 재생할 수 있다.
  - R2 파일은 공개 주소로 두지 않는다. 재생할 때 서버가 공개 여부와 소유자를 확인한 뒤 잠깐만 쓸 수 있는 주소(서명된 주소)를 준다. 주소는 30분 동안 쓸 수 있다. 그래서 비공개로 바꾸면 이미 받은 주소는 30분 안에 막히고, 새 주소는 받을 수 없다(06 결정 28).
- **다시보기 목록:** 볼 수 있고 공개한 녹화를 최근 순서로 보여준다. 제목, 방송자, 방송 날짜, 길이를 보여준다. 비로그인 사용자도 헤더의 "다시보기" 메뉴로 들어올 수 있다.
- **다시보기 보기:** 영상 플레이어로 재생한다. 방송 정보와 그 방송의 채팅, 후원 합계를 함께 보여준다. 다시보기에서는 채팅을 쓸 수 없고 후원할 수 없다. 비공개 녹화의 주소를 다른 사람이 열면 "볼 수 없는 다시보기예요"를 보여준다.
- **방송 링크에서 다시보기로:** 종료된 방송의 방송 보기 화면에서 "다시보기" 버튼으로 이어진다. 녹화가 공개일 때만 버튼을 보여준다.
- **녹화 삭제:** 내 방송 관리에서 소유자가 녹화를 지울 수 있다. R2 파일과 녹화 정보를 함께 지운다. 테스트 녹화를 지울 때 쓴다. 녹화 중이거나 처리 중인 녹화는 지울 수 없다.

### 4-10. 내 방송 관리

- **지금 방송 카드:** 목록 위에 준비 상태와 방송 중인 방송을 카드로 따로 보여준다. 카드에는 상태, 제목, 만든 시각(방송 중이면 시작 시각)이 있다. 준비 상태 카드에는 "송출 화면 열기" 버튼이 있다. 방송 중인 방송의 카드에는 "송출 중인 화면에서 관리해 주세요" 문구와 "시청자 화면으로 보기" 버튼만 있다. 송출 화면 열기 버튼과 삭제 버튼은 없다(06 결정 30). 준비 상태인 방송은 카드에서 지울 수 있다. 녹화를 고르기 전이라 남는 녹화가 없기 때문이다(06 결정 24).
- **목록:** 종료된 방송만 최근에 끝난 순서로 보여준다. 방송이 끝나야 이 목록에 들어온다. 종료 시각, 방송 길이, 후원 합계, 녹화 상태를 함께 보여준다.
- **수정:** 제목을 바꾼다. 방송 중에는 송출 화면에서, 끝난 뒤에는 목록에서 바꾼다.
- **삭제:** 목록(종료된 방송)과 준비 상태 카드에서만 지울 수 있다. 확인 창을 띄운 뒤 지운다. 방송 정보, 채팅, 녹화(R2 파일 포함)를 지운다. **후원 기록은 지우지 않는다.** 돈이 오간 기록이기 때문이다.
  - **방송 중에는 지울 수 없다.** 화면에 삭제 버튼이 없고, 서버도 방송 중인 방송의 삭제 요청을 거절한다. 방송을 끝낸 뒤 목록에서 지운다.
  - **녹화가 처리 중이면 방송을 지울 수 없다.** 삭제 버튼을 누르면 "다시보기를 만드는 중이에요. 다 된 뒤에 지울 수 있어요"를 보여준다. 서버도 거절한다. 녹화가 끝나기 전에 지우면 뒤늦게 온 "녹화가 끝났다" 알림이 주인 없는 파일을 남기기 때문이다. 녹화가 볼 수 있음이나 실패가 된 뒤에는 지울 수 있다.
- **후원 내역:** 방송별 후원 목록과 합계, 예상 수익을 보여준다. 줄마다 그 후원에 적용한 배분 비율(예: 80%)을 함께 보여준다. 방송 중인 방송의 후원은 송출 화면에서 보고, 끝나면 목록에서 펼쳐 본다.
- **정산 조회:** 목록 위에 정산 카드와 정산 내역을 보여준다. 정산 신청 버튼은 없다. 자세한 동작은 4-12의 "정산 화면"에 있다.
- **지운 방송의 후원:** 목록 맨 아래 "지운 방송" 묶음에 남는다. 방송 제목, 후원자, 금액, 시각을 보여준다. 위쪽 전체 후원 합계와 예상 수익에도 들어간다.
- **녹화 공개 설정:** 녹화가 "볼 수 있음"인 줄에 "공개/비공개" 스위치와 "미리 보기" 버튼을 둔다. 처음에는 비공개다.
- **이어서 송출:** 준비 상태인 방송만 지금 방송 카드의 "송출 화면 열기"로 들어간다. 방송 중인 방송의 송출 화면에는 다시 들어갈 수 없다(3장, 06 결정 30).

### 4-11. 내 정보

로그인한 사용자가 오른쪽 위 프로필 메뉴에서 들어온다.

- **닉네임 변경:** 가입한 뒤 한 번만 바꿀 수 있다. 규칙은 4-1과 같다. 바꾸기 전에 확인 창에서 "한 번 바꾸면 다시 바꿀 수 없어요"를 알린다. 이미 바꿨다면 입력 칸과 "변경" 버튼을 막는다. 서버도 두 번째 변경을 거절한다.
  - 바꾼 뒤 새로 쓰는 방송, 채팅, 후원에는 새 닉네임이 쓰인다. 이미 남은 방송, 채팅, 후원 기록의 닉네임은 바꾸지 않는다.
  - 바뀌기 전 닉네임은 다른 사람이 바로 쓸 수 없게 붙잡아 둔다. 다른 사람이 같은 이름으로 과거 기록을 흉내 내지 못하게 하기 위해서다.
- **내 꿀:** 잔액, 미션에 묶인 꿀, 환급 대기 중인 꿀, 충전하기, 환급 신청, 충전 내역, 사용 내역, 환급 신청 내역을 보여준다. 충전 내역의 각 줄에 "취소할 수 있음(11월 14일까지)" 또는 "취소할 수 없음"과 이유를 보여준다(4-8).
- **본인인증:** 인증했으면 "본인인증 완료(테스트)"와 인증한 이름을 보여준다. 안 했으면 "본인인증하기" 버튼을 둔다(4-8, 목업).
- **내 후원 내역:** 내가 한 후원을 최근 순서로 보여준다. 방송 제목, 방송자, 종류(채팅/미션), 금액, 메시지, 시각과 전체 합계를 보여준다. 익명으로 한 후원에는 "익명으로 후원함"을 붙인다. 방송이 지워졌어도 남고, 제목 옆에 "지운 방송"을 붙인다.
- **비밀번호 변경:** 4-1의 비밀번호 찾기와 같은 메일을 보낸다. 구글로만 가입한 사람은 비밀번호가 없으므로 이 메뉴를 보여주지 않는다.
- **회원 탈퇴:** 비밀번호를 한 번 더 입력받고 확인 창을 띄운 뒤 탈퇴한다. 구글로 가입한 사람은 비밀번호 대신 구글 로그인 창으로 한 번 더 확인한다. 다시 확인한 로그인은 5분 안에 한 것만 인정한다. 5분이 지났으면 "비밀번호를 한 번 더 확인해 주세요"를 보여준다.
  - 채팅 금지나 방송 금지가 적용 중이면 탈퇴할 수 없다. "제재 기간이 끝난 뒤에 탈퇴할 수 있어요"를 보여준다. 탈퇴하고 다시 가입해서 제재를 피하지 못하게 하기 위해서다(06 결정 29).
  - 방송 중인 방송이 있거나, 녹화 중이거나 처리 중인 녹화가 있으면 탈퇴할 수 없다. "회원 탈퇴" 옆 "?" 도움말에 "방송을 끝내고 녹화가 끝난 뒤에 탈퇴할 수 있어요"를 넣는다.
  - 내가 보낸 미션이 대기 중이거나 진행 중이면 탈퇴할 수 없다(4-8).
  - 정산 지급을 보내는 중이면 탈퇴할 수 없다. "수익 배분금을 보내는 중이라 잠시 뒤에 탈퇴할 수 있어요"를 보여준다.
  - 아직 지급받지 못한 수익 배분금(지급 대기, 보류, 지급 실패, 아직 정산하지 않은 확정 후원의 방송자 몫)이 있으면 금액과 다음 지급일을 확인 창으로 알린다. 방송자는 둘 중 하나를 고른다. 하나는 탈퇴를 그만두고 지급일 뒤에 다시 탈퇴하는 것이다. 다른 하나는 "남은 수익 배분금을 포기하고 탈퇴합니다"에 체크하고 바로 탈퇴하는 것이다. 포기하면 그 정산 기록과 후원을 "포기"로 표시하고, 동의한 시각을 탈퇴 포기 동의 기록에 남긴다(09 약관 제14조 3항(06 결정 27)).
  - "결제 대기"(만든 지 30분 안)나 "취소 중"인 충전이 있으면 탈퇴할 수 없다. 탈퇴한 뒤에 결제 승인이나 취소 결과가 오면 지운 사용자에게 꿀이 생기기 때문이다(06 결정 28).
  - 환급 신청이 처리 중(대기, 송금 중, 송금 실패)이면 탈퇴할 수 없다. 환급할 수 있는 꿀이 남아 있으면 포기 동의를 받는다(4-8).
  - 탈퇴하면 계정, 내 방송, 녹화(R2 파일 포함)를 지운다.
  - 내가 쓴 채팅은 남기고, 닉네임을 "탈퇴한 사용자"로 바꾼다. 다른 사람의 대화 흐름이 끊기지 않게 하기 위해서다.
  - 후원 기록(내가 한 것, 내가 받은 것)은 지우지 않는다. 돈이 오간 기록이기 때문이다. 후원자 이름은 "탈퇴한 사용자"로 바꿔 보여준다.
  - 탈퇴한 이메일로는 다시 가입할 수 있다. 쓰던 닉네임은 다시 쓸 수 있게 풀어 준다.
  - 테스트 계정은 탈퇴할 수 없다(4-1).

**탈퇴 처리 순서**

서버는 아래 순서로 처리한다.

1. **조건 확인:** 비밀번호(구글 가입이면 구글 로그인)를 다시 확인한 로그인인지 본다. 위의 탈퇴할 수 없는 경우에 해당하면 거절한다.
2. **계정 정지:** 계정을 먼저 정지하고 로그인 토큰을 무효로 만든다. 그래서 탈퇴를 처리하는 동안 새 채팅, 후원, 방송이 들어오지 않는다.
3. **기록 정리**
   - 다른 사람 방송에 쓴 채팅과 후원 항목의 작성자 닉네임을 "탈퇴한 사용자"로 바꾼다. 모든 방송의 채팅을 작성자 ID로 한 번에 찾는다(6장의 색인).
   - 후원 기록의 후원자 닉네임과 방송자 닉네임 가운데 내 것을 "탈퇴한 사용자"로 바꾼다.
   - 내 방송, 그 방송의 채팅, 녹화 정보와 R2 파일을 지운다. 후원 기록은 지우지 않는다.
   - 본인인증 정보(이름, 생년월일, 명의 확인값)와 정산 정보(계좌)를 지운다. 이미 만든 후원 기록의 "같은 명의" 표시는 판단 결과라 남긴다. 환급 신청과 정산 기록에 적힌 계좌 끝 4자리와 예금주는 돈이 오간 기록이라 5년 동안 남긴다(전자상거래법의 대금 결제 기록 보관 기간). 5년 뒤 지우는 작업은 이번에 만들지 않는다(06 결정 27).
   - 사용자 문서와 닉네임 문서를 지운다. 닉네임 문서가 사라지면 다른 사람이 그 닉네임을 쓸 수 있다.
   - Firestore는 한 번에 500개까지 쓸 수 있다. 그래서 바꿀 문서가 많으면 나눠서 처리한다.
4. **계정 삭제:** 마지막으로 Firebase Auth 계정을 지운다.

- 3단계가 중간에 실패하면 같은 탈퇴 요청을 처음부터 다시 실행한다. 이미 바꾼 닉네임을 또 바꾸고 이미 지운 문서를 또 지울 뿐이라 결과가 같다.
- 탈퇴 처리가 중간에 멈춰 계정이 정지된 채 남으면, 그 계정으로 로그인할 때 영구 정지 계정과 같은 안내("운영정책 위반으로 이용이 정지된 계정이에요")가 나온다. 탈퇴 중이라는 안내를 따로 보여주지는 않는다. 탈퇴를 자동으로 다시 실행하는 기능은 이번 개발에서 만들지 않는다.

### 4-12. 방송자 등급과 정산

방송자에게 성장할 목표를 주기 위해 등급을 둔다. 등급이 오르면 후원 배분 비율과 혜택이 커진다. 결정 이유는 06 결정 9에 있다.

**등급과 혜택**

| 등급 | 후원 배분(방송자 : 나비) | 다시보기 보관 기간 | 닉네임 옆 등급 표시 |
|---|---|---|---|
| 알 | 80 : 20 | 7일 | 없음 |
| 애벌레 | 82 : 18 | 30일 | 애벌레 표시 |
| 번데기 | 85 : 15 | 90일 | 번데기 표시 |
| 나비 | 88 : 12 | 영구 | 나비 표시 |

- 모든 등급이 다른 플랫폼의 같은 단계보다 많이 받는다. 가장 낮은 알 등급도 80%다(06 결정 9의 비교표).
- 가입하면 알 등급이다. 등급과 상관없이 가입하면 바로 후원을 받을 수 있다.
- 결제 수수료는 나비 몫에서 낸다.
- **다시보기 보관 기간은 화면에 "추후 적용"으로 안내만 한다**(06 결정 29). 기간이 지난 녹화를 자동으로 지우는 기능은 이번에 만들지 않는다. 정해진 시각에 도는 작업이 필요하기 때문이다.
- 등급 표시는 채팅과 후원 항목의 닉네임 옆에 붙인다. 방송 보기 화면의 방송자 이름 옆에는 붙이지 않는다.

**승급 조건 (숫자는 임시다)**

| 다음 등급 | 방송 횟수 | 누적 방송 시간 | 받은 후원 건수 |
|---|---|---|---|
| 애벌레 | 3회 | 2시간 | 1건 |
| 번데기 | 15회 | 20시간 | 30건 |
| 나비 | 50회 | 100시간 | 300건 |

- 세 조건을 모두 채우면 자동으로 다음 등급이 된다. 신청과 승인 단계는 없다.
- 방송 횟수는 10분 이상 이어진 뒤 종료된 방송만 센다. 켰다가 바로 끄는 것을 반복해서 횟수를 채우지 못하게 하기 위해서다.
- 누적 방송 시간은 방송 시작부터 종료까지의 시간을 더한다.
- 받은 후원 건수는 확정된 채팅 후원과 확정된 미션(성공한 상금과 실패한 응원금)을 센다. "같은 명의" 표시가 붙은 후원은 세지 않는다. 자기 후원으로 등급을 올리지 못하게 하기 위해서다(09 약관 제8조(06 결정 29)).
- 한 번에 한 등급씩만 올라간다. 조건이 두 등급을 넘었어도 다음 계산 때 한 번 더 올라간다.
- 이번 개발에서는 등급이 내려가지 않는다. 예외는 심사용 부분 초기화(4-18)다. README와 10 이용약관 부칙에 적는다(06 결정 29).

**언제 계산하나**

- 3장의 "방송 종료" 함수가 같은 트랜잭션에서 방송 횟수와 누적 방송 시간을 더하고 승급을 확인한다.
- 후원을 확정하는 트랜잭션이 받은 후원 건수를 더하고 승급을 확인한다.
- 승급하면 등급 변경 내역에 변경 시각, 바뀐 등급, 새 배분 비율을 남긴다.

**후원 배분 비율 저장**

- 후원을 확정할 때 그 순간의 방송자 등급과 배분 비율을 후원 기록에 함께 저장한다.
- 그래서 나중에 등급이 올라도 지난 후원의 예상 수익은 바뀌지 않는다.

**정산**

- 정산은 월 1회 자동이다. 지난달 1일부터 말일까지 확정된 후원의 방송자 몫을 이번 달 정산일에 지급한다. 정산일은 매달 25일로 임시로 정한다.
- 방송자는 조회만 한다. 정산 신청 버튼은 없다.
- 후원에는 최소 정산 금액이 없다.
- 정산 정보(본인 명의 계좌, 본인 인증)가 없으면 금액은 쌓아 둔다. 정보를 등록하면 그 뒤 첫 정산일에 한꺼번에 지급한다.
- **이번 개발 범위(06 결정 11):** 정산 계산과 확정은 실제로 만든다. 예약 작업과 송금은 목업으로 만든다. 정산 정보 등록 화면과 본인 인증은 만들지 않고 시드 스크립트로 테스트 계좌를 넣는다. 필수 기능이 모두 끝난 뒤에 만든다.

#### 정산 구조

정산은 서버 함수 네 개로 나눈다. 화면, 예약 작업, 테스트 버튼은 모두 이 함수들을 부르기만 한다.

| 함수 | 하는 일 | 이번 개발 |
|---|---|---|
| 정산 계산 | 방송자 ID와 기간을 받는다. 그 기간에 확정됐고 아직 정산 ID가 없는 후원을 모아, 건수, 꿀 합계, 방송자 몫 합계, 나비 몫 합계를 돌려준다. 저장하지 않는다 | 실제 |
| 정산 확정 | 정산 계산 결과를 정산 기록으로 저장하고, 들어간 후원마다 정산 ID를 적는다. 그다음 지급을 시도한다 | 실제 |
| 송금 | 정산 기록 하나를 받아 방송자 계좌로 보낸다. 성공하면 송금 번호를 돌려준다 | 목업 |
| 예약 작업 실행기 | 정해진 날짜에 작업을 실행한다. 여기서는 "월 정산" 작업 하나만 등록한다 | 목업 |

**정산 계산**

- 방송자 몫은 후원마다 이미 저장된 "방송자 예상 수익"을 더한다. 정산할 때 비율을 다시 곱하지 않는다. 그래서 내 방송 관리에 보이는 예상 금액과 정산 금액이 항상 같다.
- 후원마다 방송자 예상 수익은 `전달된 꿀 × 배분 비율`을 원 단위로 내림해 저장한다. 내림으로 생긴 차이는 나비 몫에 들어간다.
- 내 방송 관리의 정산 카드도 이 함수로 구한다. 숫자는 받는 날 기준으로 두 개를 보여준다. 이름에는 실제 날짜를 쓴다(예: "11월 25일에 받을 금액"). 첫째는 가장 가까운 지급일에 받을 금액이다. 그 지급일 전달 말일까지 확정됐고 아직 지급되지 않은 몫과 보류로 쌓인 금액의 합이다. 둘째는 그 다음 지급일에 받을 금액(쌓이는 중)이다. 지급일의 전달 1일부터 지금까지 확정된 몫이다. 25일이 지나면 가장 가까운 지급일은 다음 달 25일로 넘어간다(06 결정 28).
- 시각은 모두 한국 시간 기준으로 자른다.

**정산 확정**

트랜잭션 하나 안에서 아래 순서로 처리한다.

1. 정산 기록 ID가 이미 있으면 그 기록을 그대로 돌려주고 끝낸다. 같은 요청이 두 번 와도 한 번만 처리된다.
2. 정산 계산과 같은 조건으로 후원을 다시 읽는다. 트랜잭션 안에서 읽어야 그 사이 들어온 후원이 섞이지 않는다.
3. 정산할 후원이 하나도 없으면 기록을 만들지 않는다. 그래도 아래 지급 단계는 실행한다. 보류나 지급 실패로 남은 기록이 있을 수 있기 때문이다. 지급할 것도 없으면 "정산할 후원이 없어요"를 돌려준다(06 결정 27).
4. 정산 기록을 만든다. 상태는 "지급 대기"다. 방송자가 영구 정지 상태이거나 운영자가 그 방송자의 정산을 보류해 두었으면 처음부터 "보류(운영 조치)"로 만든다(06 결정 27, 28).
5. 들어간 후원마다 정산 ID를 적는다. 정산 ID가 있는 후원은 다음 정산 계산에서 빠진다.

트랜잭션이 끝나면 지급을 시도한다.

- 방송자의 정산 정보가 없으면 상태를 "보류(정산 정보 없음)"로 바꾼다.
- 정산 정보가 있으면 이 방송자의 "지급 대기", "보류(정산 정보 없음)", "지급 실패" 기록을 모은다. 쌓아 둔 금액이 이때 한꺼번에 나간다. "보류(운영 조치)" 기록은 모으지 않는다.
- **두 단계로 처리한다(06 결정 25).** 먼저 트랜잭션 안에서 모은 기록들이 아직 그 상태인지 확인하고 모두 "송금 중"으로 바꾼다. 그다음 기록마다 송금 함수를 한 번씩 부른다. 송금 함수는 정산 기록 하나를 받는다.
- 송금이 성공하면 그 기록을 "지급 완료"로 바꾸고 송금 번호와 지급 시각을 저장한다. 실패하면 "지급 실패"로 바꾸고 다음 실행에서 다시 시도한다. 다른 실행이 같은 기록을 동시에 집어도 "송금 중"을 보고 건너뛴다. 송금 결과를 모르면 "송금 중"으로 두고 조회로 정한다. 목업에서는 생기지 않고, 실제 송금을 붙일 때 만든다(06 결정 26).

- 한 트랜잭션은 문서 500개까지 쓸 수 있다. 정산 기록 하나에 후원은 490건까지 넣는다. 넘으면 나머지는 다음 정산 기록으로 나눈다. 나눈 기록의 ID는 끝에 `_1`, `_2`처럼 순번을 붙인다. 첫 기록에도 `_1`을 붙인다(06 결정 27).
- 결제 취소로 빼야 할 금액(공제)과 세금은 필드만 둔다. 지금은 0이다. 테스트 결제에서는 후원 뒤 결제가 취소되는 경우가 없다(4-8). 원천징수 비율은 세무 확인 전이다.

**정산 기록의 상태**

| 상태 | 뜻 | 다음 상태 |
|---|---|---|
| 지급 대기 | 확정했고 아직 송금하지 않았다 | 지급 완료, 지급 실패, 보류 |
| 보류(정산 정보 없음) | 계좌가 없어 쌓아 두었다 | 정산 정보가 생긴 뒤 다음 실행에서 지급 완료 |
| 보류(운영 조치) | 운영자가 정산 관리에서 그 방송자의 정산을 보류했거나, 방송자가 영구 정지됐다(4-15, 09 약관 제10조). 사유와 보류한 운영자를 남긴다. 보류는 방송자 단위로 건다. 보류를 걸면 그 방송자의 "지급 대기"와 "보류(정산 정보 없음)" 기록이 "보류(운영 조치)"로 바뀌고, 그 뒤 새로 만드는 정산 기록도 처음부터 이 상태가 된다(06 결정 28) | 운영자가 해제하면 "지급 대기"로 돌아가고 다음 실행에서 지급한다. 해제하지 않으면 그대로 남는다 |
| 송금 중 | 송금 함수를 부르는 중이다. 다른 실행은 이 기록을 건너뛴다. 결과를 모르면 조회로 정한다 | 지급 완료, 지급 실패 |
| 지급 완료 | 송금했다. 목업이면 "지급 완료(테스트)"로 보여준다 | 없음 |
| 지급 실패 | 송금이 실패했다 | 다음 실행에서 다시 시도 |
| 포기 | 방송자가 탈퇴하면서 받지 않기로 했다(4-11) | 없음 |

- 생긴 지 5년이 지난 보류 기록은 사라진다(09 약관 제10조). 이번에는 화면에 기한만 보여주고 소멸 처리는 만들지 않는다.

**송금 (목업)**

- 송금 함수는 "정산 기록과 계좌를 받아 송금 번호를 돌려준다"는 형태로 둔다. 이 형태를 실제 구현과 목업이 같이 쓴다.
- 목업은 외부를 부르지 않는다. `MOCK-` 로 시작하는 송금 번호를 만들어 성공으로 돌려준다.
- 환경 변수 하나로 목업과 실제 구현을 고른다. 실제 구현은 나중에 결제대행사 지급대행 API로 만든다.

**예약 작업 실행기 (목업)**

- 예약 작업은 "작업 이름과 실행 시각을 받아 일을 한다"는 형태로 둔다. 여기서는 "월 정산" 작업 하나만 등록한다.
- 월 정산 작업은 두 경우의 방송자에 대해 정산 확정을 부른다. 하나는 지난달에 정산되지 않은 확정 후원이 있는 방송자다. 다른 하나는 "보류(정산 정보 없음)"나 "지급 실패" 기록이 남은 방송자다. 정산 기록 ID는 `방송자ID_연월_순번`(예: `abc_2026-11_1`)이다. 그래서 같은 달을 두 번 실행해도 한 번만 정산된다.
- 실행할 때마다 작업 실행 기록을 남긴다. 작업 이름, 실행 방식(예약/테스트), 시작·끝 시각, 처리한 방송자 수, 결과다.
- **실제 운영:** 매달 25일에 실행기가 월 정산 작업을 부른다. 나중에 Vercel 예약 작업이 서버 주소를 부르게 바꾼다. 이때 비밀 값으로 호출한 곳을 확인한다.
- **목업:** 운영자 화면 정산 관리의 "월 정산 지금 실행(테스트)" 버튼이 같은 작업을 실행한다(4-15, 06 결정 13). 아래 "테스트 실행"을 따른다.

**테스트 실행 ("월 정산 지금 실행")**

- 버튼은 운영자 화면의 정산 관리에 있다. 서버는 운영자인지와 목업 실행 환경 변수가 켜져 있는지 확인한다. 아니면 403으로 거절한다.
- 정산할 후원이 있는 모든 방송자와 보류·지급 실패 기록이 남은 방송자를 한 번에 정산한다.
- 기간은 "이번 달 1일부터 지금까지"다. 심사 기간에는 지난달 후원이 없기 때문이다.
- 정산 기록 ID는 `요청번호_방송자ID_순번`이다. 요청 번호는 버튼을 누를 때 브라우저가 만든다. 같은 요청이 두 번 와도 한 번만 처리된다. 한 번 정산한 뒤 새 후원이 들어오면 다음 테스트 실행에서 새 기록이 생긴다.
- 지급일은 바로 지금이다. 상태는 곧바로 "지급 완료(테스트)"가 된다.
- 결과는 화면 알림으로 보여준다. 문구는 "새로 정산한 후원 n건(방송자 몫 n원), 지급 n건, 보류로 남은 기록 n건(테스트)"이다. 새 후원도, 지급할 기록도 없으면 "정산할 후원이 없어요"를 보여준다. 보류로 남은 기록만 있으면 "새로 정산할 후원이 없어요. 보류로 남은 기록 n건은 그대로예요"를 보여준다(06 결정 28).

**정산 정보 (시드로 대신)**

- 정산 정보는 서버만 읽는 곳에 저장한다. 은행 이름, 계좌번호 끝 4자리, 예금주 이름, 테스트 여부, 등록 시각만 둔다. 전체 계좌번호는 저장하지 않는다.
- 이번에는 시드 스크립트가 테스트 방송자에게 테스트 계좌를 넣는다. 등록 화면과 본인 인증은 만들지 않는다.
- 만 14세 이상 만 19세 미만 방송자는 정산 정보를 등록할 때 법정대리인의 동의를 받는다(09 약관 제5조). 이번에는 등록 화면을 만들지 않으므로 약관에만 적는다. 등록 화면을 만들 때 동의 단계를 함께 만든다.
- 시드 스크립트에 "정산 정보 없음" 옵션을 둔다. 이 옵션으로 보류 상태와 "등록 뒤 한꺼번에 지급"을 확인할 수 있다.

**정산 화면 (내 방송 관리)**

- 정산 카드: 가장 가까운 지급일에 받을 금액, 그 다음 지급일에 받을 금액(쌓이는 중), 각 지급 예정일, 정산 계좌(예: "테스트은행 ****1234 (테스트)" 또는 "정산 정보 없음 · 쌓아 두는 중"), 내 등급과 배분 비율. 금액 아래에 설명 문장을 두지 않는다. 두 금액은 같은 모양이 반복되므로 "?" 도움말도 두지 않는다.
- 정산 내역: 정산 기록을 최근 순서로 보여준다. 기간, 후원 건수, 방송자 몫, 상태, 지급 시각, 송금 번호다. 목업 기록에는 "테스트"를 붙인다.
- 방송자 화면에는 정산 실행 버튼이 없다. 정산 실행은 운영자 화면에서만 한다.

**내 등급 화면 (`/me/grade`)**

내 정보와 내 방송 관리에서 들어온다. 세 부분으로 나눈다.

1. **승급 안내:** 지금 등급과 다음 등급을 보여준다. 다음 등급의 세 조건을 진행 막대로 보여준다. 예를 들어 "방송 횟수 1/3회"다. 나비 등급이면 "가장 높은 등급이에요"를 보여준다.
2. **등급별 혜택:** 알, 애벌레, 번데기, 나비 탭을 둔다. 탭을 누르면 그 등급의 배분 비율, 다시보기 보관 기간, 등급 표시를 보여준다. 지금 등급 탭에는 "내 등급"을 붙인다.
3. **등급 변경 내역:** 변경일, 바뀐 등급, 배분 비율을 최근 순서로 보여준다. 가입한 날의 "알" 줄이 첫 줄이다.

### 4-13. 신고

시청자와 방송자는 문제가 있는 채팅, 방송, 사용자를 운영자에게 알릴 수 있다. 결정 이유는 06 결정 13에 있다.

**신고할 수 있는 것**

| 대상 | 어디서 | 신고 대상에 함께 저장하는 것 |
|---|---|---|
| 채팅 메시지(후원 메시지 포함) | 채팅 한 줄을 누르면 나오는 사용자 시트의 "이 메시지 신고" | 그 메시지의 원문 사본. 숨긴 채팅이면 숨긴 원문 |
| 방송 | 방송 보기 화면의 더보기 메뉴 "방송 신고" | 방송 ID, 제목, 신고한 시각 |
| 사용자 | 사용자 시트의 "사용자 신고" | 사용자 ID, 신고 시점의 닉네임 |

- 사용자 시트: 채팅에서 닉네임을 누르면 아래에서 올라온다. 닉네임, 등급 표시, "이 메시지 신고", "사용자 신고"가 있다. 방송자가 자기 방송에서 열면 "이 방송에서 채팅 금지"도 있다(4-14). 익명 후원 항목을 누르면 사용자 시트 대신 "이 메시지 신고"만 있는 시트를 연다. 익명 후원자의 닉네임과 등급은 보이지 않고, 활동 제한도 걸 수 없다(06 결정 27).
- 로그인해야 신고할 수 있다. 비로그인이면 로그인 화면으로 보냈다가 같은 방송으로 돌아온다.
- 나 자신은 신고할 수 없다. 메뉴에 신고 항목이 보이지 않는다.

**신고 흐름**

1. 신고 시트에서 사유를 하나 고른다. 사유는 욕설·비하, 성적인 내용, 도배·광고, 사칭, 불법·위험한 행동, 기타다.
2. 설명을 0~200자로 적을 수 있다. "기타"를 고르면 설명이 필수다.
3. "신고하기"를 누르면 서버가 신고를 저장한다. 화면에 "신고했어요. 처리 결과는 내 정보의 신고 내역에서 볼 수 있어요"를 보여준다.

- 같은 사람이 같은 대상을 두 번 신고할 수 없다. 신고 문서 ID를 `신고자ID_대상종류_대상ID`로 써서 막는다. 두 번째에는 "이미 신고했어요"를 보여준다.
- 한 사람은 하루 20건까지 신고할 수 있다. 넘으면 "오늘은 더 신고할 수 없어요"를 보여준다. 20은 임시값이다.
- 신고 대상은 누가 신고했는지 알 수 없다.
- 신고를 받아도 대상에 자동으로 조치하지 않는다. 운영자가 확인한 뒤 조치한다. 금칙어 자동 숨김(4-7)은 신고와 별개로 그대로 동작한다.

**신고 상태**

| 상태 | 뜻 | 신고자에게 보이는 것 |
|---|---|---|
| 접수 | 운영자가 아직 보지 않았다 | 접수됨 |
| 조치함 | 운영자가 제재하거나 콘텐츠를 숨겼다 | 조치했어요 |
| 기각 | 운영정책 위반이 아니라고 판단했다 | 위반이 확인되지 않았어요 |

- 내 정보에 "내 신고 내역"을 둔다. 신고한 대상, 사유, 시각, 상태를 보여준다. 익명 후원 메시지를 신고했으면 대상은 "익명 후원 메시지"로만 보여준다(06 결정 28). 어떤 제재를 했는지는 알려 주지 않는다.

### 4-14. 방송자 활동 제한

방송자는 자기 방송에서 특정 시청자의 채팅을 막을 수 있다. 운영자 제재(4-15)와 별개다. 활동 제한은 그 방송자의 방송에서만 효력이 있다.

- **거는 곳:** 송출 화면의 채팅에서 닉네임을 누르면 나오는 사용자 시트의 "이 방송에서 채팅 금지". 기간은 1일, 7일, 영구 중에서 고른다. 메모를 0~100자로 남길 수 있다.
- **효과:** 제한된 사용자는 그 방송자의 모든 방송에서 채팅을 쓸 수 없고, 후원 메시지도 쓸 수 없다. 후원 자체는 할 수 있다. 익명 후원자에게는 걸 수 없다(4-13). 입력 칸에 "이 방송에서 채팅이 제한됐어요"를 보여준다. 서버도 채팅 쓰기를 거절한다.
- **풀기:** 내 방송 관리의 "활동 제한" 탭에서 목록을 본다. 닉네임, 기간, 남은 시간, 메모, 건 시각이 있다. "해제"를 누르면 바로 풀린다.
- **기간이 끝나는 처리:** 예약 작업 없이 채팅을 쓸 때마다 서버가 끝나는 시각을 확인한다. 끝났으면 제한 기록을 지우고 채팅을 받는다.
- 방송자 자신과 운영자에게는 걸 수 없다.
- 제한된 사용자도 시청과 신고는 할 수 있다.

### 4-15. 운영자 화면과 제재

나비를 운영하는 사람의 화면이다. 주소는 `/admin` 아래이고 PC만 지원한다. 결정 이유는 06 결정 13에 있다.

**운영자 권한**

- 운영자는 Firebase 계정에 "운영자" 표시가 붙은 사람이다. 표시는 서버 스크립트로만 붙인다. 화면에서는 운영자를 만들 수 없다.
- 서버는 `/admin` 화면과 모든 운영자 요청에서 이 표시를 확인한다. 없으면 403이다.
- 테스트 운영자는 로그인 화면의 "테스트 운영자로 로그인"으로 들어온다(4-1).
- **테스트 계정 보호:** 테스트 운영자는 테스트 방송자, 테스트 시청자, 샘플 계정(4-18)에게 제재와 정산 보류를 할 수 없다. 실제 운영자는 할 수 있다. 비밀번호 없이 누구나 들어오는 계정이라 실제 운영자는 나쁜 방송을 막을 수 있어야 하기 때문이다. 실제 운영자가 건 제재는 부분 초기화가 풀어 준다(06 결정 29). 예외는 시드 스크립트 하나다. 시드 스크립트는 "시드 실행자"로 유스케이스를 부르고, 서버는 이 실행자일 때만 보호를 건너뛴다. 시드 실행자는 서버 스크립트에서만 만들 수 있다. 예외는 운영자 화면의 부분 초기화와 전체 초기화 API 하나다. 이 API는 운영자를 확인한 뒤, 대상이 시드 계정일 때만 서버 안에서 시드 실행자로 유스케이스를 부른다. 다른 API와 화면은 시드 실행자를 쓸 수 없다(06 결정 27, 28). 이 계정들이 막히면 다음 심사자가 확인할 화면이 사라지기 때문이다. 버튼이 눌리지 않고 "심사용 테스트 계정은 제재할 수 없어요"를 보여준다. 서버도 거절한다.
- **테스트 운영자의 조치 범위(06 결정 23):** 테스트 운영자는 시드 계정(4-18)과 그 계정의 방송, 채팅, 정산, 환급에만 조치할 수 있다. 조치는 제재, 해제, 콘텐츠 숨기기, 강제 종료, 정산 보류와 해제, 환급 승인과 거절, 신고 처리다. 실제로 가입한 사용자는 조회도 할 수 없다(06 결정 25). 운영자 화면의 모든 목록(대시보드, 회원 관리, 신고 처리, 제재 관리, 이의 제기, 방송 관리, 정산 관리, 환급 관리, 충전·결제 내역, 예약 작업 기록, 운영 기록)에서 실제 사용자 줄은 "심사용이 아닌 계정"으로 보이고 닉네임, 이메일, 본인인증 이름, 계좌, 충전·후원 기록을 가린다. 신고자가 실제 사용자이면 신고자 닉네임도 가린다. 익명 후원자의 실제 이름도 보이지 않는다. 상세 화면을 열거나 조치를 요청하면 "테스트 운영자는 심사용 계정만 보고 조치할 수 있어요"를 보여준다. 서버도 403으로 거절한다. 실제 사용자가 시드 계정의 방송에 쓴 채팅은 숨길 수 있지만, 작성자를 제재할 수는 없다. 월 정산 테스트 실행은 범위와 관계없이 할 수 있다. 목업 송금이라 돈이 움직이지 않기 때문이다. 금칙어는 보기만 한다. 전체 초기화는 10분에 한 번만 할 수 있다. 10분 안에 다시 누르면 "조금 뒤에 다시 초기화할 수 있어요"를 보여준다(06 결정 25). 서버는 운영자 표시와 별도로 "테스트 운영자" 표시를 보고 범위를 좁힌다. 이 범위는 실제 운영자에게는 적용하지 않는다.
- **제재 연습용 계정:** 시드 스크립트가 "제재 연습용" 계정을 만든다. 이 계정에는 채팅 신고 3건, 사용자 신고 1건이 쌓여 있다. 로그인 정보는 README에 적는다(4-18). 심사자는 이 계정으로 신고 처리와 제재를 해 본다.

**운영자 화면 목록**

| 화면 | 주소 | 하는 일 |

**신고 처리 상세**

- 위쪽에 대상을 보여준다. 채팅이면 원문 사본(숨긴 채팅이면 숨긴 원문), 방송이면 제목과 방송자, 사용자면 닉네임과 등급이다.
- 이 대상에 들어온 신고 목록(사유, 설명, 시각)을 보여준다. 신고자 닉네임은 운영자에게만 보인다.
- 대상 사용자의 지난 제재와 받은 신고 수를 함께 보여준다.
- 조치 버튼은 세 가지다.
  - **제재하기:** 제재 종류와 기간, 사유를 고른다. 이 대상의 신고는 모두 "조치함"이 된다.
  - **콘텐츠만 숨기기:** 채팅이면 숨김으로 바꾸고, 방송이면 강제 종료한다. 종료된 방송이면 다시보기를 비공개로 바꾼다. 신고는 "조치함"이 된다. 조치를 받은 사람(채팅 작성자, 방송자)에게 알림을 보낸다(4-17(06 결정 29)).
  - **기각:** 사유를 적는다. 신고는 "기각"이 된다.
- 조치할 때 사유는 필수다. 사유는 운영 기록과 제재 기록에 남는다.

**제재 단계와 효과**

| 제재 | 기간 | 효과 |
|---|---|---|
| 경고 | 없음 | 다음 로그인 때 경고 안내를 한 번 보여준다. 이용 제한은 없다 |
| 채팅 금지 | 1일 또는 7일 | 모든 방송에서 채팅과 후원 메시지를 쓸 수 없다. 시청과 후원은 할 수 있다 |
| 방송 금지 | 7일 또는 30일 | 방송을 만들거나 송출을 시작할 수 없다. 방송 중이면 "방송 종료" 함수로 바로 끝낸다(3장). 그 방송자의 방송 보기 주소를 열면 "이 방송자는 운영정책 위반으로 일시적으로 방송할 수 없어요"를 보여준다. 채팅과 시청은 할 수 있다 |
| 영구 정지 | 없음 | 로그인할 수 없다. 계정을 정지하고 로그인 토큰을 무효로 만든다. 방송 중이면 끝낸다. 그 방송자의 정산을 보류해서 정산 기록이 "보류(운영 조치)"가 된다(4-12, 09 약관 제10조). 운영자가 영구 정지를 해제해도 정산 보류는 따로 풀어야 한다(06 결정 28) |

- 기간이 끝나는 처리는 예약 작업 없이 요청이 올 때마다 서버가 확인한다. 사용자 문서에 "채팅 금지 끝 시각", "방송 금지 끝 시각", "영구 정지 여부"를 요약해 두고 매 요청에서 본다.
- 같은 종류의 제재가 겹치면 더 늦게 끝나는 쪽을 따른다.
- 운영자는 적용 중인 제재를 언제든 해제할 수 있다. 해제 사유는 필수다.
- 운영자에게는 제재를 걸 수 없다.

**제재받은 사람에게 보이는 것**

- 로그인하면 위쪽에 안내 띠를 보여준다. 예: "운영정책 위반(욕설·비하)으로 11월 21일 오후 3시까지 채팅을 쓸 수 없어요." 띠에 "자세히 보기"가 있다.
- 내 정보의 "제재 내역"(`/me/sanctions`)에서 제재 종류, 사유, 기간, 상태를 본다. 여기서 이의를 제기한다.
- 영구 정지된 사람은 로그인 화면에서 "운영정책 위반으로 이용이 정지된 계정이에요"를 본다. 이의 제기 안내 이메일 주소를 함께 보여준다. 로그인할 수 없으므로 화면 안에서 이의 제기는 못 한다.

**이의 제기**

- 경고, 채팅 금지, 방송 금지에 한 번씩 이의를 제기할 수 있다. 문서 ID를 제재 ID로 써서 두 번 못 하게 막는다.
- 내용은 10~500자다.
- 운영자가 받아들이면 제재를 "이의로 취소"로 바꾸고 효과를 바로 푼다. 거절하면 답변을 적는다. 제기한 사람은 제재 내역에서 결과와 답변을 본다.
- 이의 제기 중에도 제재는 계속 적용된다.

**운영 기록**

- 운영자의 모든 조치(제재, 해제, 신고 처리, 이의 제기 처리, 강제 종료, 정산 보류와 해제, 정산 실행, 환급 승인과 거절, 금칙어 변경, 테스트 계정 초기화)를 남긴다.
- 남기는 것은 운영자 ID, 행동, 대상, 사유, 바뀌기 전과 뒤의 값, 시각이다.
- 운영 기록은 서버만 쓴다. 고치거나 지울 수 없다.

### 4-16. 공통 헤더와 사이드바

모든 화면(운영자 화면 빼고) 맨 위에 헤더를 둔다. 결정 이유는 06 결정 20에 있다.

**헤더**

| 위치 | PC · 로그인 후 | PC · 로그인 전 | 휴대폰 |
|---|---|---|---|
| 왼쪽 | 사이드바 열기, 로고, 전체 방송, 다시보기 | 같다 | 사이드바 열기, 로고 |
| 오른쪽 | 스튜디오, 꿀, 알림, 화면 전환, 내 프로필 | 화면 전환, 로그인 | 로그인 후: 알림, 내 프로필. 로그인 전: 로그인 |

- **로고:** 홈(`/`)으로 간다.
- **전체 방송:** 홈으로 간다. **다시보기:** 다시보기 목록(`/replays`)으로 간다.
- **스튜디오:** 내 방송 관리(`/studio`)로 간다. 비로그인이면 로그인 화면으로 보냈다가 돌아온다.
- **꿀:** 내 꿀(`/me/honey`)로 간다.
- **알림:** 알림 패널을 연다(4-17). 읽지 않은 알림이 있으면 버튼에 점을 띄운다.
- **화면 전환:** 밝은 화면과 어두운 화면을 바꾼다. 기본은 어두운 화면이다. 고른 값은 브라우저에 저장하고, 다음에 열 때 그대로 쓴다.
- **내 프로필:** 프로필 메뉴를 연다.

**프로필 메뉴**

- 위쪽에 프로필 사진, 닉네임, 등급 표시, 이메일을 보여준다.
- 항목은 스튜디오, 내 정보, 내 꿀, 내 등급, 내 후원 내역, 내 신고 내역, 제재 내역, 로그아웃이다.

**사이드바**

- **PC(md 이상):** 왼쪽에 붙어 있는 영역이다. 헤더의 사이드바 열기 버튼으로 열고 닫는다. 열리면 오른쪽 콘텐츠가 밀려나고 어두운 막으로 덮지 않는다. 닫으면 아이콘만 보이는 좁은 막대가 된다. 처음에는 열려 있고, 고른 상태는 브라우저에 저장한다(06 결정 31).
- **휴대폰:** 지금처럼 화면 위에 덮어서 연다. 바깥을 누르면 닫힌다.
- 메뉴(전체 방송, 다시보기)를 둔다. 지금 있는 화면의 메뉴를 강조한다.
- "인기 카테고리"에 카테고리를 방송 수(방송 중과 준비 중)가 많은 순서로 보여준다. 누르면 홈의 그 카테고리 탭으로 간다.
- "지금 방송 중"에 방송 중인 채널을 홈 목록과 같은 순서(방송 중 먼저, 최근에 켠 순서)로 5개까지 보여주고, 각 줄에 시청자 수를 "1,234명"으로 붙인다. "더보기"는 홈으로 간다.

- 휴대폰에서는 헤더에서 빠진 스튜디오, 내 꿀(잔액 포함), 화면 전환을 사이드바 맨 위에 둔다.

### 4-17. 알림

나비 안에서 일어난 일을 알림으로 모아 보여준다. 팔로우와 방송 시작 알림, 웹 푸시는 만들지 않는다(06 결정 4, 결정 20).

**알리는 일**

| 일 | 받는 사람 | 문구 예 | 누르면 가는 곳 |
|---|---|---|---|
| 채팅 후원 확정 | 방송자 | 하린님이 5,000꿀을 후원했어요 | 내 방송 관리의 후원 내역 |
| 미션 상금·응원금 확정 | 방송자 | 하린님의 미션 상금 3,000꿀이 전달됐어요(06 결정 28) | 내 방송 관리의 후원 내역 |
| 미션 성공, 실패, 거절, 취소 | 미션을 보낸 시청자 | 민수님의 미션이 성공으로 끝났어요 | 내 후원 내역 |
| 정산 지급 완료, 보류 | 방송자 | 정산 28,000원이 지급됐어요 | 내 방송 관리의 정산 내역 |
| 승급 | 방송자 | 애벌레 등급이 됐어요 | 내 등급 |
| 신고 처리(조치함, 기각) | 신고한 사람 | 신고하신 채팅에 조치했어요 | 내 신고 내역 |
| 이의 제기 처리(받아들임, 거절) | 이의를 제기한 사람 | 이의 제기 결과가 나왔어요 | 제재 내역 |
| 환급 처리(완료, 거절) | 환급을 신청한 사람 | 2,970원 환급이 끝났어요 | 내 꿀의 환급 신청 내역 |
| 운영 조치(채팅 숨김, 방송 강제 종료, 다시보기 비공개) | 조치를 받은 사람 | 운영정책 위반(욕설·비하)으로 채팅을 숨겼어요 | 이동하지 않는다. 알림 패널에서 읽기만 한다. 제재가 아니라서 제재 내역에는 남지 않는다 |

- 제재는 알림이 아니라 안내 띠(4-15)로 알린다.
- 익명 후원의 알림에는 후원자 닉네임 대신 "익명"을 쓴다.

**만드는 방법**

- 서버가 일을 확정하는 같은 트랜잭션에서 알림 문서를 만든다. 예를 들어 후원을 확정하는 트랜잭션이 방송자의 알림도 만든다. 그래서 일은 됐는데 알림이 없는 경우가 생기지 않는다.
- 화면은 서버 API로 알림을 받는다. 페이지를 열 때 읽지 않은 수를, 알림 패널을 열 때 최근 30개를 불러온다. 실시간으로 바로 뜨지 않는다. 브라우저가 Firestore를 직접 읽는 범위를 넓히지 않기 위해서다(06 결정 2).
- 알림을 누르면 그 알림을 읽음으로 바꾸고 해당 화면으로 간다. "모두 읽음"은 내 알림을 모두 읽음으로 바꾼다.
- 30일이 지난 알림은 목록에서 보여주지 않는다. 지우는 작업은 만들지 않는다. 30일은 임시값이다.

### 4-18. 심사용 테스트 계정과 더미 데이터

심사자는 테스트 계정 버튼을 눌러 바로 들어온다. 이때 화면이 비어 있으면 기능을 확인할 수 없다. 그래서 시드 스크립트(처음 데이터를 넣는 스크립트)로 계정과 기록을 미리 만든다. 결정 이유는 06 결정 21에 있다.

**만드는 원칙**

1. **실제 기능을 거쳐 만든다.** 예외는 지난 방송(송출 없이 "종료"로 바로 만든다), 방송 횟수·누적 시간·샘플 방송자의 등급, 방송 중 예시 방송의 시청자 수, 그리고 실제 함수로 만들 수 없는 과거 상태다. 과거 상태는 이미 끝난 제재의 시작·끝 시각, 7일이 지난 충전과 30분이 넘은 결제 대기의 시각, 지난 예약 작업 기록이다. 이것들은 시드 실행자가 직접 쓰고, 코드에 이유를 주석으로 남긴다(06 결정 28). 정산 지급 실패와 환급 송금 실패는 실패하는 계좌와 송금 함수를 시드용으로 바꿔 실제 지급·승인 함수로 만든다. 후원, 충전, 방송 종료, 신고, 제재는 실제 서버 기능(06 결정 17의 유스케이스)을 불러서 만든다. 문서를 직접 써 넣지 않는다. 직접 써 넣으면 꿀 잔액과 꿀 내역, 받은 후원 건수와 등급, 알림이 서로 맞지 않게 되기 때문이다.
2. **바깥 서비스만 시드용으로 바꾼다.** 토스페이먼츠 결제는 "시드 결제"로, LiveKit 송출은 건너뛴다. 시각은 시드가 정한 과거 시각을 쓴다. 06 결정 17의 바깥 어댑터만 바꾸면 되므로 서버 로직을 고치지 않는다.
3. **여러 번 돌려도 결과가 같다.** 계정과 문서에 고정 ID를 쓴다. 이미 있으면 덮어쓴다.
4. **시드 기록에는 표시를 붙인다.** 시드가 만든 사용자에는 "시드 계정" 종류를, 나머지 문서에는 "시드 데이터" 표시를 붙인다. 초기화는 이 표시가 있는 것만 건드린다.
5. **시각은 실행 시각을 기준으로 정한다.** 방송과 후원은 실행 시각 기준 최근 사흘 안에 둔다. 알림 보관 기간(30일)과 충전 취소 기한(7일) 안에 들어가게 하기 위해서다.
6. **예시 표시를 붙인다.** 시드가 만든 다시보기와 샘플 계정에는 화면에 "예시"를 붙인다(06 결정 11의 목업 표시 원칙).

**계정 구성**

| 계정 | 닉네임(예) | 들어가는 방법 | 쓰임 |
|---|---|---|---|
| 테스트 방송자 | 테스트방송자 | 로그인 화면 버튼 | 방송, 승급, 정산, 활동 제한을 확인한다 |

- **버튼 로그인:** 로그인 화면의 버튼 세 개는 비밀번호를 쓰지 않는다. 서버가 그 계정 전용 로그인 토큰(Firebase 사용자 지정 토큰)을 만들어 주고, 브라우저는 이 토큰으로 로그인한다. 서버는 버튼 세 계정에만 토큰을 만든다. 배포 환경 변수로 이 기능을 켜고 끈다. 같은 IP에서 1시간에 20번까지만 토큰을 만든다. 넘으면 "잠시 뒤에 다시 시도해 주세요"를 보여준다. README에 심사가 끝나면 이 기능을 끄는 날짜를 적는다(06 결정 27).
- **테스트 방송자의 방송 길이:** 테스트 방송자 계정의 방송은 30분까지다. 송출 화면은 25분에 "5분 뒤에 방송이 끝나요"를 보여주고 30분에 종료를 요청한다. 서버도 시청 권한을 줄 때와 채팅을 받을 때 시작한 지 30분이 지났는지 확인하고, 지났으면 "방송 종료" 함수를 부른다. 공개 버튼 계정으로 LiveKit 무료 사용량(월 5,000 참가자·분)을 다 쓰지 못하게 하기 위해서다(06 결정 27).
- **README로 들어가는 계정:** 제재 연습용과 정지 예시는 버튼을 두지 않는다. 로그인 화면 버튼을 세 개로 유지하기 위해서다. 이메일과 비밀번호는 README에 적는다. 이 두 계정은 심사용이라 비밀번호가 공개돼도 괜찮다.
- **샘플 계정:** 비밀번호를 무작위로 만들고 어디에도 적지 않는다. 그래서 아무도 로그인할 수 없다.
- **확인용 명령(curl):** 10장의 직접 요청 확인에는 로그인 토큰이 필요하다. `pnpm test-token 시청자`처럼 버튼 계정의 토큰을 출력하는 명령을 둔다.

- **지난 방송 만들기(06 결정 28):** 시드의 지난 방송은 송출 없이 시드 실행자가 "종료" 상태로 바로 만든다. 시작·종료 시각은 과거로 쓰고, 채팅과 후원도 그 시각 안에 둔다. 테스트 방송자의 30분 제한은 방송 중인 방송에만 적용하므로 시드의 1시간짜리 지난 방송에는 걸리지 않는다. 방송 횟수와 누적 시간은 "방송 종료" 함수가 아니라 시드 실행자가 직접 더한다. 샘플 방송자의 등급도 시드 실행자가 직접 쓴다.
- **다시보기 영상:** 시드 스크립트가 짧은 예시 영상 3개(각 30초 안팎)를 R2에 올린다. 영상은 우리가 직접 만든 화면 녹화로, 저작권 문제가 없는 것만 쓴다. LiveKit 무료 녹화 시간(06 결정 6)을 쓰지 않는다.
- **정산 기록 만들기:** 월 정산 테스트 실행을 시드가 실제 함수로 한다. 기준 시각을 61시간 전으로 주기 때문에 그 전에 끝난 새 샘플 방송자(하늘달, 서준, 도윤, 보람, 예린)의 후원만 정산된다. 테스트 방송자, 제재 연습용, 하린방송, 민수게임의 후원은 정산되지 않고 남아 10-8의 시나리오가 그대로 된다. 이 때문에 새 샘플 방송자의 지난 방송은 62시간보다 오래된 시각으로 둔다. 월 초 사흘 안에 시드를 돌리면 기준 시각이 지난달에 걸려 일부 후원이 빠질 수 있다. 예약 실행 기록은 실제 예약 실행이 지난달 후원을 모두 정산하는 함수라서 직접 써 넣는다. 지난 예약 실행 2건(성공, 일부 실패)과 지난 테스트 실행 1건이다.
- **금칙어:** 시드가 운영자 권한으로 "먹튀", "불법토토", "도박사이트"를 더한다. 이미 있으면 건너뛴다. 금칙어 목록은 전체 초기화가 지우지 않는다.

**여러 심사자가 함께 쓸 때**

- 버튼 계정은 모든 심사자가 함께 쓴다. 심사자마다 새 계정을 만들어 주지 않는다. README의 계정 정보와 확인용 명령이 늘 같아야 하기 때문이다(06 결정 21).
- 앞 심사자가 남긴 기록은 다음 심사자에게도 보인다. 그래서 초기화를 두 가지로 둔다.
  - **부분 초기화:** 운영자 화면의 테스트 계정 메뉴에서 버튼 하나씩 누른다. 테스트 시청자 꿀을 0으로, 테스트 방송자를 승급 직전으로, 제재 연습용 계정을 신고 4건과 제재 없음, 남은 꿀 5,000으로 되돌린다. 제재 연습용 계정에 "대기" 중인 환급 신청이 있으면 거절로 처리한 뒤 되돌린다. 기록은 지우지 않는다. 꿀을 줄일 때는 꿀 내역에 "시드 조정" 줄을 남긴다. 꿀을 늘릴 때는 승인 시각이 10일 전인 시드 결제 충전을 만든다(4-8의 꿀 내역 규칙). 테스트 방송자를 승급 직전으로 되돌릴 때는 예외로 등급, 방송 횟수, 누적 방송 시간, 받은 후원 건수를 직접 덮어쓴다. 등급 변경 내역에는 "심사용 초기화" 줄을 남긴다. 이미 받은 후원에 저장한 배분 비율은 바꾸지 않는다. 실제 운영자가 테스트 방송자, 테스트 시청자, 샘플 계정에 건 제재도 해제한다(06 결정 29). 테스트 시청자의 하루 충전 한도는 "오늘 0시"와 "마지막 부분 초기화 시각" 가운데 늦은 때부터 다시 센다(06 결정 27). 제재 연습용 계정의 신고 4건은 새로 만들지 않고 시드가 만든 그 4건 문서를 "접수"로 덮어쓴다. 신고 문서 ID가 `신고자ID_대상종류_대상ID`라서 새로 만들 수 없기 때문이다. 아래도 함께 되돌린다. 테스트 방송자가 테스트 시청자에게 건 활동 제한은 지운다. 제재 연습용 계정에 걸린 제재는 모두 "해제"로 바꾸고, 영구 정지였다면 계정 정지도 푼다. 정지 예시 계정은 영구 정지를 다시 건다(06 결정 28).
  - **전체 초기화 전 확인(06 결정 28):** 먼저 시드 계정의 준비 상태와 방송 중인 방송을 "방송 종료" 함수로 끝낸다. 그다음 아래 가운데 하나라도 있으면 초기화를 거절하고 이유를 보여준다. 시드 계정이 보냈거나 시드 방송에 걸린 대기 중·진행 중 미션, 시드 계정의 결제 대기·취소 중 충전, 시드 계정의 처리 중 환급(대기, 송금 중, 송금 실패), 시드 방송자의 송금 중 정산 기록이다. 다만 시드가 일부러 만든 처리 중 기록("시드 데이터" 표시가 있는 것, 예를 들어 소라의 환급 대기, 지민의 결제 대기와 송금 실패)은 막지 않는다. 심사자가 만든 기록만 막는다. 시드가 만든 기록은 전체 초기화가 지운다. 진행 중인 돈 처리를 끊으면 4-8의 불변식이 깨지기 때문이다.
  - **전체 초기화:** 시드 계정이 주인인 문서를 "시드 데이터" 표시와 관계없이 모두 지우고 시드를 처음부터 다시 만든다. 다만 실제 사용자가 후원자나 방송자로 걸린 후원 기록은 지우지 않는다. 그 후원의 시드 쪽 이름만 "초기화된 심사용 계정"으로 바꾼다(06 결정 28). 정산 기록은 아래 규칙대로 시드 방송자의 것을 모두 지운다. 주인은 문서의 사용자 ID, 후원자 ID, 방송자 ID, 신고자 ID로 정한다. 심사자가 시드 계정으로 한 충전, 꿀 내역, 후원, 정산, 신고도 함께 지운다. 그래야 지갑과 꿀 내역이 함께 처음 상태로 돌아간다. 시드 방송자의 정산 기록은 모두 지우고, 그 기록에 들어 있던 실제 사용자의 후원은 정산 ID를 null로 되돌려 남긴다(06 결정 27). 운영자 화면의 "전체 초기화" 버튼과 `pnpm seed --reset` 명령 두 곳에서 할 수 있다. 같은 함수를 부른다.
- **전체 초기화가 지우지 않는 것**
  - 시드 계정이 아닌 실제 사용자가 얽힌 돈 기록(충전, 후원, 정산)은 남긴다. 돈이 오간 기록은 지우지 않는다는 원칙(4-10)을 지키기 위해서다. 이 후원은 "지운 방송"의 후원처럼 보인다.
  - 시드 계정이 실제 사용자의 방송에 쓴 채팅은 남긴다. 다른 사람의 대화 흐름이 끊기지 않게 하기 위해서다.
  - 운영 기록은 지우지 않는다(4-15). 전체 초기화를 했다는 기록이 한 줄 더 생긴다.
  - Firebase 계정은 지우지 않는다. 사용자 ID가 그대로라 로그인 토큰과 README가 바뀌지 않는다.
- 전체 초기화는 수십 초 걸릴 수 있다. 그동안 시드 계정의 요청에는 "테스트 계정을 준비하는 중이에요"를 보여준다.
- 두 심사자가 같은 테스트 방송자로 동시에 송출하는 것은 막지 않는다. 방송은 서로 다른 방이라 부딪히지 않는다. README에 "동시에 쓰면 서로의 기록이 보일 수 있다"고 적는다.

**실행 방법**

- 로컬: `pnpm seed`를 Firebase 에뮬레이터(내 컴퓨터에서 도는 가짜 Firebase)에 실행한다. 개발을 시작할 때 한 번 돌린다.
- 배포 환경: `pnpm seed --target=production`으로 실행한다. 실수를 막기 위해 Firebase 프로젝트 이름을 한 번 더 입력해야 실행된다. 배포한 뒤 심사 전에 한 번 돌린다.
- 시드는 시드 표시가 없는 계정과 문서를 고치거나 지우지 않는다.

**아직 정하지 않은 것**

- 예시 영상 3개를 무엇으로 찍을지 정해야 한다.
- 매달 1~3일에 시드를 돌리면 일부 후원이 지난달로 들어간다. 그러면 정산 테스트("이번 달 1일부터", 4-12)에 그 후원이 빠진다. 심사 기간(11월 말)에는 해당하지 않아 그대로 둔다.

**거절했을 때 응답**

| 경우 | 서버 응답 | 화면 |
|---|---|---|
| 로그인하지 않았다 | 401 | 로그인 화면으로 보낸다 |
| 로그인했지만 소유자나 작성자가 아니다 | 403 | "권한이 없어요"를 보여준다 |
| 대상이 없다 | 404 | "방송을 찾을 수 없어요"를 보여준다 |

**LiveKit 접속 권한**

- 송출용 권한(영상을 보낼 수 있음)은 서버가 소유자를 확인한 뒤에만 준다. 접속 이름은 `host_사용자ID`다.
- 시청용 권한(영상을 받기만 함)은 누구에게나 준다. 접속 이름은 접속할 때마다 새로 만든 `viewer_무작위값`이다. 방송자가 "시청자 화면으로 보기"로 연 탭도 시청자 이름을 받는다. 같은 이름으로 두 번 접속하면 앞의 연결이 끊길 수 있기 때문이다(06 결정 25).
- 서버는 접속 이름이 `host_`로 시작하는 참가자만 송출자로 본다(3장, 7장).
- 송출용 권한 없이 LiveKit 방에 영상을 보낼 방법은 없다.

- 브라우저가 정한 번호를 문서 ID로 쓰는 문서(채팅, 후원, 환급 신청, 신고, 정산 테스트 실행)는 서버가 `create`로만 저장한다. 같은 ID가 이미 있으면 작성자가 같을 때만 같은 요청으로 보고 저장한 결과를 그대로 돌려준다. 작성자가 다르면 409로 거절한다. `set`으로 저장하면 다른 사람의 문서를 덮어쓸 수 있기 때문이다(06 결정 27).
- 방송 삭제 후에도 후원 기록이 남는다. 그래서 후원 기록에 방송 ID와 함께 필요한 정보(방송 제목, 방송자 ID, 금액)를 직접 저장한다. 지운 방송의 후원은 이 정보로 보여준다.
- Firestore 보안 규칙은 모든 모음에서 브라우저의 쓰기를 막는다. 읽기는 방송, 채팅, 공개한 녹화만 허용한다. 사용자, 닉네임, 숨긴 원문, 꿀 지갑, 충전, 꿀 내역, 후원, 정산 기록, 정산 정보, 본인인증, 환급 신청, 작업 실행 기록, 신고, 신고 대상 요약, 제재, 이의 제기, 활동 제한, 운영 기록, 설정, 채팅 수정·삭제 기록, 탈퇴 포기 동의, 요청 횟수, 사용량은 서버만 읽는다. 익명 후원자의 실제 ID가 브라우저로 나가지 않게 하기 위해서다. 채팅 모음의 후원 항목에는 익명이면 후원자 ID를 넣지 않는다. 내 후원 내역과 받은 후원 내역은 서버가 로그인 사용자를 확인한 뒤 내려준다.
- 서버를 다시 시작해도 모든 데이터가 Firestore와 R2에 남는다.
- 시드가 만든 문서에는 모두 "시드 데이터" 표시를 붙인다. 전체 초기화는 이 표시가 있는 문서만 지운다(4-18).
- 나머지 색인 목록은 06 결정 19에 있다.
- 채팅 모음(`comments`)의 작성자 ID에 컬렉션 그룹 색인을 켠다. 이 색인이 있어야 탈퇴할 때 모든 방송에서 그 사용자의 채팅을 한 번에 찾을 수 있다(4-11).

## 7. 서버 알림 처리 (웹훅)

| 보내는 곳 | 알림 | 서버가 하는 일 |
|---|---|---|
| LiveKit | 트랙이 올라왔다 | 올린 참가자가 송출자(`host_사용자ID`)이고 방송이 준비 상태일 때만, 서버가 LiveKit 서버 API로 송출자가 방에 있는지 확인한 뒤 방송 중으로 바꾼다. 송출 화면의 "송출 확인" 요청과 먼저 온 쪽으로 한 번만 바꾼다(3장, 06 결정 25). 시청자의 알림과 이미 방송 중인 방송의 알림은 무시한다 |
| LiveKit | 참가자가 방에서 나갔다 | 나간 참가자가 그 방송의 송출자(송출용 접속 권한을 받은 방송자)이고 방송이 방송 중일 때만 3장의 "방송 종료" 함수를 부른다. 부르기 전에 LiveKit 서버 API로 송출자(`host_사용자ID`)가 아직 방에 있는지 확인한다. 같은 이름으로 다시 연결해 방에 있으면 종료하지 않는다. 앞 연결의 "나갔다" 알림이 늦게 와도 방송이 끝나지 않게 하기 위해서다(06 결정 27). 시청자가 나간 알림은 무시한다. 미션 반환과 녹화 상태 변경도 이 함수가 함께 한다 |
| LiveKit | 방이 끝났다 | 방송이 방송 중일 때만 "방송 종료" 함수를 부른다. 준비 상태인 방송은 시청자가 모두 나가 방이 끝나도 그대로 둔다 |
| LiveKit | 녹화가 끝났다 | 녹화 상태를 "볼 수 있음" 또는 "실패"로 바꾸고 파일 위치와 길이를 저장한다. 공개 여부는 비공개로 둔다. 녹화 정보가 이미 없으면(탈퇴 등) R2 파일을 지우고 끝낸다 |
| 토스페이먼츠 | 결제 상태가 바뀌었다 | 알림에 담긴 결제 키로 토스페이먼츠에 결제를 다시 조회한다. 조회 결과로 완료를 확인하면 "충전 확정" 함수(함께 처리할 후원이 있으면 후원까지)를 부른다. 이미 확정된 주문이면 아무것도 하지 않는다. 조회 결과가 취소이고 우리 충전이 "취소 중"이면 "취소"로 끝낸다(4-8 충전 취소) |

- LiveKit 알림은 서명으로 확인한다. LiveKit 서버 SDK에 확인 기능이 들어 있다. 서명이 맞지 않으면 무시한다.
- 토스페이먼츠 알림은 내용을 그대로 믿지 않는다. 결제 웹훅에 서명이 붙는지 공식 문서로 확인하지 못했기 때문이다. 서버는 알림에 담긴 결제 키로 토스페이먼츠 결제 조회 API를 비밀 키와 함께 부른다. 조회 결과가 아래 세 가지를 모두 채울 때만 충전을 확정한다.
  - 결제 상태가 완료다.
  - 주문번호가 우리 충전 주문에 있다.
  - 결제 금액이 주문 금액과 같다.
- 결제 완료 화면(`/charge/success`)과 토스페이먼츠 웹훅은 같은 "충전 확정" 함수를 부른다. 어느 쪽이 먼저 오든 꿀은 한 번만 들어간다(4-8의 "한 번만 처리하기").
- 알림은 10초 안에 성공 응답을 보낸다.

## 10. 완료 기준과 심사 시나리오

각 시나리오가 그대로 되면 그 기능은 끝난 것이다. README의 "기능 확인" 절차도 이 순서로 쓴다.

### 10-1. PC 방송

1. 맥북 크롬에서 테스트 방송자로 로그인한다.
2. 방송 만들기에서 "PC 화면 공유"를 고르고 만든다.
3. 공유 전 안내를 보고, 소리가 나는 탭(예: 유튜브)을 "탭 오디오 공유"를 켠 채 공유한다.
4. 미리보기에서 탭 소리 막대와 마이크 소리 막대가 움직인다.
5. "방송 시작"을 누르면 송출이 올라온 뒤 상태가 방송 중으로 바뀐다. 30초 안에 올라오지 않으면 준비 상태 그대로 "방송을 시작하지 못했어요"가 나온다.
6. 아이폰(휴대폰 데이터)에서 방송 링크를 연다. 화면이 나오고, "소리 켜기"를 누르면 탭 소리와 마이크 소리가 함께 들린다.
7. 맥북에서 "방송 종료"를 누르면 아이폰 화면이 "방송이 끝났어요"로 바뀐다. 홈 목록에서도 사라진다.
8. 다시 방송을 만들고 시작한 뒤 크롬의 "공유 중지"를 누른다. 방송이 종료된다.

### 10-2. 휴대폰 방송

1. 아이폰에서 테스트 방송자로 로그인한다.
2. 방송 만들기에서 카메라가 기본으로 골라져 있다. 만든다.
3. 링크를 복사하고, 권한 안내 뒤 카메라와 마이크를 허용한다.
4. "방송 시작"을 누른다.
5. 맥북에서 링크를 열면 카메라 영상과 소리가 나온다.
6. 아이폰에서 "방송 종료"를 누르면 맥북 화면이 종료 안내로 바뀐다.
7. 다시 방송을 시작한 뒤 아이폰 화면을 잠근다. 방송이 종료된다.

### 10-3. 방송 관리와 시청

1. 방송 만들기, 제목 수정, 삭제가 된다. 방송 중인 방송에는 삭제 버튼이 없고, 서버에 직접 삭제를 요청해도 거절된다. 끝난 방송은 내 방송 관리 목록에 들어오고, 거기서 지울 수 있다.
2. 홈 목록에 방송 중인 방송이 먼저, 최근 시작한 순서로 나온다.
3. 방송 보기 화면에서 상태(준비, 방송 중, 종료)가 새로고침 없이 바뀐다.
4. 서버를 다시 시작해도 방송 목록과 방송 정보가 그대로 조회된다.

### 10-4. 인증과 권한

1. 회원가입, 로그인, 로그아웃이 된다. 새로고침해도 로그인이 유지된다.
2. 비로그인 상태에서 방송 목록 보기와 시청이 된다.
3. 비로그인 상태에서 방송 만들기를 누르면 로그인 화면으로 간다.
4. 테스트 시청자로 로그인해서 테스트 방송자의 송출 화면 주소를 열면 거절된다.
5. 테스트 시청자가 서버에 테스트 방송자 방송의 수정, 삭제, 송출 시작, 종료를 직접 요청해도 403으로 거절된다. README에 확인용 명령(curl)을 적는다.
6. 회원가입에서 필수 약관에 동의하지 않으면 가입 버튼이 눌리지 않는다. 이미 쓰이는 닉네임은 거절된다.
7. 비밀번호 찾기 메일이 온다.
8. 새로 가입한 계정에서 닉네임을 한 번 바꾸면, 두 번째 변경은 화면과 서버 모두에서 거절된다.
9. 새로 가입한 계정을 탈퇴하면 다시 로그인할 수 없고, 그 계정이 쓴 채팅은 "탈퇴한 사용자"로 보인다.

### 10-5. 채팅

1. 비로그인 상태에서 채팅을 읽을 수 있고, 쓰려고 하면 로그인 화면으로 간다.
2. 로그인하면 채팅을 쓰고, 다른 기기에서 새로고침 없이 보인다.
3. 내 채팅만 고치거나 지울 수 있고, 남의 채팅을 서버에 직접 고치거나 지우면 403으로 거절된다. 1초 안에 두 번 보내면 두 번째는 "조금 천천히 보내 주세요"로 거절된다.
4. 금칙어가 들어간 채팅을 보내면 모든 기기에서 "부적절한 표현이 감지되어 숨긴 채팅이에요"로 보인다.
5. 방송이 종료되면 입력 칸이 막히고, 서버에 직접 채팅을 보내도 거절된다.
6. 방송 중에 새로고침하거나 늦게 들어와도 최근 채팅 50개가 보이고, 그 뒤 채팅은 바로 이어서 나타난다.

### 10-6. 후원과 꿀

1. 테스트 시청자로 로그인한다. 꿀이 0인 상태에서 테스트 방송자의 방송을 열고 "후원하기"를 누른다. 후원 창이 아래에서 올라온다.
2. "+1천"을 세 번 눌러 3,000꿀을 만들고 메시지를 쓴다. 버튼이 "충전하고 후원하기"로 바뀌고, 충전 꿀 수는 모자란 3,000꿀 이상인 가장 작은 단위인 5,000꿀로 골라진다.
3. 테스트 결제창에서 5,500원(부가세 포함)을 결제하면 5,000꿀이 충전되고 바로 3,000꿀 후원이 확정된다. 송출 화면에 알림이 뜨고, 방송 화면의 후원 합계가 3,000 늘어난다. 내 꿀에는 2,000꿀이 남는다.
4. 같은 결제 승인 요청을 다시 보내도 꿀과 합계가 늘지 않는다. README에 확인 방법(curl)을 적는다.
5. 익명을 켜고 남은 꿀에서 1,000꿀로 다시 후원하면 채팅 목록과 송출 화면에 "익명"으로 보인다. 결제창은 뜨지 않는다.
6. 후원 버튼을 빠르게 두 번 눌러도 꿀은 한 번만 빠진다.
7. 방송 중에 미션 탭에서 제한 시간 5분, 상금 5,000꿀로 미션을 보낸다. 잔액이 모자라므로 "충전하고 후원하기"로 채운다. 미션을 보내면 송출 화면의 미션 목록에 뜨고, 시청자 잔액에서 5,000꿀이 묶인다. 방송자가 거절하면 5,000꿀이 돌아오고, 수락 뒤 "성공"을 누르면 5,000꿀이 후원 합계에 들어간다.
7-1. 준비 상태 방송에서는 미션 탭에 "방송이 시작되면 미션을 보낼 수 있어요"만 보이고, 서버에 직접 미션을 보내도 거절된다(06 결정 25).
8. 수락한 미션을 5분 동안 두면 "실패"가 되고, 응원금 1,000꿀만 후원 합계에 들어가고 4,000꿀은 시청자에게 돌아온다. 대기 중인 미션이 있는 상태에서 방송을 종료하면 "취소됨"이 되고 5,000꿀이 모두 돌아온다.
9. 내 꿀 화면에서 쓰지 않은 충전 건은 취소되고, 일부라도 쓴 충전 건은 "취소할 수 없음"으로 보인다.
9-1. 새로 가입한 계정으로 "충전하기"를 누르면 결제창보다 본인인증(목업) 창이 먼저 뜬다. 생년월일을 만 19세 미만으로 넣으면 "만 19세 이상만 꿀을 충전할 수 있어요"가 나오고 결제창이 뜨지 않는다. 이 계정으로 서버에 충전 주문을 직접 요청해도 거절된다. README에 확인용 명령(curl)을 적는다.
9-2. 테스트 시청자의 충전 창에는 "오늘 남은 한도"가 보인다. 하루 한도를 넘기는 경우는 화면에서 확인하지 않는다. 함께 쓰는 테스트 계정의 그날 충전이 막히기 때문이다. 대신 서버 테스트(오늘 999,000꿀을 충전한 상태에서 5,000꿀 주문이 거절되는지)로 확인하고, README에 테스트 명령을 적는다.
10. 내 방송 관리에서 후원 내역, 합계, 예상 수익이 보인다. 줄마다 적용한 배분 비율이 보인다. 지운 방송의 후원도 "지운 방송" 묶음에 남는다.
11. 방송을 종료하면 시청 화면에서 후원 버튼이 사라지고, 서버에 직접 후원을 요청해도 거절된다.
12. 테스트 방송자 계정은 애벌레 승급 직전 상태(방송 2회, 누적 2시간, 받은 후원 6건)로 준비한다(4-18). 10-1에서 10분 넘게 방송했다면 이미 애벌레가 되었으므로, 이 단계 전에 운영자 화면에서 테스트 방송자를 부분 초기화한다. README에도 적는다(06 결정 28). 10분 넘게 방송하고 종료하면 등급이 애벌레로 오른다. 내 등급 화면에 등급 변경 내역이 한 줄 늘고, 그 뒤 받은 후원은 82%로 계산된다. 승급 전에 받은 후원은 80% 그대로다.

### 10-7. 녹화와 다시보기

1. 송출 화면에서 방송을 시작하기 직전에 "이 방송 녹화하기"를 켜고, 1~2분 방송한 뒤 종료한다.
2. 잠시 뒤 내 방송 관리에서 녹화가 "볼 수 있음, 비공개"로 보인다. 이때 다시보기 목록에는 없다.
3. "공개"로 바꾸면 다시보기 목록에 녹화가 나타나고, 비로그인 상태에서도 재생된다. 다시 비공개로 바꾸면 목록에서 사라지고 재생 주소도 막힌다.
4. 녹화가 처리 중인 방송은 삭제 버튼을 눌러도 지워지지 않는다. 방송 중인 방송은 목록에 없고, 지금 방송 카드에도 삭제 버튼이 없다.
5. 서버를 다시 시작해도 다시보기 목록과 재생이 그대로 된다.
6. 내 방송 관리에서 녹화를 지우면 목록에서 사라진다.

### 10-8. 정산 (필수 기능이 끝난 뒤에 만든다)

1. 테스트 방송자로 로그인한다. 내 방송 관리의 정산 카드에 정산 계좌 "테스트은행 ****1234 (테스트)"와 "다음 달 25일에 받을 금액(쌓이는 중)"이 보인다. 이 금액은 후원 내역의 예상 수익 합계와 같다.
2. 테스트 운영자로 로그인해 정산 관리의 "월 정산 지금 실행(테스트)"을 누른다. 테스트 방송자로 돌아가면 정산 내역에 새 줄이 생겨 있다. 기간은 이번 달 1일부터 지금까지이고, 상태는 "지급 완료(테스트)"이며, `MOCK-`로 시작하는 송금 번호가 붙는다.
3. 바로 한 번 더 누르면 "정산할 후원이 없어요"가 나온다. 보류로 남은 기록(민수게임)이 있으면 "새로 정산할 후원이 없어요. 보류로 남은 기록 n건은 그대로예요"가 나온다. 같은 후원이 두 번 정산되지 않는다(06 결정 28).
4. 같은 요청 번호로 서버에 다시 요청해도 정산 기록이 늘지 않는다. README에 확인 방법(curl)을 적는다.
5. 새 후원을 받은 뒤 다시 누르면 새 후원만 들어간 정산 기록이 하나 더 생긴다.
5-1. 테스트 운영자가 정산 관리에서 제재 연습용 계정의 정산을 보류한 뒤 월 정산 테스트 실행을 누르면, 그 계정의 새 정산 기록이 "보류(운영 조치)"로 생긴다. 보류를 풀고 다시 누르면 "지급 완료(테스트)"가 된다(06 결정 28).
6. 시드 스크립트의 "정산 정보 없음" 옵션으로 준비한 계정은 정산하면 "보류(정산 정보 없음)"가 된다. 정산 정보를 넣고 다시 정산하면 보류 기록과 새 기록이 함께 "지급 완료(테스트)"가 된다.
7. 테스트 방송자나 테스트 시청자가 서버에 정산 실행을 직접 요청하면 403으로 거절된다.

### 10-9. 신고와 방송자 활동 제한

1. 테스트 시청자로 테스트 방송자의 방송에서 다른 사람 채팅의 닉네임을 누르면 사용자 시트가 열린다. 내 닉네임을 누르면 신고 항목이 없다.
2. "이 메시지 신고"에서 사유를 고르고 신고하면 "신고했어요"가 나온다. 같은 메시지를 다시 신고하면 "이미 신고했어요"가 나온다.
3. 내 정보의 신고 내역에 "접수됨"으로 보인다.
4. 테스트 방송자가 송출 화면에서 시청자 닉네임을 눌러 "이 방송에서 채팅 금지(1일)"를 걸면, 그 시청자의 입력 칸에 "이 방송에서 채팅이 제한됐어요"가 보이고 서버에 직접 보내도 거절된다.
5. 내 방송 관리의 활동 제한 탭에서 해제하면 바로 다시 채팅할 수 있다.

### 10-10. 운영자 화면과 제재

1. 테스트 운영자로 로그인하면 `/admin` 대시보드가 보인다. 테스트 시청자로 `/admin`을 열면 403이다.
2. 신고 처리에 "제재 연습용" 계정의 신고 4건이 묶여 보인다. 채팅 신고 상세에 원문이 보인다.
3. "제재하기"에서 채팅 금지 1일과 사유를 고르면 신고 4건이 모두 "조치함"이 되고 운영 기록에 한 줄 남는다.
4. README의 이메일과 비밀번호로 제재 연습용 계정에 로그인하면 위쪽에 채팅 금지 안내 띠가 보이고 채팅을 쓸 수 없다. 제재 내역에서 이의를 제기할 수 있고, 두 번째 이의 제기는 막힌다.
5. 운영자가 이의를 받아들이면 바로 채팅할 수 있다.
6. 테스트 운영자로 테스트 방송자에게 제재를 걸려고 하면 "심사용 테스트 계정은 제재할 수 없어요"가 나오고 서버도 거절한다.
7. 방송 관리에서 방송 중인 방송을 강제 종료하면 시청 화면이 바로 종료로 바뀐다.
8. 테스트 계정 화면에서 제재 연습용 계정을 초기화하면 신고 4건과 제재 없음 상태로 돌아간다.
9. 새로 가입한 계정에 테스트 운영자가 제재를 걸려고 하면 "테스트 운영자는 심사용 계정만 보고 조치할 수 있어요"가 나오고 서버도 403으로 거절한다(06 결정 23).

### 10-11. 꿀 환급 (필수 기능이 끝난 뒤에 만든다)

1. README의 이메일과 비밀번호로 제재 연습용 계정에 로그인한다. 내 꿀에 잔액 5,000이 보이고, 그 충전 건은 "취소할 수 없음(7일 지남)"으로 보인다.
2. "환급 신청"을 누르면 환급할 꿀 5,000, 결제 금액 기준 5,500원, 수수료 550원, 받을 금액 4,950원이 보인다. 계좌를 넣고 신청하면 잔액은 0, 환급 대기는 5,000이 된다. 이때 후원하려고 하면 잔액이 모자라다고 나온다.
3. 같은 신청 번호로 서버에 다시 요청해도 환급 신청은 하나만 남는다. 처리 중인 신청이 있으면 새 신청 버튼이 눌리지 않는다.
4. 테스트 운영자로 로그인해 환급 관리에서 이 신청을 사유와 함께 거절한다. 제재 연습용 계정의 잔액이 5,000으로 돌아오고, 환급 결과 알림이 온다.
5. 다시 신청하고 운영자가 승인하면 상태가 "환급 완료(테스트)"가 되고 `MOCK-`로 시작하는 송금 번호가 붙는다. 꿀 내역에 "환급" 줄이 생긴다.
6. 테스트 시청자가 서버에 환급 승인을 직접 요청하면 403으로 거절된다.
7. 테스트 계정 화면에서 제재 연습용 계정을 초기화하면 남은 꿀 5,000으로 돌아온다. 지난 환급 신청 기록은 남는다.

## 11. 공모 체크리스트 대조

공모 체크리스트와 이 문서의 절을 맞춘 표는 [15 요구사항과 구현 근거](15-requirements-evidence.md) 한 곳에만 둔다. 표가 여러 곳에 있으면 한쪽만 고쳐져 서로 달라지기 때문이다. 15의 "명세" 칸이 이 문서의 절을 가리킨다.

## 12. 확인할 것

| 항목 | 확인 방법 |
|---|---|
| 화면 공유 녹화에 탭 소리가 함께 담기는지 | 실제로 녹화해서 재생한다 |
| 휴대폰 잠금 뒤 LiveKit이 "송출자가 나갔다"를 얼마나 빨리 알리는지 | 아이폰으로 송출하다가 화면을 잠그고 종료까지 걸린 시간을 잰다 |
| 토스페이먼츠를 사업자 없이 테스트 결제와 웹훅까지 쓸 수 있는지 | 확인했다. 테스트 키로 연동할 수 있다(06 결정 28) |
| R2 서명된 주소로 다시보기 영상이 아이폰에서 재생되는지 | 테스트 녹화를 아이폰에서 재생한다. 영상을 넘겨 보는 도중에 주소가 만료되지 않는지도 본다 |
| 금칙어 목록을 어디서 가져올지 | 공개된 한국어 욕설 목록의 이용 조건을 확인한다. 없으면 직접 50~100개로 시작한다 |
| 이용약관과 개인정보 처리방침의 내용 | 개인정보보호위원회의 처리방침 작성 지침을 참고해 쓴다. 수집 항목은 이메일, 닉네임, 충전과 후원 기록, 본인인증 정보(이름, 생년월일, 명의 확인값), 환급·정산 계좌(은행, 끝 4자리, 예금주)다(06 결정 27) |
| 포인트 이름 "꿀" | 임시 이름이다. 브랜드와 어울리는지 정한다 |
| 꿀 결제에 부가세 10%를 붙이는 표시가 맞는지 | 실제 서비스라면 세무 확인이 필요하다. 공모에서는 테스트 결제라 표시만 맞춘다 |
| 후원 안내 문구(13장)의 법적 검토 | 실제 서비스 전에는 전자상거래법과 유료서비스 약관을 기준으로 검토받는다 |
| 꿀이 선불전자지급수단에 해당하는지 | 실제 서비스 전에 금융위원회에 묻거나 변호사 의견을 받는다. 특히 미션 후원을 대가로 보는지 확인한다(06 결정 22) |
| 현금영수증 | 토스페이먼츠 테스트 모드에서 현금영수증 발급과 취소를 해 볼 수 있는지 확인한다. 통신판매업이 의무발행업종인지는 세무사에게 묻는다 |
| 매출을 후원 총액으로 잡을지 나비 몫만 잡을지 | 실제 서비스 전에 세무사와 정한다 |

## 13. 후원 안내 문구

후원 창의 "안내 보기"를 누르면 이 문구를 보여준다. 치지직 안내 창의 구성(채팅 후원 안내, 충전 안내)을 참고했다. 문장은 나비의 정책(4-8)에 맞춰 새로 썼다. 다른 서비스의 약관 문장을 그대로 옮기지 않는다.

### 후원 안내

- 후원 메시지와 미션 내용에 다른 사람의 권리를 침해하거나 법령, 나비 이용약관, 나비 운영정책을 어기는 내용이 있으면 그 내용의 일부나 전부를 숨길 수 있어요. 이런 후원을 한 사용자는 나비 이용이 제한될 수 있어요.
- 위와 같은 후원으로 생긴 불이익과 법적 책임은 후원한 사용자에게 있어요.
- 익명으로 후원해도 나비는 후원한 계정을 기록해요. 법령이나 운영정책을 어긴 후원은 익명이어도 이용 제한 대상이에요.
- 미션 후원은 방송자를 응원하는 후원이에요. 무언가를 사는 값이 아니에요. 방송자는 미션을 꼭 해야 하는 것이 아니고 거절할 수 있어요.
- 위험한 행동, 불법 행위, 선정적인 행동, 다른 사람을 괴롭히는 행동을 요구하는 미션은 보낼 수 없어요. 이런 미션을 보내면 나비 이용이 제한될 수 있어요.
- 미션 후원은 방송자가 수락한 때부터 정한 제한 시간 안에 "성공"을 누르면 상금 전부가 전달돼요.
- 방송자가 "실패"를 누르거나, 제한 시간이 지나거나, 진행 중에 방송이 끝나면 상금의 20%인 응원금만 전달되고 나머지는 돌려드려요. 응원금에서 100꿀 아래는 버려요.
- 방송자가 거절하거나, 수락하기 전에 방송이 끝나면 상금을 모두 돌려드려요.
- 채팅 후원과 전달된 상금·응원금은 취소할 수 없어요.

### 꿀 충전 안내

- 충전한 꿀로 준비 중이거나 방송 중인 방송자에게 후원할 수 있어요. 끝난 방송과 다시보기에서는 후원할 수 없어요.
- 꿀 1개는 1원이에요. 결제할 때 부가가치세 10%가 더해져요. 예를 들어 1,000꿀은 1,100원이에요.
- 꿀은 충전한 날부터 5년 동안 쓸 수 있어요.
- 꿀은 나비에서 후원에만 쓰는 포인트예요. 다른 사람에게 넘길 수 없어요. 쓰지 않은 꿀은 환급 신청으로 돌려받을 수 있어요.
- 꿀은 만 19세 이상만 충전할 수 있어요. 처음 충전할 때 본인인증을 한 번 해요.
- 한 번에 1,000꿀부터 1,000,000꿀까지 충전하고 후원할 수 있어요.
- 하루에 충전할 수 있는 꿀은 1,000,000꿀까지예요. 하루는 0시부터 세요. 결제를 기다리는 충전(30분 안)도 한도에 들어가요. 충전을 취소해도 그날 한도는 돌아오지 않아요.
- 꿀은 먼저 충전한 것부터 써요.
- 충전하고 7일 안에, 그 충전 건의 꿀을 하나도 쓰지 않았다면 내 정보 > 내 꿀에서 직접 충전을 취소할 수 있어요.
- 후원에 쓴 꿀은 돌려받을 수 없어요. 일부라도 쓴 충전 건은 충전 취소를 할 수 없어요.
- 충전 취소를 할 수 없는 꿀도, 쓰지 않았다면 내 정보 > 내 꿀에서 환급을 신청할 수 있어요. 결제 금액의 10%를 수수료로 빼고 본인 명의 계좌로 보내 드려요. 예를 들어 3,000꿀이면 2,970원이에요.
- 환급은 7일 안에 취소할 수 있는 충전 건의 꿀을 뺀 남은 꿀 전부를 한 번에 신청해요. 1,000꿀 미만이면 신청할 수 없어요. 미션에 묶인 꿀은 환급할 수 없어요.
- 환급을 신청하면 그 꿀은 후원에 쓸 수 없어요. 나비가 확인한 뒤 보내 드리고, 결과는 알림으로 알려 드려요.
- 계좌이체처럼 현금으로 결제하면 충전할 때 현금영수증을 발급해요. 충전을 취소하면 현금영수증도 취소돼요.
- 미션에 묶여 "대기 중"인 꿀이 들어 있는 충전 건은 취소할 수 없어요. 미션이 거절되거나 취소되어 꿀이 모두 돌아오면 다시 취소할 수 있어요(충전 후 7일 안). 실패해서 응원금이 나간 충전 건은 취소할 수 없어요.
- 충전 내역과 사용 내역은 내 정보 > 내 꿀에서 볼 수 있어요.
- 이용 목적 없이 충전과 취소를 되풀이하는 등 서비스 운영을 어렵게 하면 이용이 제한될 수 있어요.
- 회원 탈퇴 전에 남은 꿀을 확인해 주세요. 환급을 신청하지 않고 탈퇴하면 남은 꿀은 사라지고 되살릴 수 없어요. 환급을 처리하는 중에는 탈퇴할 수 없어요.
- 나비는 공모용 서비스라 모든 결제는 테스트 결제예요. 실제 돈이 나가지 않아요.
