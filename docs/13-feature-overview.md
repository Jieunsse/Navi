# 나비 기능 명세 요약

- 마지막 수정: 2026-11-19
- 한 줄 요약: 나비의 모든 기능과 공모 요구사항을 한 문서에서 보고, 기능마다 자세한 명세, 화면 시안, API 주소를 찾아갈 수 있게 정리한다.
- 이 문서의 위치: [문서 색인](README.md)
- 자세한 동작은 [07 기능 명세](07-feature-spec.md)가 기준이다. 이 문서와 07이 다르면 07을 따른다.

이 문서는 07 기능 명세를 줄인 요약이다. 07은 길어서 한 번에 읽기 어렵다. 그래서 기능 목록, 공모 요구사항 대조, 기능별 핵심 규칙, 화면 주소, API 주소를 이 문서 하나에 모았다.

- 화면 시안은 [08 화면 설계서](08-screen-spec.md)의 화면 묶음(A~O)에 있다. 각 묶음은 피그마 와이어프레임으로 이어진다.
- 꿀 가격, 수익 배분, 정산 같은 돈 이야기는 [11 수익 구조(BM)](11-business-model.md)에 있다.
- 신고, 제재, 충전 취소 같은 운영 규칙은 [12 운영 정책](12-policy.md)에 있다.
- 심사자가 기능을 확인하는 순서는 [README의 기능 확인 순서](../README.md#기능-확인-순서)에 있다.
- 각 기능의 확인 시나리오는 [07 10장 완료 기준과 심사 시나리오](07-feature-spec.md#10-완료-기준과-심사-시나리오)에 있다.
- 누가 무엇을 할 수 있는지는 [07 5장 권한 표](07-feature-spec.md#5-권한-표)에 있다.

## 3. 방송 상태 요약

방송 상태는 세 가지다. 자세한 표는 [07 3장 방송 상태](07-feature-spec.md#3-방송-상태)에 있다.

| 상태 | 뜻 | 이 상태가 되는 때 |
|---|---|---|
| 준비 | 방송을 만들었지만 송출은 아직이다 | 방송 만들기에서 "만들기"를 누른다. "방송 시작"을 눌러도 송출이 실제로 올라오기 전까지는 준비 그대로다 |
| 방송 중 | 송출하고 있다 | 송출이 LiveKit(실시간 영상 서비스)에 실제로 올라온다. 송출 화면의 "송출 확인" 요청과 LiveKit 알림 가운데 먼저 온 것으로 서버가 한 번만 바꾼다 |
| 종료 | 방송이 끝났다. 다시 방송 중으로 돌아가지 않는다 | 방송자의 "방송 종료", 크롬의 "공유 중지", 탭 닫기나 네트워크 끊김, 휴대폰 잠금, 운영자의 강제 종료나 방송 금지 |

- "방송 시작"을 누르고 30초 안에 송출이 올라오지 않으면 준비 상태로 남는다. 화면은 다시 시도하라고 안내한다.
- 종료로 가는 모든 길은 서버의 "방송 종료" 함수 하나를 부른다. 이 함수는 녹화 상태 변경, 미션 정리, 방송 횟수와 방송 시간 더하기를 한 번에 처리한다.
- 같은 종료 요청이 두 번 와도 한 번만 처리한다.
- 송출용 접속 권한은 준비 상태인 방송에만 준다. 그래서 방송 중인 방송의 송출 화면에는 다시 들어갈 수 없다.
- 준비 상태인 방송은 지울 수 있다. 방송 중인 방송은 지울 수 없다.

## 4. 기능별 핵심 규칙

API는 `apps/web/app/api` 아래에 실제로 있는 주소만 적었다. `[id]`는 방송 ID다. API가 없다고 적은 기능은 브라우저가 Firestore를 읽기 전용으로 실시간 구독해서 화면을 채운다.

### 4-1. 회원가입, 로그인, 로그아웃

- 이메일, 비밀번호, 닉네임, 약관 동의를 서버에 한 번에 보낸다. 서버가 계정과 사용자 정보를 함께 만든다.
- 닉네임은 2~12자의 한글, 영문, 숫자다. 다른 사람과 겹칠 수 없고 금칙어가 들어갈 수 없다. 가입 화면의 "중복 확인"을 통과해야 가입 버튼이 눌린다.
- 필수 약관은 만 14세 이상, 이용약관, 방송자 이용약관, 개인정보 수집과 이용 네 가지다. 방송자 등록 단계를 따로 두지 않으므로 가입할 때 방송자 약관도 받는다.
- 구글로 처음 로그인한 사람은 `/signup/google`에서 닉네임과 약관만 받고 가입을 마친다.
- 로그인 화면에 "테스트 방송자", "테스트 시청자", "테스트 운영자" 버튼이 있다. 버튼을 누르면 서버가 만든 로그인 토큰으로 비밀번호 없이 들어간다.
- 비밀번호 찾기는 가입하지 않은 이메일에도 "메일을 보냈어요"로 똑같이 안내한다. 가입 여부를 알려주지 않기 위해서다.
- API: `POST /api/auth/signup`, `POST /api/auth/check-nickname`, `POST /api/auth/signup-google`, `POST /api/auth/test-login`, `GET /api/me`
- 원문: [07 4-1](07-feature-spec.md#4-1-회원가입-로그인-로그아웃)

### 4-2. 홈(방송 목록)

- 위에서부터 안내 카드 줄, 지금 방송, 광고 예시 배너, 카테고리별 방송, 다시보기 순서로 채운다.
- 방송 중인 방송을 먼저 보여준다. 그 안에서는 최근에 시작한 방송이 위에 온다.
- 시청자 수로 정렬하지 않는다. 그래서 방금 켠 작은 방송도 맨 위에 보인다. 시청자 수는 카드에 숫자로 보여주기만 한다.
- 만든 지 1시간이 지난 준비 상태 방송은 홈에 보이지 않는다. 종료된 방송은 홈이 아니라 다시보기 목록에 나온다.
- 카테고리는 잡담, 게임, 공부, 음악, 요리, 그림, 운동, 여행 여덟 가지다.
- API: 없음. 홈은 Firestore를 실시간 구독해서 새로고침 없이 바뀐다.
- 원문: [07 4-2](07-feature-spec.md#4-2-홈방송-목록)

### 4-3. 방송 만들기

- 필수 입력은 제목 하나다. 기본값은 "[닉네임]의 방송"이고 1~50자다.
- 카테고리는 고르지 않으면 "잡담"이다.
- 송출 방식은 "PC 화면 공유"와 "카메라" 중에서 고른다. 휴대폰 브라우저에서는 화면 공유를 고를 수 없다.
- "만들기"를 누르면 준비 상태의 방송과 방송 링크가 생긴다. 그래서 방송을 시작하기 전에 링크를 먼저 복사할 수 있다.
- 방송 금지 제재를 받은 사람은 방송을 만들 수 없다.
- API: `POST /api/broadcasts`
- 원문: [07 4-3](07-feature-spec.md#4-3-방송-만들기)

### 4-4. 송출 화면(PC 화면 공유)

- 방송 소유자만 들어올 수 있다.
- 브라우저 공유 창이 뜨기 전에 "Chrome 탭"을 고르고 "탭 오디오도 공유"를 켜라고 그림으로 안내한다.
- 공유에 소리 트랙이 없으면 경고를 띄우고 "다시 공유" 버튼을 준다. 마이크를 거부해도 방송은 시작할 수 있지만, 마이크가 꺼져 있다는 안내가 끝까지 남는다.
- 녹화는 "방송 시작" 바로 위의 스위치로 고른다. 기본은 꺼짐이고, 방송이 시작된 뒤에는 바꿀 수 없다.
- 방송 중에는 링크 복사, 경과 시간, 연결 상태("좋음", "불안정", "다시 연결 중"), 채팅, 후원 알림, 미션 목록을 보여준다. "시청자 화면으로 보기"는 방송 보기 화면을 소리를 끈 새 탭으로 연다.
- "내 얼굴도 같이 보여주기"를 켜면 화면과 카메라를 함께 송출한다.
- API: `POST /api/broadcasts/[id]/publish-token`, `POST /api/broadcasts/[id]/confirm-live`, `POST /api/broadcasts/[id]/end`, `PATCH /api/broadcasts/[id]`, `POST /api/broadcasts/[id]/recording/stop`
- 원문: [07 4-4](07-feature-spec.md#4-4-송출-화면-pc-화면-공유)

### 4-5. 송출 화면(휴대폰 카메라)

- 시작 전에 링크를 먼저 복사하라고 안내한다. 방송 중에 다른 앱으로 가면 방송이 끝나기 때문이다.
- 권한 창이 뜨기 전에 "다음 창에서 허용을 눌러 주세요"를 먼저 보여준다.
- 미리보기에서 앞 카메라와 뒤 카메라를 바꿀 수 있다.
- 화면이 잠기거나 다른 앱으로 넘어가 송출이 끊기면 방송이 종료된다. 다시 돌아오면 "방송이 끝났어요. 새 방송 만들기"를 보여준다.
- 녹화 고르기, 방송 시작과 종료, 연결 상태 표시는 PC와 같다.
- API: 4-4와 같다.
- 원문: [07 4-5](07-feature-spec.md#4-5-송출-화면-휴대폰-카메라)

### 4-6. 방송 보기

- 로그인 없이 볼 수 있다. 서버가 송출할 수 없는 시청 전용 접속 권한을 준다.
- 시청 권한은 준비 상태와 방송 중인 방송에만 준다. 종료된 방송은 저장된 기록만 보여준다.
- 준비 상태에서는 "곧 방송이 시작돼요"를 보여주고, 방송이 시작되면 새로고침 없이 영상이 나온다.
- 영상은 소리를 끈 채 자동 재생한다. 화면 가운데의 "눌러서 소리 켜기"를 누르면 소리가 나온다. 아이폰이 소리 있는 자동 재생을 막기 때문이다.
- 방송 중이면 지금 보는 사람 수를 보여준다. 서버가 LiveKit 알림을 받을 때마다 시청자 수를 다시 센다.
- 방송자가 방송 금지 제재를 받았으면 그 방송자의 방송 주소에 안내를 보여준다.
- API: `GET /api/broadcasts/[id]`, `POST /api/broadcasts/[id]/viewer-token`, `GET /api/broadcasts/[id]/access`, `GET /api/broadcasts/[id]/replay`
- 원문: [07 4-6](07-feature-spec.md#4-6-방송-보기)

### 4-7. 채팅

- 공모 요강의 "댓글"은 나비에서 방송 옆의 실시간 채팅이다.
- 읽기는 누구나 한다. 쓰기는 로그인한 사용자만 하고, 1~200자다.
- 내 채팅만 고치거나 지울 수 있다. 서버가 작성자 본인인지 확인한다. 규칙은 06 결정 32에 있다.
- 준비 상태와 방송 중에만 쓸 수 있다. 종료된 방송과 다시보기에서는 읽기만 한다.
- 한 사람은 같은 방송에 1초에 1개까지 보낼 수 있다.
- 서버가 금칙어를 확인한다. 걸린 채팅은 "숨김" 상태로 저장하고, 원래 내용은 브라우저에 보내지 않는다.
- 서버가 저장한 뒤 LiveKit으로 방에 보낸다. 브라우저는 LiveKit으로 직접 보낼 수 없다.
- API: `POST /api/broadcasts/[id]/chat`, `GET /api/broadcasts/[id]/authors/[userId]/example`
- 원문: [07 4-7](07-feature-spec.md#4-7-채팅)

### 4-8. 후원

- 후원은 꿀로 한다. 꿀은 나비 안에서 쓰는 후원용 포인트이고, 꿀 1개는 1원이다. 결제 금액은 꿀 수에 부가가치세 10%를 더한 값이다.
- 채팅 후원과 미션 후원 두 가지가 있다. 한 번에 1,000~1,000,000꿀이고, 익명으로 보낼 수 있다. 내 방송에는 후원할 수 없다.
- 미션 후원은 상금을 묶어 두고, 방송자가 수락, 거절, 성공, 실패를 고른다. 성공하면 상금 전부, 실패하면 상금의 20%인 응원금만 방송자에게 간다.
- 결제는 토스페이먼츠 테스트 모드다. 잔액이 모자라면 "충전하고 후원하기"로 충전과 후원을 한 번에 한다.
- 서버는 결제 금액이 주문 금액과 같은지 확인하고, 승인 결과가 "완료"일 때만 꿀을 넣는다. 같은 결제가 두 번 알려 와도 꿀은 한 번만 들어간다.
- 충전 후 7일 안에 하나도 쓰지 않은 충전은 직접 취소할 수 있다. 그 밖의 쓰지 않은 꿀은 환급을 신청한다. 충전, 취소, 환급의 돈 규칙은 [11 수익 구조(BM)](11-business-model.md)과 [12 운영 정책](12-policy.md)에 있다.
- API: `POST /api/broadcasts/[id]/donations`, `GET /api/broadcasts/[id]/missions`, `POST /api/broadcasts/[id]/missions`, `POST /api/broadcasts/[id]/missions/[missionId]/[action]`(action은 accept, reject, success, fail, expire), `GET /api/honey`, `POST /api/honey/verify`, `POST /api/charges`, `POST /api/charges/confirm`, `POST /api/charges/fail`, `POST /api/charges/[id]/cancel`, `POST /api/refunds`, `POST /api/webhooks/toss`
- 원문: [07 4-8](07-feature-spec.md#4-8-후원)

### 4-9. 녹화와 다시보기

- 송출 화면에서 녹화를 켰을 때만 녹화한다. 녹화 파일은 MP4로 Cloudflare R2(파일 저장소)에 저장한다.
- 녹화는 한 번에 3분까지다. 녹화를 시작할 때 3분을 미리 더해서, 이번 달 녹화 사용량이 50분을 넘게 되면 새 녹화를 시작하지 않는다. 녹화가 실패해도 방송은 계속된다.
- 녹화 상태는 녹화 중, 처리 중, 볼 수 있음, 실패 네 가지다.
- 녹화는 처음에 비공개다. 방송자가 내 방송 관리에서 "공개"로 바꿔야 다시보기 목록에 나온다.
- 재생할 때 서버가 공개 여부와 소유자를 확인하고 30분 동안 쓸 수 있는 주소를 준다.
- 다시보기에서는 채팅을 쓸 수 없고 후원할 수 없다.
- API: `GET /api/recordings`, `GET /api/recordings/[id]`, `PATCH /api/recordings/[id]`, `DELETE /api/recordings/[id]`, `GET /api/recordings/studio`, `GET /api/broadcasts/[id]/replay`, `POST /api/broadcasts/[id]/recording/stop`, `POST /api/webhooks/livekit`
- 원문: [07 4-9](07-feature-spec.md#4-9-녹화와-다시보기)

### 4-10. 내 방송 관리

- 위쪽에 준비 상태와 방송 중인 방송을 카드로 따로 보여준다. 아래 목록에는 종료된 방송만 최근에 끝난 순서로 보여준다.
- 제목은 방송 중에는 송출 화면에서, 끝난 뒤에는 목록에서 바꾼다.
- 삭제는 종료된 방송과 준비 상태 방송만 할 수 있다. 방송 중이거나 녹화가 처리 중이면 지울 수 없다.
- 방송을 지워도 후원 기록은 지우지 않는다. 지운 방송의 후원은 목록 아래 "지운 방송" 묶음에 남는다.
- 방송별 후원 내역에 그 후원에 적용한 배분 비율과 예상 수익을 함께 보여준다.
- API: `GET /api/me/broadcasts`, `GET /api/broadcasts/[id]`, `PATCH /api/broadcasts/[id]`, `DELETE /api/broadcasts/[id]`, `GET /api/recordings/studio`, `GET /api/me/settlements`
- 원문: [07 4-10](07-feature-spec.md#4-10-내-방송-관리)

### 4-11. 내 정보

- 닉네임은 가입한 뒤 한 번만 바꿀 수 있다. 서버도 두 번째 변경을 거절한다.
- 내 꿀 화면에 잔액, 미션에 묶인 꿀, 환급 대기 중인 꿀, 충전 내역, 사용 내역, 환급 신청 내역을 보여준다.
- 내 후원 내역은 방송이 지워져도 남는다.
- 회원 탈퇴는 비밀번호를 다시 확인한 뒤 한다. 제재 중이거나, 방송 중이거나, 처리 중인 미션, 충전, 환급이 있으면 탈퇴할 수 없다.
- 탈퇴해도 후원 기록은 남고, 이름만 "탈퇴한 사용자"로 바꾼다. 테스트 계정은 탈퇴와 닉네임 변경을 할 수 없다.
- API: `GET /api/me/profile`, `PATCH /api/me/nickname`, `GET /api/me/donations`, `GET /api/me/withdraw`, `POST /api/me/withdraw`, `GET /api/honey`
- 원문: [07 4-11](07-feature-spec.md#4-11-내-정보)

### 4-12. 방송자 등급과 정산

- 등급은 알, 애벌레, 번데기, 나비 네 단계다. 배분 비율(방송자 몫)은 80%, 82%, 85%, 88%다.
- 방송 횟수, 누적 방송 시간, 받은 후원 건수 세 조건을 모두 채우면 자동으로 다음 등급이 된다. 이번 개발에서는 등급이 내려가지 않는다.
- 후원을 확정하는 순간의 등급과 배분 비율을 후원 기록에 저장한다. 그래서 나중에 등급이 올라도 지난 후원의 예상 수익은 바뀌지 않는다.
- 정산은 월 1회 자동이다. 방송자는 조회만 하고 신청 버튼은 없다.
- 정산 계산과 확정은 실제로 만들었다. 송금과 예약 작업은 목업이다. 운영자 화면의 "월 정산 지금 실행(테스트)" 버튼으로 같은 작업을 실행한다.
- 등급과 정산의 돈 규칙은 [11 수익 구조(BM)](11-business-model.md)에 있다.
- API: `GET /api/me/grade`, `GET /api/me/settlements`, `GET /api/jobs/monthly-settlement`(예약 작업 실행기가 비밀 값으로 부르는 입구), `POST /api/admin/settlements/run-test`
- 원문: [07 4-12](07-feature-spec.md#4-12-방송자-등급과-정산)

### 4-13. 신고

- 채팅 메시지, 방송, 사용자를 신고할 수 있다. 로그인해야 하고, 나 자신은 신고할 수 없다.
- 사유는 욕설·비하, 성적인 내용, 도배·광고, 사칭, 불법·위험한 행동, 기타 가운데 하나를 고른다.
- 같은 대상을 두 번 신고할 수 없다. 한 사람은 하루 20건까지 신고할 수 있다.
- 신고를 받아도 자동으로 조치하지 않는다. 운영자가 확인한 뒤 조치한다.
- 신고 상태는 접수, 조치함, 기각 세 가지다. 신고한 사람은 내 신고 내역에서 상태를 본다.
- API: `POST /api/reports`, `GET /api/me/reports`
- 원문: [07 4-13](07-feature-spec.md#4-13-신고)

### 4-14. 방송자 활동 제한

- 방송자는 송출 화면의 채팅에서 닉네임을 눌러 "이 방송에서 채팅 금지"를 건다. 기간은 1일, 7일, 영구 중에서 고른다.
- 제한된 사람은 그 방송자의 모든 방송에서 채팅과 후원 메시지를 쓸 수 없다. 시청, 후원, 신고는 할 수 있다.
- 운영자 제재와 별개이고, 그 방송자의 방송에서만 효력이 있다.
- 내 방송 관리의 "활동 제한" 탭에서 목록을 보고 바로 풀 수 있다.
- 익명 후원자, 방송자 자신, 운영자에게는 걸 수 없다.
- API: `POST /api/me/chat-bans`, `GET /api/me/chat-bans`, `DELETE /api/me/chat-bans/[userId]`
- 원문: [07 4-14](07-feature-spec.md#4-14-방송자-활동-제한)

### 4-15. 운영자 화면과 제재

- 운영자 화면은 `/admin` 아래에 있고 PC만 지원한다. 서버는 모든 운영자 요청에서 운영자 표시를 확인하고, 없으면 403으로 거절한다.
- 제재는 경고, 채팅 금지(1일 또는 7일), 방송 금지(7일 또는 30일), 영구 정지 네 가지다. 조치할 때 사유는 필수다.
- 방송 금지나 영구 정지를 걸면 방송 중인 방송을 바로 끝낸다. 영구 정지는 그 방송자의 정산도 보류한다.
- 제재받은 사람은 위쪽 안내 띠와 제재 내역(`/me/sanctions`)에서 내용을 본다. 경고, 채팅 금지, 방송 금지에 한 번씩 이의를 제기할 수 있다.
- 테스트 운영자는 시드 계정과 그 기록에만 조치할 수 있다. 실제로 가입한 사용자는 조회도 할 수 없다.
- 운영자의 모든 조치는 운영 기록에 남는다. 운영 기록은 고치거나 지울 수 없다. 제재 기준은 [12 운영 정책](12-policy.md)에 있다.
- API: 5장 운영자 화면 기능 목록의 `/api/admin/*` 전부, `GET /api/me/sanctions`, `POST /api/me/sanctions/ack`, `POST /api/me/sanctions/[id]/appeal`
- 원문: [07 4-15](07-feature-spec.md#4-15-운영자-화면과-제재)

### 4-16. 공통 헤더와 사이드바

- 운영자 화면을 뺀 모든 화면 맨 위에 헤더를 둔다.
- 로그인 후 헤더 오른쪽에는 스튜디오, 꿀, 알림, 화면 전환, 내 프로필이 있다.
- 기본은 어두운 화면이다. 고른 값은 브라우저에 저장한다.
- 프로필 메뉴의 "운영자 화면" 항목은 운영자 계정에만 보인다. 항목이 보이지 않아도 서버는 `/admin` 요청마다 다시 확인한다.
- 사이드바에는 인기 카테고리와 지금 방송 중인 채널 5개를 보여준다.
- API: `GET /api/me`, `GET /api/me/notifications/unread`
- 원문: [07 4-16](07-feature-spec.md#4-16-공통-헤더와-사이드바)

### 4-17. 알림

- 후원 확정, 미션 결과, 정산 지급과 보류, 승급, 신고 처리, 이의 제기 처리, 환급 처리, 운영 조치를 알린다.
- 서버가 일을 확정하는 같은 트랜잭션(한 번에 함께 저장하는 묶음)에서 알림을 만든다. 그래서 일은 됐는데 알림이 없는 경우가 생기지 않는다.
- 실시간으로 바로 뜨지 않는다. 페이지를 열 때 읽지 않은 수를, 알림 패널을 열 때 최근 30개를 불러온다.
- 제재는 알림이 아니라 안내 띠로 알린다.
- 팔로우, 방송 시작 알림, 웹 푸시는 만들지 않았다.
- API: `GET /api/me/notifications`, `GET /api/me/notifications/unread`, `POST /api/me/notifications/[id]/read`, `POST /api/me/notifications/read-all`
- 원문: [07 4-17](07-feature-spec.md#4-17-알림)

### 4-18. 심사용 테스트 계정과 더미 데이터

- 시드 스크립트(처음 데이터를 넣는 스크립트)가 계정 17개와 방송, 채팅, 후원, 신고, 제재, 정산 기록을 미리 만든다. 그래서 심사자가 들어왔을 때 화면이 비어 있지 않다.
- 기록은 실제 기능을 거쳐 만든다. 결제와 송출 같은 바깥 서비스만 시드용으로 바꾼다.
- 홈에는 방송 중인 예시 방송 8개와 준비 중인 예시 방송 2개를 둔다. 시드가 만든 다시보기와 샘플 계정에는 "예시"를 붙인다.
- 테스트 방송자 계정의 방송은 30분까지다.
- 운영자 화면의 테스트 계정 메뉴에서 부분 초기화와 전체 초기화를 한다. 다음 심사자가 처음 상태로 확인할 수 있게 하기 위해서다.
- 계정 정보와 로그인 방법은 [README](../README.md)에 있다.
- API: `POST /api/auth/test-login`, `GET /api/admin/test-accounts`, `POST /api/admin/test-accounts/reset`, `POST /api/admin/test-accounts/reset-all`
- 원문: [07 4-18](07-feature-spec.md#4-18-심사용-테스트-계정과-더미-데이터)

## 5. 운영자 화면 기능 목록

운영자 메뉴, 화면 주소, API를 한 줄씩 맞춰 적었다. 화면 시안은 [08 O 묶음](08-screen-spec.md#o-운영자-화면)에 있다.

| 메뉴 | 화면 주소 | 하는 일 | API |
|---|---|---|---|
| 대시보드 | `/admin` | 오늘 방송 수, 방송 중인 방송 수, 후원 합계, 처리할 신고·이의 제기·환급 수, 이번 달 녹화 시간을 보여준다 | `GET /api/admin/dashboard` |
| 신고 처리 | `/admin/reports` | 신고를 대상 사용자별로 묶어 보여주고, 제재하기, 콘텐츠만 숨기기, 기각 가운데 하나로 처리한다 | `GET /api/admin/reports`, `GET /api/admin/reports/[userId]`, `POST /api/admin/reports/[userId]/resolve` |
| 제재 관리 | `/admin/sanctions` | 사용자에게 제재를 걸고 푼다 | `GET /api/admin/sanctions`, `POST /api/admin/users/[userId]/sanctions`, `POST /api/admin/sanctions/[id]/revoke` |
| 이의 제기 | `/admin/appeals` | 이의 제기를 받아들이거나 거절한다 | `GET /api/admin/appeals`, `POST /api/admin/appeals/[id]/resolve` |
| 방송 관리 | `/admin/broadcasts` | 방송 중인 방송을 강제 종료하고, 종료된 방송의 다시보기를 비공개로 바꾼다 | `GET /api/admin/broadcasts`, `POST /api/admin/broadcasts/[id]/end`, `POST /api/admin/broadcasts/[id]/private-replay` |
| 회원 관리 | `/admin/users` | 닉네임이나 이메일로 찾고, 등급, 꿀 잔액, 제재 이력, 받은 신고를 본다 | `GET /api/admin/users`, `GET /api/admin/users/[userId]` |
| 정산 관리 | `/admin/settlements` | 정산 기록을 보고, 방송자 단위로 정산을 보류하거나 풀고, 월 정산을 테스트로 실행한다 | `GET /api/admin/settlements`, `POST /api/admin/settlements/[userId]/hold`, `POST /api/admin/settlements/[userId]/release`, `POST /api/admin/settlements/run-test` |
| 환급 관리 | `/admin/refunds` | 환급 신청을 승인하거나 거절한다. 승인하면 송금 목업을 부른다 | `GET /api/admin/refunds`, `POST /api/admin/refunds/[id]/approve`, `POST /api/admin/refunds/[id]/reject` |
| 충전·결제 내역 | `/admin/charges` | 충전 목록과 상태, 웹훅 처리 결과를 본다. 취소 결과를 모르는 충전은 결제 조회로 정리한다 | `GET /api/admin/charges`, `POST /api/admin/charges/[id]/reconcile` |
| 예약 작업 기록 | `/admin/jobs` | 월 정산 작업의 실행 기록을 본다 | `GET /api/admin/jobs` |
| 금칙어 관리 | `/admin/banned-words` | 금칙어를 더하고 뺀다. 바꾸면 1분 안에 채팅 검사에 쓰인다 | `GET /api/admin/banned-words`, `POST /api/admin/banned-words/add`, `POST /api/admin/banned-words/remove` |
| 테스트 계정 | `/admin/test-accounts` | 테스트 계정을 부분 초기화하거나 전체 초기화한다 | `GET /api/admin/test-accounts`, `POST /api/admin/test-accounts/reset`, `POST /api/admin/test-accounts/reset-all` |
| 운영 기록 | `/admin/logs` | 운영자가 한 모든 일을 누가, 언제, 무엇을, 누구에게, 왜 했는지 보여준다 | `GET /api/admin/logs` |

## 7. 만들지 않은 것

자세한 이유는 [07 9장 이번에 만들지 않는 것](07-feature-spec.md#9-이번에-만들지-않는-것)에 있다.

- 모바일 앱은 만들지 않았다. 웹 서비스만 만든다.
- 광고, 채널 구독, 플랫폼 구독은 수익 구조 설명만 한다.
- 팔로우, 방송 시작 알림, 웹 푸시는 만들지 않았다. 나비 안의 알림은 만들었다.
- 종료된 방송은 다시 시작하지 않는다. 새 방송을 만든다.
- 실제 송금과 실제 예약 작업은 목업이다. 정산 송금과 환급 송금 모두 해당한다.
- 정산 정보 등록 화면은 없다. 시드 스크립트가 테스트 계좌를 넣는다.
- 실제 휴대폰 본인인증과 계좌 확인은 하지 않는다. 입력만 받는 목업이다.
- 등급 하락, 다시보기 보관 기간이 지난 녹화의 자동 삭제, 꿀 유효기간 만료, 정산 보류 기록의 5년 소멸은 화면에 안내만 한다.
- 채팅 읽어주기는 와이어프레임에만 그렸다.
- 클립, 편성표, 라운지, e스포츠는 나비가 풀려는 문제와 관계없어서 만들지 않았다.

## 8. API 문서 위치

- 화면으로 보는 API 문서는 `/api-docs` 페이지다. 소스는 `apps/web/app/api-docs/page.tsx`다.
- OpenAPI 명세 파일은 `apps/web/public/openapi.json`이다.
- API의 요청과 응답 모양은 `packages/shared/src`에 기능별 파일로 정의돼 있다. 예를 들어 후원과 꿀은 `honey.ts`, 채팅은 `chat.ts`, 운영자 기능은 `adminOps.ts`와 `moderation.ts`, 정산은 `settlement.ts`다.
- 실제 API 경로는 `apps/web/app/api` 아래의 `route.ts` 파일이다.
- 외부 서비스가 부르는 주소는 `POST /api/webhooks/livekit`과 `POST /api/webhooks/toss` 두 개다. 처리 규칙은 [07 7장 서버 알림 처리](07-feature-spec.md#7-서버-알림-처리-웹훅)에 있다.
- 로그인 토큰을 받아 curl로 확인하는 방법은 [README](../README.md)의 "확인용 명령"에 있다.
