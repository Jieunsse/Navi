# 나비 고객 여정 지도

- 작성일: 2026-11-05
- 기준 문서: [01-problem-definition.md](01-problem-definition.md), [02-competitor-analysis.md](02-competitor-analysis.md)
- 레퍼런스: 치지직 캡처 중 7장을 직접 확인했다. 스튜디오 방송하기, 스튜디오 리허설, 스튜디오 라이브 목록, 시청 화면 광고, 채널 오프라인, 팔로잉 비로그인, 모바일 후원 충전 화면이다.
- 범위: 웹 서비스만 다룬다. 광고, 채널 구독, 플랫폼 구독은 이번 개발 범위 밖이다. 이 문서에서는 수익이 어디서 생기는지 보여주려고 표시만 한다.

## 1. 한 줄 요약

세 사람 모두 가장 크게 막히는 곳은 첫 화면이 나오기 직전이다. 방송자는 브라우저 권한 창과 탭 오디오 체크에서 막힌다. 시청자는 광고, 꺼진 소리, 로그인 요구에서 막힌다. 나비는 외부 프로그램과 스트림 키를 없앴지만, 이 작은 단계에서 막히면 핵심 문제를 풀지 못한 것과 같다.

## 2. 읽는 법

### 사실과 추론 표시

- **(사실)**: 기준 문서나 레퍼런스 화면에서 확인한 내용이다. 어디서 확인했는지 괄호 안에 적었다.
- **(추론)**: 근거 없이 판단한 내용이다. 인터뷰나 테스트로 확인해야 한다.
- 표시가 없는 칸은 나비가 만들 화면이나 기능에 대한 설명이다.

### 감정 점수

| 점수 | 뜻 |
|---|---|
| +2 | 아주 만족한다. 다른 사람에게 말하고 싶다 |
| +1 | 기대하거나 편하다 |
| 0 | 특별한 감정이 없다 |
| -1 | 귀찮거나 헷갈린다 |
| -2 | 막혀서 그만두고 싶다 |

감정 점수는 모두 추론이다. 실제 사용자를 관찰한 기록은 아직 없다.

### 단계 구성

방송자 두 명은 아래 열 단계를 같이 쓴다. 1~5단계가 켜기까지의 단계다. 이 문서는 이 다섯 단계를 가장 자세히 쓴다.

1. 방송을 켜기로 마음먹는다
2. 가입하고 로그인한다
3. 방송 정보를 입력한다
4. 브라우저 권한을 허용한다
5. 송출을 시작한다
6. 시청자가 들어온다
7. 댓글과 후원을 받는다
8. 방송을 끝낸다
9. 다시보기와 후원 내역을 확인한다
10. 다시 켠다

시청자는 들어오는 길이 달라서 단계를 따로 나눴다. 3장의 여정 3에 적었다.

## 3. 세 사람의 여정

### 여정 1. 가볍게 한 번 보여주는 사람

- **상황:** 친구에게 게임 화면을 보여주거나 지금 있는 현장을 보여주고 싶다. 방송 장비가 없다. (사실, 문제정의 3장)
- **하려는 일:** 보여주고 싶은 순간에 링크를 보내고 바로 켠다. 끝나면 확실하게 끈다. (사실, 문제정의 3장)
- **기기:** PC에서는 맥북 크롬으로 탭을 공유한다. 휴대폰에서는 아이폰 크롬이나 사파리로 카메라를 켠다.
- **이 사람에게 가장 중요한 것:** 보여주고 싶은 순간이 지나기 전에 켜지는 것이다. 준비가 1~2분을 넘으면 그냥 메신저로 사진을 보낼 것이다. (추론)

| 단계 | 행동 | 접점(화면) | 감정 | 막히는 지점 | 기회 |
|---|---|---|---|---|---|
| 1. 마음먹기 | 친구와 대화하다가 "지금 이거 보여줄게"라고 생각한다 | 메신저, 나비 첫 화면 | +1 | 디스코드 화면 공유나 영상 통화가 이미 익숙하다. 나비를 써야 할 이유를 모른다. (추론) | 첫 화면에 "설치 없이 링크 하나로 바로 보여준다"를 한 줄로 쓴다 |
| 2. 가입·로그인 | 방송하기를 누르자 로그인 화면이 나온다 | 로그인 화면 | -1 | 한 번만 쓸 생각인데 가입을 요구받는다. 이메일 인증까지 있으면 여기서 그만둔다. (추론) 로그인은 공모 요구사항이라 없앨 수 없다. (사실, 문제정의 5장) | 소셜 로그인 한 번으로 끝낸다. 로그인 뒤에는 하던 단계로 바로 돌아온다 |
| 3. 방송 정보 입력 | 제목을 쓰고 화면 공유와 카메라 중 하나를 고른다 | 방송 만들기 화면 | 0 | 치지직은 제목, 카테고리, 태그, 미리보기 이미지를 한 화면에서 받는다. (사실, 레퍼런스 스튜디오 방송하기) 이 사람에게는 제목 하나도 귀찮다. (추론) | 제목에 기본값을 넣어 둔다. 필수 입력은 제목 하나만 둔다 |
| 4. 권한 허용 (PC) | 크롬의 공유 창에서 탭을 고르고 공유를 누른다 | 크롬 공유 선택 창 | -2 | 공유 창에 탭, 창, 전체 화면 세 갈래가 나와서 무엇을 골라야 할지 모른다. (추론) 전체 화면을 고르면 맥의 화면 기록 권한이 따로 필요하고, 켠 뒤 크롬을 다시 시작해야 한다. (사실, 문제정의 9장) 탭 오디오 공유 체크를 놓치면 소리 없는 방송이 나간다. (사실, 문제정의 5장) | 공유 창이 뜨기 전에 "탭을 고르고, 탭 오디오 공유를 켜 두세요"라고 그림으로 먼저 보여준다 |
| 4. 권한 허용 (휴대폰) | 카메라와 마이크 허용 창에서 허용을 누른다 | 사파리 권한 창 | -1 | 아이폰은 HTTPS 주소에서만 카메라가 켜진다. (사실, 문제정의 9장) 한 번 거부하면 아이폰 설정 앱에 가서 다시 켜야 한다. (추론) | 권한 창 전에 "다음 창에서 허용을 눌러 주세요"를 먼저 띄운다. 거부했을 때 다시 켜는 방법을 화면에 바로 보여준다 |
| 5. 송출 | 내 화면이 미리보기에 뜨는 것을 보고 방송 시작을 누른다 | 송출 화면 | +1 | 소리가 실제로 나가는지 확인할 방법이 없다. (추론) 휴대폰은 화면이 잠기거나 메신저로 넘어가면 카메라가 끊긴다. (사실, 문제정의 9장) | 소리 막대로 탭 소리와 마이크 소리가 들어오는지 보여준다. 휴대폰에서는 "화면을 켜 둔 채로 두세요"를 안내한다 |
| 6. 시청자 유입 | 방송 링크를 복사해서 친구에게 보낸다 | 송출 화면의 링크 복사 버튼, 메신저 | +1 | 링크를 보내려고 메신저로 넘어가면 휴대폰 카메라가 끊긴다. (사실과 추론. 끊김은 문제정의 9장, 이 순서로 막힌다는 판단은 추론) | 방송을 켜기 전에 링크를 먼저 만들어 복사하게 한다 |
| 7. 댓글·후원 | 친구가 단 댓글을 보고 말로 대답한다 | 송출 화면의 댓글 영역 | +2 | 탭을 공유하는 동안 송출 화면을 보고 있지 않아서 댓글을 놓친다. (추론) | 새 댓글이 오면 크롬 탭 제목에 숫자를 띄운다 |
| 8. 종료 | 방송 종료를 누르거나 크롬의 공유 중지를 누른다 | 송출 화면, 크롬 공유 중지 막대 | 0 | 크롬 막대에서 공유만 멈추면 목록에는 아직 방송 중으로 남을 수 있다. (사실, 문제정의 6장) 치지직 리허설도 송출이 끊겨도 자동으로 끝나지 않는다고 안내한다. (사실, 레퍼런스 스튜디오 리허설) | 공유가 멈추면 방송도 바로 끝낸다. 끝났다는 화면을 확실하게 보여준다 |
| 9. 다시보기·후원 확인 | 대부분 확인하지 않고 떠난다 | 방송 종료 화면 | 0 | 다시보기가 남는다는 사실을 모른다. (추론) | 종료 화면에 "다시보기 링크가 만들어졌어요"와 받은 댓글 수를 보여준다 |
| 10. 다시 켜기 | 다음에 보여줄 일이 생기면 다시 온다 | 첫 화면 | +1 | 처음과 같은 권한 설명을 또 보면 귀찮다. (추론) | 두 번째부터는 설명을 접고 지난번 설정으로 바로 켜게 한다 |

### 여정 2. 입문 스트리머

- **상황:** 방송을 꾸준히 해 보고 싶다. 장비 세팅이 부담된다. (사실, 문제정의 3장)
- **하려는 일:** 설치 없이 시작한다. 방송이 끝나면 기록과 반응과 수익이 남는다. (사실, 문제정의 3장)
- **기기:** 맥북 크롬으로 화면이나 탭을 공유하고 마이크로 말한다.
- **이 사람에게 가장 중요한 것:** 첫 방송이 사고 없이 나가는 것이다. 그리고 끝난 뒤에 무엇인가 남는 것이다. 소리가 안 나갔거나 방송이 안 꺼졌다면 다시 켜지 않을 것이다. (추론)

| 단계 | 행동 | 접점(화면) | 감정 | 막히는 지점 | 기회 |
|---|---|---|---|---|---|
| 1. 마음먹기 | 치지직에서 방송을 켜 보려다가 OBS 가이드를 보고 멈춘다. 설치 없는 방법을 찾는다 | 치지직 스튜디오, 검색 결과, 나비 첫 화면 | -1 | 치지직은 사이트 안에서 방송을 켤 수 없다. 스트림 주소와 키를 송출 프로그램에 붙여 넣어야 한다. (사실, 레퍼런스 스튜디오 방송하기, 문제정의 2장) 유튜브와 틱톡은 휴대폰 방송에 구독자나 팔로워 조건이 있다. (사실, 경쟁분석 4장) | 첫 화면에 "프로그램 설치 없음, 구독자 조건 없음"을 쓴다 |
| 2. 가입·로그인 | 가입하고 채널 이름을 정한다 | 가입 화면 | 0 | 꾸준히 할 생각이라 가입 자체는 받아들인다. (추론) 채널 이름을 정하라고 하면 고민이 길어진다. (추론) | 채널 이름은 나중에 바꿀 수 있다고 알려 주고 기본값을 넣는다 |
| 3. 방송 정보 입력 | 제목을 쓰고 화면 공유를 고른다 | 방송 만들기 화면 | 0 | 무엇을 꼭 채워야 하는지 모른다. 치지직은 입력 칸이 많다. (사실, 레퍼런스 스튜디오 방송하기) | 제목만 필수로 둔다. 나머지는 방송 중에도 바꿀 수 있게 한다 |
| 4. 권한 허용 | 화면 공유 창에서 공유 대상을 고르고, 마이크 허용 창에서 허용을 누른다 | 크롬 공유 선택 창, 크롬 마이크 권한 창, 맥 시스템 설정 | -2 | 게임 창 전체를 보여주려고 전체 화면을 고르면 맥 화면 기록 권한이 필요하다. 권한을 켜면 크롬을 다시 시작해야 해서 지금까지 한 입력이 사라질 수 있다. (사실, 문제정의 9장. 입력이 사라지는 것은 추론) 맥에서 시스템 소리 전체를 보낼 수 있는지는 확인하지 못했다. (사실, 문제정의 10장) 권한 창이 두 번 연달아 떠서 어느 것이 무엇인지 헷갈린다. (추론) | 탭 공유를 기본 추천으로 둔다. 전체 화면을 고르면 "크롬을 다시 켜야 할 수 있다"를 미리 알린다. 입력한 방송 정보는 저장해 두고 다시 열었을 때 채워 둔다 |
| 5. 송출 | 미리보기에서 화면과 소리를 확인하고 방송 시작을 누른다 | 송출 화면 | +1 | 시청자에게 어떻게 보이는지 모른다. 치지직은 시청자에게 보이지 않는 리허설 방송을 따로 제공한다. (사실, 레퍼런스 스튜디오 리허설) 화질이나 끊김을 조절할 방법이 송출 프로그램보다 적다. (사실과 추론. 경쟁분석 7장) | 시작 전 미리보기를 시청자 화면과 같게 보여준다. 탭 소리와 마이크 소리 막대를 따로 보여준다 |
| 6. 시청자 유입 | 링크를 SNS에 올리고 방송 목록에 뜨기를 기다린다 | 방송 목록, SNS | -1 | 시청자가 0명이다. 치지직 홈은 시청자가 많은 방송을 위에 크게 보여주므로 작은 방송은 보이지 않는다. (사실, 문제정의 6장) 나비는 아직 시청자 자체가 적다. (사실, 경쟁분석 7장) | 목록에 "방금 켠 방송"을 따로 보여준다. 이번 개발 범위에서는 위험으로만 기록한다 |

| 8. 종료 | 마무리 인사를 하고 방송 종료를 누른다 | 송출 화면 | 0 | 종료를 눌렀는데 송출이 계속되거나, 송출이 끊겼는데 방송 중으로 남으면 믿고 쓸 수 없다. (사실, 문제정의 6장) | 종료와 송출 중단을 하나로 묶는다. 종료 직후 "방송이 끝났습니다. 시청자에게도 끝났다고 보입니다"를 보여준다 |
| 9. 다시보기·후원 확인 | 다시보기를 열어 보고 오늘 받은 후원을 확인한다 | 내 방송 목록, 다시보기 화면, 후원 내역 화면 | +1 | 다시보기가 언제 만들어지는지 모르면 빈 목록을 보고 실망한다. 치지직 라이브 목록은 비어 있을 때 "동영상이 없습니다"만 보여준다. (사실, 레퍼런스 스튜디오 라이브 목록) | 종료 화면에서 다시보기와 후원 내역으로 바로 가게 한다. 처리 중이면 처리 중이라고 보여준다 |
| 10. 다시 켜기 | 다음 방송 시간을 정하고 다시 켠다 | 첫 화면, 내 채널 | +1 | 다시 켤 이유가 약하면 그만둔다. 반응과 수익이 남지 않으면 다시 켤 이유가 없다. (사실, 문제정의 6장) 방송이 익숙해지면 화질 때문에 송출 프로그램으로 옮길 수 있다. (추론, 경쟁분석 7장) | 지난 방송의 댓글 수, 후원 금액, 다시보기 조회 수를 다음 방송 화면에 보여준다 |

### 여정 3. 시청자

- **상황:** 친구가 보낸 링크나 방송 목록으로 들어온다. (사실, 문제정의 3장)
- **하려는 일:** 가입 없이 바로 본다. 댓글이나 후원을 할 때만 로그인한다. (사실, 문제정의 3장)
- **기기:** 메신저에서 링크를 누르면 대부분 휴대폰 브라우저로 열린다. (추론) 아이폰에서는 크롬도 사파리와 같은 엔진을 쓴다. (사실, 문제정의 9장)
- **이 사람에게 가장 중요한 것:** 링크를 누르자마자 화면과 소리가 나오는 것이다.

시청자의 단계는 아래처럼 나눴다.

| 단계 | 행동 | 접점(화면) | 감정 | 막히는 지점 | 기회 |
|---|---|---|---|---|---|
| 1. 링크·목록 발견 | 친구가 보낸 링크를 누르거나 방송 목록에서 하나를 고른다 | 메신저, 나비 방송 목록 | +1 | 메신저 안의 브라우저로 열리면 화면이 어색할 수 있다. (추론) | 링크 미리보기에 방송 제목과 "지금 방송 중"을 보여준다 |
| 2. 입장·재생 | 방송 화면이 열리고 재생되기를 기다린다 | 시청 화면 | -1 | 아이폰에서 영상이 자동으로 재생되려면 처음에는 소리가 꺼져 있어야 한다. (사실, 문제정의 9장) 소리가 안 나와서 방송이 고장 났다고 생각한다. (추론) 치지직은 들어오자마자 광고가 나오고 몇 초 뒤에야 건너뛸 수 있다. (사실, 레퍼런스 시청 화면 광고) | 소리가 꺼져 있으면 화면 가운데에 "눌러서 소리 켜기"를 크게 보여준다. 광고는 이번 개발 범위 밖이다 |
| 3. 시청 | 화면을 보고 다른 사람의 댓글을 읽는다 | 시청 화면, 댓글 영역 | +1 | 방송자 화면이 멈추면 시청자 문제인지 방송자 문제인지 모른다. (추론) | 송출이 끊기면 "방송자 연결이 잠시 끊겼어요"를 보여준다 |
| 4. 로그인 | 댓글을 쓰려고 입력 칸을 누르자 로그인을 요구받는다 | 로그인 화면 | -1 | 치지직은 팔로잉 목록을 보는 것도 로그인을 요구한다. (사실, 레퍼런스 팔로잉 비로그인) 로그인하고 돌아오면 방송 화면이 처음부터 다시 열리거나 쓰던 댓글이 사라진다. (추론) | 로그인 창을 방송 화면 위에 띄운다. 로그인 뒤에는 같은 방송, 쓰던 댓글로 돌아온다 |
| 5. 댓글 | 댓글을 쓰고 방송자가 읽어 주기를 기다린다 | 댓글 영역 | +2 | 방송자가 댓글을 늦게 보면 무시당한 느낌이 든다. (추론) | 방송자 화면의 댓글 알림을 잘 보이게 해서 대답이 빨리 오게 한다 |
| 6. 후원 | 후원 버튼을 누르고 금액을 고른 뒤 결제한다 | 후원 창, 테스트 결제 창 | 0 | 치지직은 치즈를 먼저 충전한 뒤에 후원하는 두 단계 방식이다. (사실, 레퍼런스 모바일 후원 충전) 이번에는 테스트 결제라서 실제로 돈이 나가는지 헷갈릴 수 있다. (추론) | (06 결정 8에서 바뀜: 꿀을 충전해서 후원한다. 잔액이 모자라면 "충전하고 후원하기" 한 번으로 끝난다) 꿀이 모자라면 "충전하고 후원하기"로 충전과 후원을 한 번에 한다. 결제 창에 "테스트 결제라 실제 돈이 나가지 않는다"를 적는다. 이 단계에서 나비의 후원 수수료가 생긴다 |
| 7. 방송 종료 | 방송자가 방송을 끝낸다 | 시청 화면 | 0 | 치지직은 끝난 채널에 "채널이 오프라인 상태입니다"와 다른 방송 보러가기 버튼만 보여준다. (사실, 레퍼런스 채널 오프라인) 방금 본 방송을 다시 볼 수 있는지 모른다. (추론) | 종료 화면에 "다시보기가 곧 올라와요"와 방송자 채널 링크를 보여준다 |
| 8. 다시보기 | 놓친 부분이나 재미있던 부분을 다시 본다 | 다시보기 화면 | +1 | 다시보기 주소를 따로 찾아야 하면 보지 않는다. (추론) | 같은 방송 링크가 종료 뒤에는 다시보기로 열리게 한다 |
| 9. 다시 찾아옴 | 방송자의 다음 방송을 보러 다시 온다 | 방송자 채널, 방송 목록 | +1 | 다시 오는 이유는 팔로우한 방송자가 방송을 켜면 알려 주는 방향으로 정했다. 이 기능은 이번 개발 범위에 넣지 않았다. (사실, 06 결정 4) 그래서 지금은 다음 방송을 알 방법이 없다. (추론) | 채널 구독과 플랫폼 구독은 이 단계의 수익이다. 둘 다 이번 개발 범위 밖이다 |

## 4. 켜기까지 막히는 지점 자세히

방송자 여정의 2~5단계에서 막히는 지점을 기기별로 다시 정리했다. 심사자는 맥북 크롬과 아이폰 크롬을 쓸 가능성이 높다. (사실, 문제정의 9장)

### 4-1. 맥북 크롬 (PC 방송)

| 순서 | 사용자가 보는 것 | 막히는 지점 | 근거 |
|---|---|---|---|
| 1 | 방송하기 버튼을 누르면 로그인 화면이 나온다 | 한 번만 쓰려는 사람은 가입에서 그만둔다 | 추론 |
| 2 | 제목 입력 칸이 나온다 | 무엇을 써야 할지 몰라 멈춘다 | 추론 |
| 3 | 크롬 공유 선택 창이 뜬다 | 탭, 창, 전체 화면 중 무엇을 고를지 모른다 | 추론 |
| 4 | 탭을 고르면 아래에 탭 오디오 공유 체크가 보인다 | 체크를 놓치면 소리 없는 방송이 나간다 | 체크가 생긴다는 것은 사실(문제정의 5장). 놓친다는 것은 추론 |
| 5 | 창이나 전체 화면을 고르면 맥 화면 기록 권한 요청이 뜬다 | 시스템 설정에서 권한을 켜고 크롬을 다시 시작해야 한다. 다시 시작하면 하던 단계가 사라진다 | 권한과 재시작은 사실(문제정의 9장). 단계가 사라지는 것은 추론 |
| 6 | 마이크 권한 창이 뜬다 | 공유 창 바로 뒤에 또 창이 떠서 헷갈린다. 실수로 차단을 누르면 주소창 옆 아이콘에서 다시 켜야 한다 | 추론 |
| 7 | 미리보기가 나온다 | 소리가 실제로 들어오는지 알 수 없다 | 추론 |
| 8 | 크롬 화면 아래에 공유 중이라는 막대가 계속 보인다 | 막대의 공유 중지를 누르면 방송 상태가 어떻게 되는지 모른다 | 추론. 방송 상태 문제는 문제정의 6장 |

### 4-2. 아이폰 크롬 또는 사파리 (휴대폰 카메라 방송)

| 순서 | 사용자가 보는 것 | 막히는 지점 | 근거 |
|---|---|---|---|
| 1 | 로그인 화면이 나온다 | 휴대폰에서 비밀번호를 치기 귀찮다 | 추론 |
| 2 | 카메라와 마이크 허용 창이 뜬다 | HTTPS 주소가 아니면 창이 뜨지 않고 카메라가 켜지지 않는다 | 사실(문제정의 9장) |
| 3 | 허용 창에서 실수로 거부한다 | 페이지 안에서 다시 켤 수 없고 설정으로 가야 한다 | 추론 |
| 4 | 미리보기가 나온다 | 전면과 후면 카메라 중 원하는 쪽이 아닐 수 있다 | 추론 |
| 5 | 방송을 시작하고 링크를 보내려고 메신저로 넘어간다 | 다른 앱으로 넘어가면 카메라가 끊긴다 | 사실(문제정의 9장) |
| 6 | 방송 중에 화면이 자동으로 잠긴다 | 화면이 잠기면 카메라가 끊긴다 | 사실(문제정의 9장) |
| 7 | 휴대폰에서 화면 공유를 하려고 한다 | 아이폰 브라우저에서는 화면 공유 방송을 할 수 없을 가능성이 높다 | 추론. 5장 가정 표에서 확인한다 |

## 6. 켜기까지 막히는 지점 상위 5개

방송을 포기하게 만드는 정도와 심사 환경에서 바로 보이는지를 기준으로 골랐다. 순위는 추론이다.

| 순위 | 막히는 지점 | 누가 막히는가 | 왜 큰 문제인가 | 줄이는 방법 |
|---|---|---|---|---|
| 1 | 탭 오디오 공유 체크를 놓쳐 소리 없는 방송이 나간다 | PC 방송자 | 방송은 켜졌는데 실패한 방송이 된다. 방송자는 시청자가 말해 주기 전까지 모른다 | 공유 창이 뜨기 전에 체크 위치를 그림으로 보여준다. 미리보기에 탭 소리 막대를 따로 두고, 소리가 없으면 "탭 소리가 들어오지 않아요. 다시 공유해 주세요"를 띄운다 |
| 2 | 크롬 공유 창에서 탭, 창, 전체 화면 중 무엇을 고를지 모른다 | PC 방송자 | 창이나 전체 화면을 고르면 맥 화면 기록 권한과 크롬 재시작으로 이어진다. 탭을 고를 때보다 단계가 많이 늘어난다 | 탭 공유를 기본 추천으로 안내한다. 다른 것을 고르는 사람에게만 재시작 가능성을 미리 알린다. 입력한 방송 정보는 저장해 둔다 |
| 3 | 휴대폰에서 다른 앱으로 넘어가거나 화면이 잠기면 카메라가 끊긴다 | 휴대폰 방송자 | 링크를 보내러 메신저에 가는 것은 자연스러운 행동이다. 그 행동 때문에 방송이 끊긴다 | 방송을 켜기 전에 링크를 먼저 복사하게 한다. 방송 중에는 화면을 켜 두라고 안내한다. 카메라가 끊겼다가 돌아오면 다시 켜기 버튼을 크게 보여준다 |
| 4 | 한 번만 쓰려는 사람에게 가입과 로그인을 요구한다 | 가볍게 보여주는 사람 | 공모 요구사항이라 없앨 수 없다. 그래서 단계 수를 줄이는 것만 할 수 있다 | 소셜 로그인 한 번으로 끝낸다. 로그인 뒤에는 방송 만들기 화면으로 바로 돌아온다 |
| 5 | 권한 창을 거부하거나 차단해서 다시 켜는 방법을 모른다 | 두 방송자 | 브라우저 권한은 페이지에서 다시 물을 수 없는 경우가 많다. 그래서 한 번 거부하면 사용자가 나비 화면 안에서는 방송을 켤 수 없다 | 권한 창 전에 무엇을 누를지 먼저 알린다. 거부했을 때는 맥 크롬과 아이폰 각각의 다시 켜는 방법을 화면에 바로 보여준다 |

## 7. 개선 우선순위

### 바로 할 수 있는 것

화면 문구와 안내만 바꾸면 되는 것들이다.

- 공유 창이 뜨기 전에 "탭을 고르고 탭 오디오 공유를 켜 두세요" 안내를 띄운다.
- 권한 창 전에 "다음 창에서 허용을 눌러 주세요" 안내를 띄운다.
- 방송 제목에 기본값을 넣는다.
- 아이폰 시청 화면에 "눌러서 소리 켜기" 버튼을 크게 둔다.
- 후원 결제 창에 테스트 결제라고 적는다.
- 방송 종료 화면에 다시보기와 후원 내역으로 가는 버튼을 둔다.

### 개발이 더 필요하지만 효과가 큰 것

- **송출과 방송 상태를 하나로 묶는다.** 크롬의 공유 중지, 휴대폰 화면 잠금, 종료 버튼 중 무엇으로 끝나도 방송이 끝난 상태가 되게 한다. 문제정의 6장에서 핵심 문제와 함께 지킬 조건으로 정했다.
- **소리 확인 막대를 만든다.** 탭 소리와 마이크 소리를 따로 보여주고, 소리가 없으면 경고한다. 상위 1번 막히는 지점을 직접 줄인다.
- **로그인 뒤 하던 곳으로 돌아오게 한다.** 방송자는 방송 만들기 화면으로, 시청자는 같은 방송과 쓰던 댓글로 돌아온다.
- **입력한 방송 정보를 저장한다.** 크롬을 다시 시작해도 다시 쓰지 않아도 되게 한다.

## 8. 수익이 생기는 단계

| 수익 | 생기는 단계 | 이번 개발 범위 |
|---|---|---|
| 후원 수수료 | 시청자 여정 6단계(후원), 방송자 여정 7단계(댓글·후원) | 포함한다. 테스트 결제로 만든다 |
| 광고 | 시청자 여정 2단계(입장·재생) | 범위 밖이다. 광고가 너무 잦으면 시청자가 바로 볼 수 없다 (사실, 문제정의 7장) |
| 채널 구독 | 시청자 여정 9단계(다시 찾아옴) | 범위 밖이다 |

## 9. 확인되지 않은 가정

| 가정 | 왜 중요한가 | 확인 방법 |
|---|---|---|
| 가볍게 보여주는 사람은 준비가 1~2분을 넘으면 포기한다 | 켜기 단계를 얼마나 줄여야 하는지 정하는 기준이다 | 실제 사용자 3~5명에게 처음부터 방송을 켜게 하고 걸린 시간과 포기 지점을 기록한다 |
| 사용자는 크롬 공유 창에서 탭 오디오 공유 체크를 자주 놓친다 | 상위 1번 막히는 지점의 근거다 | 안내 없이 탭 공유를 시켜 보고 소리가 나간 비율을 센다 |
| 맥 크롬의 탭 오디오 공유 체크가 기본으로 켜져 있는지 모른다 | 기본으로 켜져 있으면 1번 막히는 지점이 작아진다 | 심사 환경과 같은 맥북 크롬 최신 버전에서 직접 확인한다 |
| 맥 크롬의 탭 공유는 화면 기록 권한 없이 동작한다 | 탭 공유를 기본 추천으로 두는 근거다 | 실제 맥북에서 테스트한다 (문제정의 10장과 같다) |
| 아이폰 브라우저에서는 화면 공유 방송을 할 수 없다 | 휴대폰 방송을 카메라만으로 정한 근거다 | 아이폰 사파리와 크롬 최신 버전에서 화면 공유를 시도해 본다 |
| 아이폰에서 카메라 권한을 한 번 거부하면 설정 앱에 가야 다시 켤 수 있다 | 5번 막히는 지점의 안내 문구가 달라진다 | 아이폰 사파리와 크롬에서 거부한 뒤 다시 켜 본다 |
| 크롬을 다시 시작하면 입력한 방송 정보가 사라진다 | 방송 정보를 저장하는 기능이 필요한지 정한다 | 방송 만들기 화면을 구현한 뒤 크롬을 다시 시작해 본다 |
| 방송자는 탭을 공유하는 동안 나비 화면을 보지 않아서 댓글과 후원을 놓친다 | 탭 제목 알림 같은 기능이 필요한지 정한다 | 실제 방송 중인 사용자를 관찰한다 |
| 메신저에서 연 링크는 대부분 휴대폰 브라우저로 열린다 | 시청 화면을 휴대폰 기준으로 먼저 만들지 정한다 | 링크 클릭 기록에서 기기 종류를 센다 |
| 가볍게 켠 사람이 반응과 후원을 받으면 입문 스트리머가 된다 | 두 방송자 여정을 하나로 잇는 가정이다 | 다시 방송하는 비율을 센다 (문제정의 10장과 같다) |
| 시청자가 다시 찾아오는 이유가 있다 | 네 가지 수익이 모두 시청자에게서 나온다 | 같은 시청자가 두 번째 방송에 들어온 비율을 센다 |
| 감정 점수는 모두 추론이다 | 표의 감정 점수를 근거로 우선순위를 정하면 틀릴 수 있다 | 사용 테스트 뒤 사용자에게 단계별 만족도를 묻는다 |

이 문서를 바탕으로 피그잼에서 그림 형태의 여정 지도를 그리면 발표 자료로 쓰기 쉽다.
